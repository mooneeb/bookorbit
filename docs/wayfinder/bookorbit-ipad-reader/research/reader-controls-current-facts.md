# Reader controls, preferences and bookmarks: current facts

Read-only source audit on 2026-10-25 for [Choose everyday reading controls and preference behavior](https://github.com/mooneeb/bookorbit/issues/22), pinned to `9d21470783f5c1009c4b5a18f98fb938151522b9`. A delegated factual agent inspected committed instructions, reader/engine code, APIs, schemas and accepted decision files. It made no changes and ran no builds, tests, services, devices or external research. The parent assembled this evidence note from its report. Product choices remain with the live user review.

## Preferences: ownership and contracts

Existing browser preferences merge built-in defaults, format-group defaults and sparse overrides keyed by bookFileId. Database uniqueness is user/format-group and user/bookFileId. Deleting a file cascades its preference row. Browser local keys use reader:default:group and reader:book:fileId without an account component. Those keys must not be copied as a safe native account-isolation design. [Settings merge][settings-merge], [local keys][settings-keys], [schema][preference-schema].

Local storage is used even when server synchronization is disabled. Server requests occur only with syncReaderPreferences enabled; changing storage mode accepts a sync boolean. Existing writes are fire-and-forget in the composable, without a durable queue or response-status/revision acknowledgment. Loading absent server rows does not explicitly clear all local overrides. [Settings persistence][settings-persistence], [loading/writes][settings-writes], [storage setting][storage-setting].

Under /api/v1/reader, preferences GET returns settings/isCustomized; PUT replaces settings; PATCH accepts set/unset; DELETE resets. Default-setting routes use format groups. The service validates known format-specific keys, rejects empty patches and overlapping set/unset fields. SQL JSONB patch preserves unrelated field changes but has no same-field revision/CAS contract. [Controller][preferences-controller], [validation][preferences-service], [repository][preferences-repository].

Publisher-formatting mode skips injected CSS without file customization and applies only customized deltas when present. Reset applies defaults. EPUB sidebar pinning is per-file sessionStorage; PDF sidebar width/tab/open is browser-wide localStorage. Comments describing another iOS client's look-sync/layout-local policy do not settle this independent app's product policy. [Publisher formatting][publisher-formatting], [reset][settings-reset], [sidebar pin][sidebar-pin], [PDF chrome][pdf-chrome], [type comment][settings-comment].

## User bookmarks: separate owner, missing native protocol

The bookmark module owns integer IDs and database-generated client UUIDs, user/book links, CFI, label, optional note/audio position, origin/device locators and a tombstone. It has no file FK, verified source version/digest, immutable operation ID or revision precondition. CFI uniqueness includes user/book and tombstones. Book deletion cascades bookmark rows. These are different ownership/lifecycle rules from reading annotations. [Schema][bookmark-schema].

Book-scoped bookmark routes support GET/POST and item PATCH/DELETE. Create accepts cfi up to 2,000 characters and title up to 500. Update accepts title and nullable/blank-cleared note up to 4,000. Responses expose identity/origin/note/timestamps, without source binding/deletion state. Services check book access and authenticated ownership; inspected mutation methods lack explicit RequirePermission metadata. [Controller][bookmark-controller], [create DTO][bookmark-create], [update DTO][bookmark-update], [response][bookmark-response].

Duplicate POST returns a live location bookmark. A create at a tombstoned CFI can reactivate that identity, reset origin/device placement and retain untouched fields such as note. DELETE soft-deletes; a repeated deletion returns 404. PATCH has no stale-edit protection. Browser state uses exact CFI-string matching, loads the full active per-book list and issues direct in-memory requests, without a durable offline queue, remote refresh, revision reconciliation or pending-toggle guard. Reusing these calls does not meet a newly chosen offline bookmark contract. [Service][bookmark-service], [repository][bookmark-repository], [browser state][bookmark-state].

KOReader consumes datetime/position keys, XPointer/CFI conversion and device links. Known-device labels can overwrite API renames. Its exchange caps the working set at 500 and its tombstone purge considers age and KOReader links, not acknowledgment by every reader. Kobo dogears also flow through the bookmark sync owner with external mappings/deletions. Those adapters need explicit compatibility handling if new source/retry/lifecycle rules are selected. [KOReader processing][koreader-process], [exchange cap][koreader-cap], [purge][koreader-purge], [Kobo dogears][kobo-bookmarks].

Notebook is a projection including bookmark records; it is not another owner. Audiobook bookmark routes are separate. The annotation owner, automatic source-bound progress, existing whole-book notes and journals remain separate accepted boundaries. No new native bookmark authoring, optional bookmark-note editor, offline deletion policy or preference synchronization policy follows automatically from these facts. [Notebook mapping][notebook], [accepted sync][accepted-sync], [merge preservation][accepted-merge].

## Meaning for the live decision

The native control inventory and preferences need explicit user choices. If bookmarks are included, settle their source scope, offline/cross-device behavior and removal/conflict policy before describing the existing endpoints as sufficient. If preferences sync, a safe same-field/offline contract remains necessary. Current browser availability is evidence for adapter seams rather than a promise of native parity.

Publication-profile coverage is separately tracked in [Define supported EPUB and PDF publication profiles](https://github.com/mooneeb/bookorbit/issues/23). The confirmed note/progress/asset/merge models are inputs, not questions to reopen. Existing fixture gates do not establish production native controls, footnotes, bookmarks, accessibility or durable network behavior.
