# Native platform and reader stack facts

Research date: **2026-10-23**. Planning evidence for [Choose the native app boundary and reader stack](https://github.com/mooneeb/bookorbit/issues/10), under [Find the design for a personal BookOrbit iPad reader](https://github.com/mooneeb/bookorbit/issues/1). Repository baseline: `ebf17719a2207eb9dd0abad32830b12d9c63992b`, branch `BO-10-native-reader-stack`. This document evaluates candidates; it does not select the stack or authorize implementation.

**Evidence labels:** **Documented** means primary Apple documentation, upstream documentation or release source. **Observed** means the existing BookOrbit evidence records a bounded result. **Inference** identifies engineering consequences rather than platform guarantees. **Unverified** identifies integration work this research did not perform. Apple API introduction versions below are availability facts, not promises to support older operating systems.

## Accepted inputs and existing evidence

The confirmed [note model](../decisions/note-model.md) and [offline-sync contract](../decisions/offline-sync.md), confirmed in [Choose note identity, anchoring, and storage ownership](https://github.com/mooneeb/bookorbit/issues/8) and [Choose offline sync, conflict, and deletion behavior](https://github.com/mooneeb/bookorbit/issues/9), are inputs. PDF uses native editable page ink. EPUB has one mixed typed/ink note per exact selected range, with ink in a separate canvas. Preserve fully hashed/versioned source bindings, editable originals, matching previews and saved context after source replacement/removal. Neither silent remapping nor automatic cross-format placement is allowed. Earlier research's unresolved EPUB page-ink alternatives do not reopen this accepted split.

**Observed:** the selected Chrome, Vivaldi and Android browser fixtures passed inline PDF ink and exact-text EPUB note previews; the matching native originals reopened and remained editable. Manual SideStore renewal/update preserving the same AppID and originals also passed. These are completed bounded findings, not pending prerequisites. They did not exercise the production network queue, which remains unimplemented. [Browser evidence](../prototypes/browser-compatibility/README.md), [renewal evidence](../prototypes/context-preservation/evidence/free-signing-renewal/README.md), [preservation resolution](https://github.com/mooneeb/bookorbit/issues/15#issuecomment-6300054724).

The supplied supported device is **iPad Air 13-inch M2, iPadOS 26.6.1**, with Pencil Pro in the [accepted brief](../brief.md). Apple lists that iPad as compatible with Pencil Pro and USB-C Pencil; their capabilities differ. This audit did not inspect the installed OS, Pencil settings or runtime libraries. [Apple compatibility](https://support.apple.com/en-us/108937), [Pencil feature comparison](https://www.apple.com/apple-pencil/).

## SwiftUI and UIKit integration

**Documented:** `UIViewRepresentable` and `UIViewControllerRepresentable`, available from iPadOS 13, let SwiftUI create, update and dismantle UIKit views/controllers. UIKit delegate/state changes need an explicit coordinator to reach SwiftUI. SwiftUI controls the represented root view's layout properties. These are supported hosting mechanisms for `PDFView`, `PKCanvasView` and `WKWebView`, rather than evidence that their combined interactions work automatically. [View wrapper](https://developer.apple.com/documentation/swiftui/uiviewrepresentable), [controller wrapper](https://developer.apple.com/documentation/swiftui/uiviewcontrollerrepresentable).

**Inference:** a SwiftUI shell with a UIKit reader controller is technically viable. A UIKit-owned shell is also viable; these sources do not establish which is simpler for BookOrbit. The integration must retain the active reader/canvas state, forward delegates and route tool/undo focus across notes and pages. SwiftUI view reconstruction must not become note identity or an implicit save boundary. The accepted [local-save contract](../decisions/offline-sync.md#scope-durable-local-state-and-operation-identity) still applies independently of UI hosting.

## PencilKit archives, tools and input

### Editable bytes and compatibility

**Documented:** from iPadOS 13, `PKDrawing.dataRepresentation()` serializes the entire drawing and `init(data:) throws` restores drawing content. A rendered image is a separate representation. These APIs do not define durable autosave, note identity, server synchronization or persistent undo history. [Serialization](<https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct/datarepresentation()>), [restoration](<https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct/init(data:)>), [image rendering](<https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct/image(from:scale:)-220d0>).

**Documented:** newer ink types can make an archive fail to decode on an older PencilKit runtime. From iPadOS 17, `requiredContentVersion` describes the drawing's minimum content requirement. To constrain new editing, Apple specifies setting `maximumSupportedContentVersion` on **both canvas and tool picker**; the default is `.latest`. This limits offered content, not a documented converter for an already incompatible drawing. [Backward compatibility](https://developer.apple.com/documentation/pencilkit/supporting-backward-compatibility-for-ink-types), [canvas limit](https://developer.apple.com/documentation/pencilkit/pkcanvasview/maximumsupportedcontentversion).

The documented content versions include version 1 for pen/pencil/marker, version 2 for the iPadOS 17 inks, version 3 for barrel-roll data from 17.5, and version 4 for Reed Pen from 26.0. Current documentation also contains version 5 with **27.0** availability, outside this target. The old compatibility article's two-version example is not an exhaustive current list. [Version 1](https://developer.apple.com/documentation/pencilkit/pkcontentversion/version1), [version 2](https://developer.apple.com/documentation/pencilkit/pkcontentversion/version2), [version 3](https://developer.apple.com/documentation/pencilkit/pkcontentversion/version3), [version 4 and availability](https://developer.apple.com/tutorials/data/documentation/pencilkit/pkcontentversion/version4.json), [version 5 availability](https://developer.apple.com/tutorials/data/documentation/pencilkit/pkcontentversion/version5.json).

**Inference:** version 4 is an available compatibility ceiling to evaluate for the stated 26.6.1 baseline, not an adopted product pin. Keep the required content version distinct from app schema/protocol versions and runtime provenance. Preserve incompatible original bytes and report the limitation rather than replacing them with a preview. The accepted [ink manifest](../decisions/note-model.md#editable-ink-previews-and-saved-context) already requires archive encoding/version, hashes, provenance and immutable revisions. Apple does not supply a public portable archive schema or a universal future/backward compatibility guarantee in the cited serialization contract.

### Tools, undo and gestures

**Documented:** registering a canvas as a `PKToolPicker` observer connects selected drawing tools; picker visibility involves the current first responder. iPadOS 18 adds ordered/custom picker items. A selected custom item disables PencilKit drawing on observing canvases; the app supplies that tool's rendering. UIKit exposes responder-chain `undoManager`; Apple's drawing sample explicitly registers undo for programmatic drawing replacement. None of this establishes persistent undo across canvas disposal or relaunch. [Picker](https://developer.apple.com/documentation/pencilkit/pktoolpicker), [custom tool sample](https://developer.apple.com/documentation/pencilkit/configuring-the-pencilkit-tool-picker), [undo manager](https://developer.apple.com/documentation/uikit/uiresponder/undomanager), [Apple sample source](https://docs-assets.developer.apple.com/published/d18940fcfc4f/DrawingWithPencilKit.zip).

Apple demonstrates built-in picker undo/redo buttons in regular size classes; compact layouts need app-provided controls. It also warns that `canvasViewDidEndUsingTool` can precede final force updates: the subsequent `canvasViewDrawingDidChange` supplies the finished drawing. **Inference:** tool-up alone is insufficient as the authoritative durable-save event. The app still needs explicit drawing-change persistence and undo routing. [Introducing PencilKit, canvas delegates and tool picker](https://developer.apple.com/videos/play/wwdc2019/221/).

**Documented:** custom double-tap/squeeze behavior uses `UIPencilInteraction` delegates or SwiftUI's Pencil modifiers. Respect `preferredTapAction`, `preferredSqueezeAction`, disabled/ignore choices, squeeze phase and optional hover pose. A squeeze assigned to a system shortcut is not delivered to the app. Installing a squeeze-handling delegate suppresses the system squeeze undo slider. Native picker behavior and arbitrary app gestures are different scopes. [Double taps](https://developer.apple.com/documentation/applepencil/handling-double-taps-from-apple-pencil), [squeezes](https://developer.apple.com/documentation/applepencil/handling-squeezes-from-apple-pencil), [Apple Pencil Pro integration](https://developer.apple.com/videos/play/wwdc2024/10214/).

Accessibility settings can disable/slow double tap and change squeeze firmness. Default canvas drawing policy follows the system Pencil-only preference with a visible picker; otherwise only Pencil draws. SwiftUI states that all visible views with a matching Pencil modifier receive the callback. **Inference:** gesture ownership and responder routing need explicit integration so several visible pages do not perform one action repeatedly. [Pencil accessibility settings for iPadOS 26](https://support.apple.com/en-au/guide/ipad/ipad63913965/26/ipados/26), [default drawing policy](https://developer.apple.com/documentation/pencilkit/pkcanvasviewdrawingpolicy/default), [SwiftUI double tap](<https://developer.apple.com/documentation/swiftui/view/onpencildoubletap(perform:)>), [SwiftUI squeeze](<https://developer.apple.com/documentation/swiftui/view/onpencilsqueeze(perform:)>).

### Sensor and feedback scopes

- **Pressure/tilt:** custom UIKit input exposes `UITouch.force`, `altitudeAngle` and `azimuthAngle(in:)`; force can initially be estimated and need later updates. PencilKit supplies native ink capture/rendering, but this does not promise a custom tool will reproduce its pressure curves. [Force](https://developer.apple.com/documentation/uikit/uitouch/force), [altitude](https://developer.apple.com/documentation/uikit/uitouch/altitudeangle), [azimuth](<https://developer.apple.com/documentation/uikit/uitouch/azimuthangle(in:)>).
- **Hover/roll:** custom hover uses `UIHoverGestureRecognizer`; `zOffset` is normalized distance, not millimetres. Touch/hover roll APIs start at 17.5; unsupported Pencils return zero. PencilKit supplies Pro tool shadows and marker/fountain-pen roll response. Custom hover graphics/commands need app work, including respecting `prefersHoverToolPreview`. [Hover sample](https://developer.apple.com/documentation/uikit/adopting-hover-support-for-apple-pencil), [hover distance](https://developer.apple.com/documentation/uikit/uihovergesturerecognizer/zoffset), [touch roll](https://developer.apple.com/documentation/uikit/uitouch/rollangle), [hover preference](https://developer.apple.com/documentation/uikit/uipencilinteraction/prefershovertoolpreview), [PencilKit Pro behavior](https://developer.apple.com/videos/play/wwdc2024/10214/).
- **Haptics:** `UICanvasFeedbackGenerator`, from 17.5, requests semantic alignment/path-completion feedback with view/location context. Pencil Pro playback depends on hardware, foreground state, settings, battery and other system conditions. A feedback request does not guarantee vibration. [Canvas feedback](https://developer.apple.com/documentation/uikit/uicanvasfeedbackgenerator), [playback conditions](https://developer.apple.com/documentation/applepencil/playing-haptic-feedback-in-your-app).
- **Scribble:** standard text-input integration supports handwriting-to-text, with custom controls needing additional interaction support. Scribble text is distinct from retained editable ink. The actual typed editor and drawing canvas still need gesture arbitration. [Apple Scribble integration](https://developer.apple.com/videos/play/wwdc2020/10106/), [Scribble interactions](https://developer.apple.com/documentation/uikit/uiscribbleinteraction).

**Unverified:** the complete production combination of writing toggle, finger scrolling/selection, Pencil navigation, palette settings, Scribble and undo. The retained native erase/Undo trials already passed their fixtures; they do not certify every future controller, tool or gesture. [Accepted interactions](../brief.md), [completed fixture evidence](../prototypes/browser-compatibility/README.md).

## PDFKit page ink and geometry

**Documented:** `PDFPageOverlayViewProvider`, from iPadOS 16, supplies per-page views as PDFKit needs them. PDFKit sizes/rotates overlays; display callbacks support interaction configuration. Apple's example restores a drawing when making a canvas, copies it to a page model when the overlay ends display, and releases the cached view. Apple separately demonstrates saving an annotation appearance plus private drawing data for native editing. An overlay alone does not persist ink or establish editable interoperability with other PDF applications. [Overlay protocol](https://developer.apple.com/documentation/pdfkit/pdfpageoverlayviewprovider), [Apple overlay and saving demonstration](https://developer.apple.com/videos/play/wwdc2022/10089/).

**Inference:** this is a credible bounded-view integration for PDF page ink, but saving only when a page leaves display cannot meet the durable local-edit contract. Native originals can remain sidecar app-data assets under the accepted model; embedding them in the source PDF is not required by PDFKit's presentation API or by this research. [Accepted preservation and storage](../decisions/note-model.md#editable-ink-previews-and-saved-context), [durable save contract](../decisions/offline-sync.md#scope-durable-local-state-and-operation-identity).

**Documented:** PDFView converts points/rectangles between view and page coordinates; page space uses 72-point units and a lower-left origin. `bounds(for:)` distinguishes display boxes, intersects effective bounds with MediaBox, supplies fallback boxes and warns about rotation transforms. `PDFPage.rotation` uses multiples of 90 degrees. [To-page conversion](<https://developer.apple.com/documentation/pdfkit/pdfview/convert(_:to:)-9twqk>), [from-page conversion](<https://developer.apple.com/documentation/pdfkit/pdfview/convert(_:from:)-4evlx>), [page bounds](<https://developer.apple.com/documentation/pdfkit/pdfpage/bounds(for:)>), [rotation](https://developer.apple.com/documentation/pdfkit/pdfpage/rotation).

**Inference:** preserve the accepted source/page identity, MediaBox, CropBox, rotation, coordinate convention, canvas extent and transforms. A universal Y flip or stretching a preview to the page rectangle cannot establish correctness across nonzero crop origins, rotations and aspect-fit margins. PDFKit's page-sized overlay contract does not promise enlarged scrolling/hit-testing for ink outside the page. [Accepted PDF geometry](../decisions/note-model.md#pdf-notes-and-page-ink), [overlay lifecycle](https://developer.apple.com/documentation/pdfkit/pdfpageoverlayviewprovider).

**Observed:** the browser proof already needed real padded scroll bounds to reach retained outside-crop ink. Its corrected crop/rotation/margin fixture passed. **Unverified:** equivalent general behavior in the proposed production PDFKit reader, across mixed page sizes, all supported rotations/zoom levels and canvas recreation. Preserving original out-of-page ink remains distinct from deciding the production margin-writing UI. [Retained geometry and correction](../prototypes/browser-compatibility/README.md#native-ink-provenance).

## Contained EPUB web adapter

**Documented:** `WKURLSchemeHandler`, from iPadOS 11, loads resources for schemes WebKit does not already handle; registration for a built-in scheme is an error. Handler tasks can be stopped when resources are no longer needed. Alternatively, `loadFileURL(_:allowingReadAccessTo:)` grants access to a specified file/directory, with the same file URL being the narrowest grant. These APIs provide resource loading, not EPUB parsing or CFI semantics. [Scheme handler](https://developer.apple.com/documentation/webkit/wkurlschemehandler), [registration](<https://developer.apple.com/documentation/webkit/wkwebviewconfiguration/seturlschemehandler(_:forurlscheme:)>), [file loading](<https://developer.apple.com/documentation/webkit/wkwebview/loadfileurl(_:allowingreadaccessto:)>).

**Documented:** `WKContentWorld`, from 14, separates JavaScript variable namespaces but shares the document/DOM. Registering a message handler in a world exposes it in **all frames** in that world. Messages identify their world and sending frame; `WKFrameInfo` exposes main/subframe status and security origin. Frame-info objects are transient, not persistent frame identities. [Content worlds](https://developer.apple.com/documentation/webkit/wkcontentworld), [handler registration](<https://developer.apple.com/documentation/webkit/wkusercontentcontroller/add(_:contentworld:name:)>), [message frame](https://developer.apple.com/documentation/webkit/wkscriptmessage/frameinfo), [message world](https://developer.apple.com/documentation/webkit/wkscriptmessage/world), [frame information](https://developer.apple.com/documentation/webkit/wkframeinfo), [security origin](https://developer.apple.com/documentation/webkit/wkframeinfo/securityorigin).

Navigation delegates can reject navigation. `allowsContentJavaScript` controls publication/page scripts; its default is enabled. App-bound domains constrain privileged browsing APIs/top-level navigation, but WebKit explicitly permits third-party subframes and treats local content as app-bound. None of these alone validates book content or native commands. Foliate's own security guidance warns about publication scripts, same-origin blob content and reliance on CSP. [Navigation delegate](https://developer.apple.com/documentation/webkit/wknavigationdelegate), [page scripts](https://developer.apple.com/documentation/webkit/wkwebpagepreferences/allowscontentjavascript), [WebKit app-bound domains](https://webkit.org/blog/10882/app-bound-domains/), [Foliate security](https://github.com/johnfactotum/foliate-js#security).

**Inference:** a contained adapter would need to serve only the active account's verified publication and trusted reader assets, normalize/validate resource paths, reject traversal/arbitrary file access and bound reads. It would need a narrow typed message protocol validating payload bounds, expected world/origin/frame, current source version and selected range. Legitimate spine subframes need an explicit rule; accepting every subframe or assuming all messages originate in the main frame is insufficient. Keep native credentials/filesystem/network capabilities outside publication JavaScript. Trusted renderer code and untrusted publication scripts need separate treatment; simply disabling all page scripts may also disable the renderer. These are integration requirements derived from the API scopes above and the [accepted ownership/source rules](../decisions/note-model.md), not security guarantees supplied by a URL scheme.

**Inference:** reusing the vendored EPUB implementation may reduce CFI translation, but a WKWebView host does not by itself certify exact-range identity. Bundle/localize required reader code, fonts and book resources; cold offline opening must not depend on a previously visited website. Recover after WebKit content-process termination from native source/locator state. The existing selected-fixture success remains valid, while general range round trips, Unicode/repeated text, local module/font loading and large chapters need production integration evidence. [Vendored CFI implementation at the baseline](https://github.com/mooneeb/bookorbit/blob/ebf17719a2207eb9dd0abad32830b12d9c63992b/client/public/assets/foliate/epubcfi.js), [content-process termination callback](<https://developer.apple.com/documentation/webkit/wknavigationdelegate/webviewwebcontentprocessdidterminate(_:)>), [accepted exact-range contract](../decisions/note-model.md#epub-text-linked-notes).

## Local persistence: GRDB/SQLite and Apple alternatives

### Verified release, runtime and license facts

**Documented:** the official latest stable GRDB release checked is **7.11.1, 2026-06-18**. Its release README requires iOS 13+, SQLite 3.20.0+, Swift 6.1+ and Xcode 16.3+. Its package manifest declares Swift tools 6.1, Swift language mode 6, an iOS 13 platform minimum and the system SQLite target. Those minimums fit the supplied OS baseline; they do not verify an actual build or its toolchain. [Release](https://github.com/groue/GRDB.swift/releases/tag/v7.11.1), [release README](https://github.com/groue/GRDB.swift/blob/v7.11.1/README.md), [package manifest](https://github.com/groue/GRDB.swift/blob/v7.11.1/Package.swift).

GRDB's release license is MIT and requires retaining the copyright/permission notice. SQLite's deliverable library/documentation is public domain. The default GRDB installation uses **OS-supplied SQLite**, so pinning GRDB does not pin SQLite or establish the SQLite version/Apple backports in iPadOS 26.6.1. A custom SQLite build is a separate integration choice. [GRDB license](https://github.com/groue/GRDB.swift/blob/v7.11.1/LICENSE), [SQLite dedication](https://www.sqlite.org/copyright.html), [GRDB installation](https://github.com/groue/GRDB.swift/blob/v7.11.1/README.md#installation).

### Transaction fit and limits

**Documented:** GRDB `DatabaseWriter.write` runs operations in a transaction with serialized writes and rollback on error. `DatabasePool` uses WAL and configurable reader concurrency; SQLite still allows only one writer. GRDB provides schema migrations. These primitives can support explicit note parts, operation IDs, receipts, checkpoints and indexed bounded queries; they do not supply BookOrbit replication semantics. [Writer contract](https://github.com/groue/GRDB.swift/blob/v7.11.1/GRDB/Core/DatabaseWriter.swift), [pool configuration](https://github.com/groue/GRDB.swift/blob/v7.11.1/GRDB/Core/Configuration.swift), [SQLite transactions](https://www.sqlite.org/lang_transaction.html), [migrator](https://github.com/groue/GRDB.swift/blob/v7.11.1/GRDB/Migration/DatabaseMigrator.swift).

**Documented durability caveat:** GRDB 7.11.1's WAL setup selects `synchronous=NORMAL`. SQLite documents that NORMAL/WAL transactions survive application crashes but may roll back after power loss/system crash; FULL/WAL adds commit synchronization for durability, subject to the storage/VFS contract. **Inference:** a durable-note design needs an explicit verified synchronization configuration; the default pool must not be presented as a power-loss guarantee. [GRDB WAL setup](https://github.com/groue/GRDB.swift/blob/v7.11.1/GRDB/Core/Database.swift#L530), [SQLite synchronous semantics](https://www.sqlite.org/pragma.html#pragma_synchronous).

SQLite also documents the rare WAL-reset corruption bug, fixed in 3.51.3 with backports including 3.44.6/3.50.7. It concerns multiple connections writing/checkpointing concurrently. **Unverified:** whether the supplied OS SQLite contains the fix. Record the actual runtime/source identity and Apple patch evidence before treating a particular WAL/pool configuration as validated; an older version number alone cannot establish whether Apple backported it. [SQLite bug and affected conditions](https://www.sqlite.org/wal.html#walresetbug), [runtime identity APIs](https://www.sqlite.org/c3ref/libversion.html).

**Inference:** GRDB is a credible candidate where explicit SQL constraints and transaction boundaries are valuable. Local revision, immutable operation/dependency/sequence, asset-reference and receipt changes can be committed together; network requests must remain outside that transaction. File durability and metadata publication still require the restart reconciliation specified in [offline sync](../decisions/offline-sync.md). Neither GRDB transactions nor SQLite ACID make separate asset files or HTTP publication atomic. [SQLite transaction scope](https://www.sqlite.org/lang_transaction.html), [SQLite transactional guarantees](https://www.sqlite.org/transactional.html).

### SwiftData and Core Data remain alternatives

**Documented:** SwiftData `ModelContext`, from iPadOS 17, supports explicit `save()` and `transaction(block:)`. Changes remain in memory until saved. Its main context normally has autosave enabled, including lifecycle-triggered saves. Local history APIs are available from 18. It is inaccurate to reject SwiftData as having no transactions. [Model context](https://developer.apple.com/documentation/swiftdata/modelcontext), [save](<https://developer.apple.com/documentation/swiftdata/modelcontext/save()>), [transaction](<https://developer.apple.com/documentation/swiftdata/modelcontext/transaction(block:)>), [autosave](https://developer.apple.com/documentation/swiftdata/modelcontext/autosaveenabled), [history transaction availability](https://developer.apple.com/documentation/swiftdata/defaulthistorytransaction), [history use](https://developer.apple.com/documentation/swiftdata/fetching-and-filtering-time-based-model-changes).

**Documented:** Core Data has explicit context saving and persistent-history transactions/tokens. Saving a child context only pushes into its parent; persistence requires saving through to the persistent-store coordinator. [Context save](<https://developer.apple.com/documentation/coredata/nsmanagedobjectcontext/save()>), [persistent history](https://developer.apple.com/documentation/coredata/consuming-relevant-store-changes).

**Inference:** either Apple framework could store an explicit durable outbox and receipts. Their local histories are not the accepted server change feed, per-part base revisions or idempotency protocol. Autosave alone cannot define when the UI may announce Saved on iPad. GRDB offers direct SQL ownership; SwiftData/Core Data offer Apple object-persistence integration. No examined source proves one is categorically safer/faster for this workload. All require migrations, bounded fetching, account isolation, crash recovery and separate file reconciliation. Selection remains with the native stack decision, measured against the [confirmed sync invariants](../decisions/offline-sync.md).

## Immutable app-data assets and credentials

**Documented:** Apple distinguishes persistent Application Support data from Caches/tmp, which may be purged. Foundation's atomic writing option writes an auxiliary file then replaces the destination; `FileHandle.synchronize()` flushes file data/attributes. These are file operations, not a transaction across several files and a database. [Storage directories](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemOverview/FileSystemOverview.html), [atomic writing](https://developer.apple.com/documentation/foundation/nsdata/writingoptions/atomic), [file synchronization](<https://developer.apple.com/documentation/foundation/filehandle/synchronize()>).

**Inference:** managed persistent app data fits authoritative local archives, matching previews/context and pending upload files. Hash/verify and place a complete immutable asset before committing its references, saved revision and operation. Recover orphan files/incomplete placements after interruption. Do not equate atomic replacement with a complete power-loss/backup strategy. Retention, quotas and coordinated backups remain with [Set library scale, storage, backup, and export requirements](https://github.com/mooneeb/bookorbit/issues/12); recoverable local originals must not depend on cache survival. [Accepted asset/save rules](../decisions/offline-sync.md#asset-transfer-and-atomic-publication).

**Documented:** Keychain Services stores encrypted credential items. `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` allows access after the first unlock until restart, is suitable for background access and does not migrate to another device. File protection separately determines whether asset/database files can be opened while locked; `completeUntilFirstUserAuthentication` remains accessible after first unlock. These are candidate accessibility policies, not choices made here. [Keychain storage](https://developer.apple.com/documentation/security/adding-a-password-to-the-keychain), [credential accessibility](https://developer.apple.com/documentation/security/ksecattraccessibleafterfirstunlockthisdeviceonly), [file protection](https://developer.apple.com/documentation/foundation/fileprotectiontype/completeuntilfirstuserauthentication).

**Inference:** credentials, the local database and transfer files need a compatible lock-state policy. Account/server scoping, serialized token refresh, durable credential replacement and sign-in-required recovery remain app responsibilities; Keychain does not implement them or make credential updates atomic with SQLite. Reauthentication must preserve retained work as already specified. [Accepted authentication/lifecycle contract](../decisions/offline-sync.md#authentication-server-changes-and-lifecycle).

## URLSession transport and execution boundaries

**Documented:** URLSession offers foreground data/upload/download tasks, async methods and delegate callbacks. `waitsForConnectivity` concerns establishing a connection, not recovery after an established connection drops; background sessions always wait for connectivity. These mechanisms do not prove an application mutation was accepted. [URLSession](https://developer.apple.com/documentation/foundation/urlsession), [connectivity semantics](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/waitsforconnectivity).

From iPadOS 17, resumable uploads require support for Apple's documented HTTP resumable-upload protocol on the server. Resume data may be absent; background uploads manage eligible resumption automatically. Arbitrary chunk/offset APIs do not thereby become compatible with `uploadTask(withResumeData:)`. **Inference:** the accepted staged/chunked asset contract can use file-backed URLSession requests, but its exact protocol must be implemented and negotiated on both sides. [Resumable uploads](https://developer.apple.com/documentation/foundation/pausing-and-resuming-uploads), [accepted asset protocol](../decisions/offline-sync.md#asset-transfer-and-atomic-publication).

**Documented background constraints:** transfers run in another process and can reconnect after normal system termination using the same session identifier. User force quit cancels background transfers and prevents automatic relaunch until the user opens the app. [Background configuration](<https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background(withidentifier:)>).

Background sessions require delegates, support HTTP/HTTPS, automatically follow redirects and support persistent upload bodies **from files**; data/stream uploads fail after app exit. Move downloaded temporary files before the delegate returns. Scheduling is discretionary/rate limited, especially when chaining background launches; no completion deadline is guaranteed. [Apple background file guide](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background).

`BGContinuedProcessingTaskRequest`, available from iPadOS 26, must be submitted from the foreground following a person's action. It cannot be assumed to start unattended sync on a later connectivity change. [Continued processing](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtaskrequest).

**Inference:** the app-owned durable queue remains the source of pending work. Map/reconcile session tasks and immutable upload files with operation/asset identity after relaunch, persist receipts before retiring work, and enforce scope during credential/account changes. Background task completion is neither note publication nor durable local acknowledgment. Foreground save/reopen/reconnect/Sync now reconciliation is still necessary; closed-app sync stays best effort. [Task enumeration](<https://developer.apple.com/documentation/foundation/urlsession/getalltasks(completionhandler:)>), [accepted receipts](../decisions/offline-sync.md#retry-results-and-durable-acknowledgments), [save states](../decisions/offline-sync.md#reader-visible-save-states).

## Dependency provenance and remaining integration evidence

Candidate pins must distinguish app dependencies from OS frameworks. GRDB **7.11.1** is an inspected release candidate, not an installed/adopted dependency. PencilKit/PDFKit/WebKit/SwiftUI/Foundation are OS/SDK frameworks; this audit establishes no independent framework package versions. Runtime provenance must include the actual OS/build, app build, archive content requirement and SQLite identity. API introduction metadata does not prove all later implementation behavior. The evidence supports the feasibility of the proposed SwiftUI/UIKit/PencilKit/PDFKit/contained-EPUB composition and explicit SQLite persistence, while exposing app-owned work and viable persistence alternatives. It does not settle the reader stack. The following are **future integration checks**, not failures of the completed fixture/signing reviews and not authorization to perform them:

1. **Device input and persistence:** the production responder/undo/tool configuration, system preference changes, Scribble versus drawing, archive limits/unsupported versions and canvas recreation. Apple's drawing sample itself requires a physical Pencil device. [Sample requirements](https://developer.apple.com/documentation/pencilkit/drawing-with-pencilkit).
2. **Reader adapters:** PDF crop/rotation/transforms and reachable outside-page ink; EPUB exact-range round trips, WebKit termination recovery and hostile-resource/message rejection. Extend beyond the [already accepted fixtures](../prototypes/browser-compatibility/README.md); do not recertify them as if they were pending.
3. **Durability/protocol faults:** storage full, lock-state access, interrupted file/DB publication, migration, lost responses, expired authentication, account switches, forced quit and server restore. Verify the exact SQLite runtime/configuration and accepted per-part/queue/receipt behavior. These follow the [existing sync acceptance cases](../decisions/offline-sync.md#required-validation-scenarios), not a new protocol decision.
4. **Scale/accessibility:** large scanned PDFs, giant EPUB chapters, dense ink, paged notes and long queues, with bounded active canvases, memory and concurrency; verify accessible reading/note focus in the integrated app. The present sources provide mechanisms, not a measured BookOrbit performance/accessibility guarantee.
