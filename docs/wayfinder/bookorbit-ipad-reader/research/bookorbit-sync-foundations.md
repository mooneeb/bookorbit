# BookOrbit sync foundations for a personal iPad reader

Research date: 2026-10-20. Source baseline: `ce118e3890ea8c9019857cb7556552cdc9992f8e`.
All repository links below are relative to this asset and refer to source at that baseline, not a verified hosted deployment.

Question: Which BookOrbit contracts can a personal iPad reader reuse, and which gaps prevent safe offline note creation/editing and automatic display in the existing browser app?

Scope from the supplied ticket and brief: personal native iPad reader; EPUB and PDF equally important; page ink and passage-linked notes; editable handwriting; Scribble enters typed notes; only iPad edits ink. Existing MacBook and Android browsers must receive/display notes automatically. Downloaded reading and note edits must work offline. Backend/web changes are allowed. This research does not settle product choices, define a final schema/protocol, implement code, contact `books.mooneeb.dev`, or assume access to the official iOS source.

## Findings that affect the specification

- **Reusable foundations exist:** native token issuance/renewal, persistent installation identity, feature discovery, paginated library queries, authenticated EPUB/PDF delivery with ranges, file-scoped progress, text highlights, and client-UUID journal creation. These are separate contracts rather than one native synchronization protocol. [Auth](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.service.ts#L300-L417), [identity](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/server-identity/server-identity.service.ts#L12-L23), [query](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/pipes/book-query.pipe.ts#L11-L51), [delivery](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.controller.ts#L401-L445), [journal](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.service.ts#L23-L65).
- **Editable ink is an extension:** inspected inputs/shared types describe strings, CFIs, PDF highlight rectangles, timestamps, and IDs. They do not expose an ink document, ink revision, asset upload/download, or browser preview reference. Page ink also cannot use an annotation create unchanged because it requires nonempty selected text and exactly one CFI/PDF highlight location. [Annotation input](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/dto/create-annotation.dto.ts#L57-L126), [annotation types](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/annotation.ts#L67-L105), [journal types](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/book-journal.ts#L12-L50), [Notebook types](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/notebook.ts#L48-L106).
- **Revisions/tombstones exist internally, but are specialized:** annotation sync state permits only Kobo/KOReader sources. Generic highlight writes neither accept a base revision nor a client operation ID; ordinary responses do not expose the internal `version`. Journal creates are retry-safe while their identity row exists, but edits and permanent deletion do not provide a full offline conflict/deletion protocol. [Schema](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/db/schema/reader.ts#L508-L637), [annotation mutation](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation.repository.ts#L323-L445), [response](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/dto/annotation-response.dto.ts#L5-L46), [journal repository](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.repository.ts#L39-L113).
- **Browser display needs explicit work:** current browser consumers load highlights and personal reviews, including PDF text-note cards. A bounded search of `client/src` found no consumers of the journal or Notebook APIs and no ink preview consumer. Existing highlight state reloads on view/filter/local mutation, with no verified remote-note invalidation. Saving a row on the server is insufficient evidence of automatic display in an already-open browser. [EPUB consumer](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/epub/composables/useAnnotations.ts#L13-L68), [PDF consumer](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/composables/usePdfAnnotations.ts#L102-L175), [review consumer](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/book/composables/usePersonalNote.ts#L18-L69), [hub refresh](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/annotations/composables/useAnnotationsHub.ts#L108-L151), [hub mount](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/annotations/views/AnnotationsHubView.vue#L206-L208).
- **Automatic sync has lifecycle limits:** Apple supports background file transfer and discretionary background execution, not unrestricted continuous execution or a guaranteed reconnect deadline. Foreground reconciliation and durable local edits remain necessary design implications. [Apple background strategies](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app), [background session](<https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background(withidentifier:)>).

## Source-verified HTTP and authorization baseline

Unless explicitly stated otherwise, paths below are relative to `/api/v1`. Global validation uses `whitelist`, `forbidNonWhitelisted`, and transformation. Adding an unrecognized ink/version/client-ID field to a DTO-backed request is therefore not a compatible extension. Book query bodies use their own Zod pipe. [Bootstrap](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/main.ts#L70-L80), [query pipe](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/pipes/book-query.pipe.ts#L11-L51).

JWT extraction accepts `Authorization: Bearer <accessToken>` or the access cookie. Session validation checks the session, active account, token version, and allowed authentication method. Default-password accounts face an additional guard restriction. This is reusable native bearer authentication, not permission to access another user's data. [JWT strategy](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/jwt.strategy.ts#L10-L25), [session validation](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.service.ts#L420-L435), [default-password guard](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/common/guards/jwt-auth.guard.ts#L26-L38).

Book access checks current library membership, superuser bypass, and content filters. `verifyBookAccess` deliberately masks inaccessible books as 404; `verifyFileAccess` delegates membership denial directly and also checks content filters. Thus not every denial is 403, despite the general ownership convention. Annotation and journal mutations additionally constrain stored records to the current user. A superuser can access more library content but these personal-note mutations still use that user's own ID. [Book/file checks](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.service.ts#L564-L602), [annotation scope](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation.repository.ts#L376-L403), [annotation base predicates](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation.repository.ts#L751-L752), [journal identity](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.repository.ts#L112-L113).

The inspected per-book annotation, journal, personal-note, and progress write routes do not carry an explicit `@RequirePermission` decorator. Their current gates are authentication, access checks, and user-scoped queries. Download explicitly requires `LibraryDownload`. This is a source observation, not an endorsement of copying missing permission gates into new destructive/asset routes; the project instructions require backend permission gates for sensitive/destructive work. [Annotation routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation.controller.ts#L22-L44), [journal routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.controller.ts#L25-L72), [book routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.controller.ts#L419-L420), [progress/personal-note routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.controller.ts#L520-L588), [project rules](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/AGENTS.md).

## Native authentication and token lifecycle

1. **Discover login options:** public `GET /auth/login-options` returns `passwordLoginEnabled`, `allowRegistration`, and `oidcProviders`. Public `POST /auth/login` takes `username` (nonempty, max 100), `password` (nonempty, max 1024), optional `clientKind: "web" | "native"`, and optional `deviceLabel` (max 100). Login is limited to five requests per minute at this controller. Use `clientKind: "native"` to receive native credentials; the default is web. [Routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.controller.ts#L68-L94), [login DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/dto/login.dto.ts#L1-L14), [client DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/dto/auth-client.dto.ts#L4-L12), [options shape](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/auth.ts#L89-L93).
2. **Native login response:** `accessToken`, `accessTokenExpiresAt`, `refreshToken`, `refreshTokenExpiresAt`, `sessionId`, and `user`. User includes identity, account state, settings, authentication method, and permissions; superusers receive `['*']`. Native delivery returns credentials in the body with `Cache-Control: no-store`; web delivery sets cookies and omits the refresh token from the body. [Issuance](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.service.ts#L300-L348), [transport](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.service.ts#L411-L417), [shared credentials](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/auth.ts#L164-L202).
3. **Renew:** public `POST /auth/refresh` accepts `{ refreshToken }`, a 64-character lowercase hexadecimal string. Body-token transport must match a native session. A different refresh cookie plus body token is rejected with 400. Response contains replacement credentials, not `user`; authenticated `GET /auth/me` returns the current user. [Refresh DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/dto/refresh.dto.ts#L1-L8), [refresh implementation](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.service.ts#L352-L381), [me route](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.controller.ts#L104-L107).
4. **Rotation is not indefinite replay tolerance:** tokens are hashed in storage, exchanges lock user/session records, rotate to a successor, extend expiry, and allow a bounded successor-chain replay during a configured grace period. Unacceptable replay revokes the session. Defaults are 15-minute access, seven-day refresh, and 30-second rotation grace, all configuration-dependent rather than hosted-server facts. [Token service](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth-session.service.ts#L19-L76), [transaction/replay](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth-session.repository.ts#L68-L150), [defaults](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/config/config.ts#L26-L31).
5. **Logout/revocation:** public `POST /auth/logout` accepts the same refresh body and returns `{}`; matching native credentials revoke their session. `GET /auth/sessions` lists the user's sessions; `DELETE /auth/sessions/:id` returns 204 and explicitly rejects a different owner with 403. Inactive/revoked/expired sessions or invalidated token versions cannot renew. [Routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.controller.ts#L97-L124), [logout](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.service.ts#L384-L408), [ownership](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth.service.ts#L474-L482), [expiry checks](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth-session.repository.ts#L90-L106).

OIDC callback input also inherits native client options and accepts `code`, `codeVerifier`, `redirectUri`, `nonce`, and `state`; the service passes options to token issuance. This verifies a native-capable callback contract, not an approved callback URI or a complete iPad sign-in flow. Password/OIDC deployment policy is unknown. [OIDC DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/dto/oidc-callback.dto.ts#L1-L29), [OIDC issuance](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/oidc/oidc.service.ts#L245-L250).

**Implications, not an implemented client:** serialize refresh, durably replace rotated credentials before dependent retries, keep pending notes through reauthentication, and distinguish HTTP authorization failure from temporary offline failure. An old refresh token retried long after a lost rotation response is not guaranteed recoverable. The browser currently uses a cookie refresh with a shared in-flight promise and one 401 retry; it is useful behavioral evidence, not a native credential store/outbox implementation. [Rotation](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/auth/auth-session.repository.ts#L134-L150), [browser auth](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/lib/api.ts#L156-L210).

Browser authentication confirms the transport distinction: `useAuth.login` sends only username/password with cookies, then consumes `accessToken` and `user`; initialization refreshes and calls `/auth/me`. It does not exercise the native body-refresh contract. [Browser login/init](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/auth/composables/useAuth.ts#L123-L158).

## Server, book, and file identity

- Public `GET /server-identity` is credential-free and `no-store`, returning `{ product: "bookorbit", protocolVersion: 1, instanceId }`; failure to obtain identity is 503. Identity is a UUID stored in a singleton database row, inserted with conflict-ignore rather than regenerated on each request. [Controller](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/server-identity/server-identity.controller.ts#L7-L16), [service](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/server-identity/server-identity.service.ts#L12-L23), [repository](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/server-identity/server-identity.repository.ts#L11-L16), [schema](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/db/schema/server-identity.ts#L4-L11).
- Authenticated `GET /app-info` returns `version`, update information, `maxUploadSizeMb`, optional `instanceId`, and `features`. Identity failure omits that field here. Feature names are append-only; current names include `book-journal`, `notebook-hub`, annotation capabilities, and `server-connection-identity`, with no advertised ink/native-note-sync capability. This protocol version identifies the identity response, not a generic note-sync version. [Controller](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/app-info/app-info.controller.ts#L8-L14), [response construction](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/app-info/app-info.service.ts#L36-L70), [feature/type definitions](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/app-info.ts#L1-L41).
- `GET /books/:id` returns a `BookDetail`, including `files[]` with numeric `id`, format, role, size, filename, optional `fileHash`, and `contentVersion`. Actual `contentVersion` is the file row's `updatedAt.toISOString()`. The detail also contains server paths; these are not iPad filesystem paths. Book/file IDs are distinct; a book may have multiple files and a nullable primary file. A UUID `bookFiles.publicId` exists in storage but is not returned by this detail mapping. [Detail types](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/book.ts#L226-L238), [detail mapping](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.service.ts#L3490-L3502), [database identity](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/db/schema/books.ts#L23-L43), [file schema](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/db/schema/books.ts#L69-L107).

The scanner uses a partial MD5 fingerprint compatible with KOReader for `fileHash`; it samples blocks rather than hashing every byte. Treat it as a matching fingerprint, not proof of full download integrity. [Hash implementation](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/common/utils/file-hash.utils.ts#L8-L37), [scanner usage](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/scanner/scanner.service.ts#L2927-L2942).

**Inference:** an offline cache/outbox needs an installation/account identity boundary plus book/file and content identity. Same numeric IDs on another installation must not attract pending notes. The database identity will also be copied if its database is cloned; clone/restore/re-enrollment policy is not established by the singleton contract. `updatedAt`, a stored file hash, HTTP ETag, and a renderer's anchor compatibility are different concepts; none alone establishes that an old note still anchors to replacement bytes. [Identity persistence](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/server-identity/server-identity.repository.ts#L11-L16), [file fields](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/db/schema/books.ts#L72-L99), [HTTP validators](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/common/utils/file-range.utils.ts#L19-L40).

The browser app-info consumer currently reads version/update information and upload size, not `instanceId` or capability flags. No native connection-enrollment behavior is established by this browser consumer. [Browser app-info](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/settings/composables/useAppInfo.ts#L14-L34).

## Library browsing, search, and file delivery

`GET /libraries` returns accessible libraries with folders, without book pagination. Non-superusers are queried through their membership/content filters; superusers receive all libraries. For books, use `POST /libraries/:id/books` or `POST /books/query`, not a full-library fetch. The per-library route additionally requires viewer access and a books library. [Library routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/library/library.controller.ts#L36-L76), [library service](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/library/library.service.ts#L136-L155), [global route](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.controller.ts#L148-L155).

Both book query routes accept `BookQuery`: optional `q` (max 200), filter tree (depth 5), up to five sort entries, optional `collapseSeries`/`randomSeed`, and `pagination: { page, size }`. Page is **zero-based**; defaults are page 0/size 50, max size 200, and `page * size <= 1,000,000`. Response is `{ items: BookCard[], total, page, size }`. Queries derive accessible libraries and user-specific fields/content filters server-side; result hydration is page-bounded. This is offset browsing, not a stable snapshot or a deletion/change feed. [Input](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/pipes/book-query.pipe.ts#L11-L51), [offset ceiling](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/common/constants/pagination.constants.ts#L3-L9), [shared query](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/query.ts#L394-L406), [response](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/book.ts#L434-L439), [scope/execution](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.service.ts#L1124-L1136), [global execution](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.service.ts#L1172-L1230).

`GET /books/search?q=...&limit=...` is a small suggestion search: q length 1-500, default limit 10/max 20, response array without a cursor/total. It searches title/subtitle/series/authors within accessible libraries/content filters; returns IDs, title, series name, authors, library ID/name, update time, formats, optional read-along flag. It cannot substitute for paginated full search. [DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/dto/search-books.dto.ts#L4-L15), [scope](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.service.ts#L1725-L1729), [repository search](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.repository.ts#L1815-L1866), [result mapping](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.repository.ts#L1906-L1918).

File routes are `GET /books/files/:fileId/serve` (inline, non-audio) and `GET /books/files/:fileId/download` (attachment, explicit `LibraryDownload` permission). Both resolve current access, stat the file, and stream it. For both EPUB and PDF they support `Range`, `If-Range`, `If-None-Match`; send `Accept-Ranges: bytes`, `ETag`, `Last-Modified`, `Cache-Control: private, no-cache`; and can return 200, 206, 304, or 416. They support single closed/open/suffix ranges; malformed or multiple ranges are ignored with a full response. Stale `If-Range` causes a full response. ## Journal and personal notes

### Book journal

`GET /books/:bookId/journal?status=active|trashed` returns an array, oldest first, hard-capped at **2000** with no continuation/total/truncation marker. `POST` creates; `PATCH /:clientId` updates; `DELETE /:clientId` trashes (204); `POST /:clientId/restore` restores (200); `DELETE /:clientId/permanent` purges (204). Route IDs are UUIDs. [Routes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.controller.ts#L12-L72), [list cap](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.service.ts#L23-L26), [ordering](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.repository.ts#L22-L36), [limit constant](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/book-journal.ts#L1-L6).

Create requires client UUID `clientId` and nonblank trimmed `body` (max 10,000). Optional quote max 5000, chapterTitle max 500, CFI max 2000, positionPercent 0-100, nonnegative positionSeconds, and ISO `createdAt`. Future time beyond five minutes is clamped; dates before 1970 are rejected. Response: numeric `id`, UUID `clientId`, `bookId`, body/quote/location fields, `createdAt`, `updatedAt`, `deletedAt`. No `bookFileId`, PDF geometry, ink content, or base revision exists in this journal contract. [DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/dto/create-book-journal-entry.dto.ts#L15-L58), [time normalization](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.service.ts#L106-L117), [shared contract](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/book-journal.ts#L12-L50).

Client ID uniqueness is **per user across books**. Replayed create returns the stored row unchanged, including if edited/trashed, with 201; reusing the UUID for another book gives 409. The service verifies current book access first. Patch modifies active rows, optional fields can be cleared, body cannot be blank/null, and no revision precondition is accepted. Repeated trash is a no-op; restore requires a trashed row. Purge physically removes it without a device-ack ledger. **Inference:** after purge, the previous create UUID can be inserted again, so journal create idempotency is not a permanent anti-resurrection guarantee. [Create/update service](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.service.ts#L29-L85), [repository](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/book-journal.repository.ts#L39-L113), [update DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book-journal/dto/update-book-journal-entry.dto.ts#L15-L53).

## Specialized device synchronization is not a generic native contract

The annotation storage has canonical content/version/deletedAt, separate positions (`cfi | xpointer | pdf | kobo_span`) with file/status/converter metadata, and per-device applied-version/delete-ack state. Sync sources are constrained to `koreader | kobo`. There is one position per annotation/format, not arbitrary multiple PDF/EPUB editions per annotation. **Inference:** reusable internal primitives exist, but an iPad source, ink document, cross-file anchor, or attachment lifecycle would require deliberate extensions. [Schema](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/db/schema/reader.ts#L508-L637).

**KOReader:** `POST /koreader/plugin/annotations/exchange` and `/exchange-ack` use `KoreaderAuthGuard`, not native bearer-session auth. Headers are `x-auth-user`/`x-auth-key`; the guard requires active user, enabled sync, and `KoreaderSync` permission. The legacy `POST .../annotations` is retained for older plugin uploads. [Controller](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/koreader/koreader-plugin.controller.ts#L27-L63), [guard](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/koreader/koreader-auth.guard.ts#L20-L55).

Exchange takes plugin/device identity and up to 20 books, identified by 32-hex hashes; each carries up to 5000 `{k, dt}` keys, `keysComplete`, and up to 50 changes. Service further caps **50 changes total per request**, resolves hashes against accessible libraries/user, ingests changes, detects missing-key deletion only when `keysComplete`, then returns per-book `applied`, `toApply: { add, edit, delete }`, `more`, `skippedNoPosition`, plus unmatched hashes. Push-down caps 100 per book with a bounded conversion budget. Ack includes server IDs, versions, applied/failed status, verification/correction information, and deletion outcomes, with bounded lists. These are device snapshot/conversion semantics rather than a generic account-wide change cursor. [DTO limits](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/koreader/dto/koreader-exchange.dto.ts#L19-L137), [service limits/scope](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/koreader/koreader-annotation-exchange.service.ts#L17-L19), [exchange scope](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/koreader/koreader-annotation-exchange.service.ts#L102-L139), [per-book response](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/koreader/koreader-annotation-exchange.service.ts#L211-L282).

Device ingest deduplicates by device/external identity and does not resurrect matched tombstones. Its content reconciliation compares incoming device datetime against stored device datetime and protects canonical style/color from lossy device echoes. Ack advances applied-version/delete state; push-down prioritizes deletes, then edits, then adds. This is substantive existing sync logic, but its timestamps/identity/projection rules are not a verified solution to two offline iPad/browser edits or ink merge conflicts. [Ingest/tombstone handling](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation-sync.service.ts#L90-L95), [matched tombstone](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation-sync.service.ts#L148-L212), [content reconciliation](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation-sync.service.ts#L329-L402), [bounded push](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation-sync.service.ts#L600-L615), [ack](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation-sync.service.ts#L681-L756).

**Kobo:** reading-service `GET`/`PATCH .../api/v3/content/:contentId/annotations` and `POST .../api/v3/content/checkforchanges` are guarded by Kobo token/device identity and `KoboSync` permission. The controller supports tokened and root reading-service routes; `/api/v3/*` is excluded from the global `/api/v1` prefix. ## Apple lifecycle constraints on offline and automatic sync

Primary Apple documentation was collected by one background helper and checked by the owning researcher. These facts describe platform behavior, not an implemented BookOrbit iPad app.

- **Persist during use/deactivation:** Apple says to save user data to disk during deactivation and prepare for suspension. Scene-based apps receive the relevant scene delegate transition; background apps can be terminated for resources. **Inference:** editable ink, typed notes, and pending operations need durable local storage before treating an edit as saved; a final network send on exit cannot be the only copy. [Preparing for background](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-background).
- **Short completion time is bounded:** `beginBackgroundTask` can extend crucial work already underway; request it before long work, provide expiration handling, and call `endBackgroundTask`. Apple can terminate an app that fails to finish/end appropriately. This is not a permanent sync worker or a guaranteed fixed 30-second allowance. [Extending execution](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time).
- **Refresh is system-scheduled:** `BGAppRefreshTask` is for short updates; Apple describes up to 30 seconds, with the system choosing launch time. `BGProcessingTask` handles longer work but is interruptible; processing tasks run when idle and terminate when the device is used. `earliestBeginDate` is only a lower bound. A processing request can require network connectivity, which does not establish that a particular self-hosted endpoint/auth session is usable. [Strategies](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app), [processing task](https://developer.apple.com/documentation/backgroundtasks/bgprocessingtask), [earliest date](https://developer.apple.com/documentation/backgroundtasks/bgtaskrequest/earliestbegindate), [network requirement](https://developer.apple.com/documentation/backgroundtasks/bgprocessingtaskrequest/requiresnetworkconnectivity).
- **File transfer can outlive the app process:** a background `URLSession` transfers files in another process while the app is suspended or normally terminated by the system. Recreate it with the same identifier to reconnect. User force quit cancels transfers and prevents automatic relaunch until explicit launch. A transfer callback is an opportunity to update durable state, not a guarantee of arbitrary subsequent sync execution. [Background configuration](<https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background(withidentifier:)>).
- **Asset transfer has specific requirements:** background transfers need delegates and HTTP/HTTPS; upload bodies must be files, not in-memory data/streams after exit. Downloaded temporary files must be moved before the delegate returns. Background-started transfers are treated as discretionary; relaunch throttling makes one-transfer-per-wake chains undesirable. Background sessions always wait for connectivity, but an established connection can still fail. **Inference:** ink/preview assets need staged files, durable transfer identity, bounded batches, retryable completion, and authorization recovery independent of a live editor. [Background file guide](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background), [connectivity behavior](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/waitsforconnectivity).
- **Silent push is optional assistance:** Apple does not guarantee delivery; it can delay, throttle, replace older held pushes, or discard them when the app is killed. Push therefore cannot be the sole record/trigger for correctness. No APNs enrollment/provider contract was verified in this audit. [Apple background updates](https://developer.apple.com/documentation/usernotifications/pushing-background-updates-to-your-app).

**Specification implication, not a settled service-level promise:** sync can run automatically while active, on reconnect/foreground return, and during eligible system-granted opportunities, backed by durable pending edits. Do not promise that every edit reaches the browser immediately after Wi-Fi returns while the app remains suspended or force quit. The product still needs a visible pending/error state and a chosen freshness expectation. [Lifecycle](https://developer.apple.com/documentation/uikit/preparing-your-ui-to-run-in-the-background), [scheduling](https://developer.apple.com/documentation/backgroundtasks/bgtaskrequest/earliestbegindate), [force quit](<https://developer.apple.com/documentation/foundation/urlsessionconfiguration/background(withidentifier:)>).

## Minimal plausible extension seams, not selected designs

1. **Identity/capability seam:** reuse server identity, account identity, file IDs, and additive feature discovery. Define what happens on account/server changes, restore/clone, missing capabilities, and changed source bytes before retrying offline work. Do not overload `protocolVersion: 1` as an ink-sync guarantee. [Identity type](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/app-info.ts#L25-L41), [file mapping](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/book/book.service.ts#L3490-L3502).
2. **Note/anchor seam:** annotation positions are the closest existing passage/PDF-highlight boundary; journal is the closest client-UUID free-note boundary. Neither currently represents both page ink and passage-linked ink. The specification must address PDF coordinates/page convention and EPUB reflow/file version separately. The unique `(annotationId, format)` constraint and journal's lack of file/PDF fields matter when deciding whether reuse is sufficient. No schema choice is made here. 3. **Editable asset/preview seam:** preserve an authoritative editable handwriting asset and a browser-readable preview as separately identified representations if the later design requires both. Define transfer limits, content/version association, authorization for both reads/writes, partial-upload handling, retry identity, and cleanup of abandoned/replaced assets. Existing text DTOs and app-info's generic `maxUploadSizeMb` do not define an ink asset contract. A preview alone would not meet the accepted editable-ink requirement. Ink editing may remain iPad-only while previews are visible on MacBook/Android. ## Unresolved decision implications

These are questions for the parent specification, not decisions made by this ticket:

- Which note owns editable ink, typed/Scribble text, preview, and page/passage anchors? Reuse must not turn every free ink mark into a fake selected-text highlight or overwrite a personal review.
- What constitutes the same downloaded EPUB/PDF after replacement, rescan, or edition change, and what happens to anchors that cannot be verified?
- How should concurrent browser text edits, offline iPad revisions, deletes/restores, lost responses, expired credentials, and long-offline replays resolve? A single ink editor does not remove text/metadata/deletion races.
- What is the minimum supported iPadOS version, and what does automatic sync promise while active, suspended, force quit, disconnected, or awaiting sign-in? No background deadline has been established.
- Where do MacBook/Android browser users see page ink and passage notes, and how fresh must an already-open view be? Journal/Notebook server availability does not settle the web surface.

The preceding contract and Apple evidence establish why each decision matters; no persistence schema, merge rule, UI surface, or final sync protocol is selected.
