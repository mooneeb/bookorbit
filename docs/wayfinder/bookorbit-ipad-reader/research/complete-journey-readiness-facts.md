## Existing future acceptance obligations

- [Note identity/migration][notes]: preserve every legacy ID/body/asset, identify unresolved provenance/canonical collisions before enforcing uniqueness, protect retained associations from cascades, and reject unsafe unknown-ink/legacy writes.
- [Sync fault matrix][sync-faults]: lost responses, process exits, partial asset publication, per-part conflicts, dirty browser drafts, Trash/deletion/restore races, old acknowledgments, account/auth changes, feed/receipt compaction, restored history, changed sources, visible-browser backlog and competing/backward positions. Real production note lists and automatic arrival remain untested.
- [Native integration matrix][stack-tests]: complete bounded offline EPUB packages/containment, canonical repeated/Unicode ranges, WebKit termination, arbitrary PDF geometry/margin reachability, Pencil settings/tools/final-force/Undo, accessibility, migrations/lock-state/crash behavior, management-session handoff/isolation and reader identity/update continuity.
- [Storage/operational matrix][storage-tests]: twenty offline books, 50,000-book/100,000-annotation primary account plus isolation/Trash/conflict/replay loads, declared resource/performance conditions, two-GiB app recovery, coordinated restic capture and twenty-GiB notes-first restore. Every new percentile, memory, boundary, retention and restore target remains a measurement to collect.
- [Merge matrix][merge-tests]: explicit confirmation at all collapse entry points, complete source equality/distinct-file preservation, private history/reviews, aliases and late writes, historical attribution, stale previews, cancellation/retry/restart, publication/cleanup and backup/GC leases.
- [Packaging obligations][packaging]: inspect the actual production entitlements/free signing slots and stable AppID; restore required vendor notices and record exact bundled hashes/provenance. These are implementation/package gates. This audit makes no new license judgment and does not reopen the independent-app decision.

## Precise missing product choices

**Everyday reader controls and preferences:** no comprehensive native control inventory is recorded. Native reader controls and an Apple Books-like aim do not choose contents/chapter/page navigation, in-book search, bookmark authoring, link/footnote return, appearance/layout options or preference persistence/sync. Existing browser behavior is not automatically a native requirement. The [stack's reader interface][stack-reader] provides ownership, rather than that product inventory.

**Publication profile coverage:** ordinary, unprotected EPUB/PDF does not enumerate EPUB 2/3, reflowable/fixed-layout/spreads, RTL/vertical text, fonts or the full static/interactive PDF feature profile. The [selected containment/delivery rules][stack-delivery] already cover scripting/remote resources, canonical range limits and failure states, while [preservation limits][preservation-limits] explicitly leave several variants unverified. Which profiles must pass initially is a human scope choice. Whether the implementation handles a chosen profile is technical validation.

These questions are now tracked as [Choose everyday reading controls and preference behavior](https://github.com/mooneeb/bookorbit/issues/22) and [Define supported EPUB and PDF publication profiles](https://github.com/mooneeb/bookorbit/issues/23), both native blockers of the complete-journey decision. General migration/backward-compatibility obligations are already specified; an actual newly exposed trade-off would require a precise ticket, not a standing assumption that all old-client behavior is safe.
