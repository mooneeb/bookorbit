# Reader stack: current facts

Checked **2026-10-23** for [Choose the native app boundary and reader stack](https://github.com/mooneeb/bookorbit/issues/10), planning only. Repository evidence is pinned to **`ebf17719a2207eb9dd0abad32830b12d9c63992b`**. **Source evidence** means inspected first-party documentation, code or package artifacts; **fixture evidence** means the existing recorded experiment; **inference** identifies a consequence, not a tested integration or a stack choice.

The confirmed [note model][note-model] and [offline sync contract][sync-model] remain inputs: native editable PDF page ink; EPUB mixed typed/ink notes on a separate canvas, one per exact range; full source hashes/versions; retained original context; no silent remapping or automatic cross-format placement. The [browser proof][browser-proof] passed its selected Chrome, Vivaldi and Android fixtures and native-original editing checks. [Manual same-AppID SideStore renewal/update][renewal] already passed on the iPad Air 13-inch (M2), iPadOS 26.6.1. Those are completed prerequisites; the production network queue remains unimplemented. These records do not authorize implementation.

## Official BookOrbit iOS source and license

**Source evidence:** The [official website](https://bookorbit.app/) and [baseline README][repo-readme] link the official app, App Store ID **6811807346**. Its [listing][app-store] names Ila Chandel as developer/seller, displays © 2026 BookOrbit, and links Apple's Standard EULA as its Terms of Use. The public server/web repository declares **AGPL-3.0-only**, with separate [BookOrbit Additional Terms][repo-terms]. Neither that repository declaration nor the end-user EULA establishes a source-code license for the separately distributed native app. [Client manifest][client-manifest], [Apple EULA](https://www.apple.com/legal/internet-services/itunes/dev/stdeula/).

**Bounded negative finding:** The unauthenticated [official organization inventory][official-repos] returned five public repositories: `bookorbit`, `bookorbit-site`, `bookorbit-ios-support`, `bookorbit-android-support` and `bookorbit-metadata-providers`. Their complete default-branch trees, official website/support/privacy pages and App Store developer links did not reveal native app source or its source license. The public [iOS support repository][ios-support] at `d230ad8cc374635c83eda3a4b9162228fc0b3eda` contains support/release documentation and website files, with no Swift/Xcode project or license file in its [nine-entry tree][ios-tree]. This establishes public support-site source, not public native application source.

**Inference:** Reuse of an official native-app codebase is not currently substantiated by these public sources. This is **not proof of closed source**: another host, historical release, non-default branch or private source arrangement remains possible. No downloaded app was examined. Current app behavior, embedded reader engine and component notices cannot be inferred from its marketing description.

## EPUB loading, identity and UI tradeoffs

**Offline/resource evidence:** The existing [web integration][foliate-integration] opens EPUB through authenticated `/epub/.../info` and streaming resource APIs. That path needs the server; it is not an offline native package. The vendored [File/ZIP loader][foliate-view] can open local EPUB bytes. The existing native prototype embeds Foliate in `WKWebView` and serves bundled fixture resources over loopback; this demonstrates that fixture route, not a complete download/cache system. [Native host][native-host], [fixture resource server][native-server]. Apple's [custom-scheme API][wk-scheme] is another resource-loading primitive, not evidence that replacing this loader works unchanged.

Readium's [opening guide][readium-open] supports local `FileURL` assets and explicitly distinguishes HTTP streaming from downloading. Its inspected EPUB navigator serves local publication resources/static assets using an internal `readium://` `WKURLSchemeHandler`; the old HTTP-server initializer is deprecated as unnecessary. [View model][readium-model], [resource handler][readium-server], [navigator][readium-navigator]. **Inference:** either host still needs complete local publication/resource availability, original-byte verification, durable notes and the agreed sync queue. An EPUB archive alone cannot guarantee that externally referenced resources are available offline.

**Exact-range portability evidence:** BookOrbit [captures a DOM range and full CFI][foliate-selection] and resolves CFIs through its vendored engine. Its [iframe fallback][foliate-iframe] deliberately preserves the XHTML body tree to avoid parser-inserted elements changing persisted CFIs. **Inference:** reusing that code retains an established serializer and its fixes, but does not prove every EPUB or WebKit update preserves ranges.

Readium 3.11.1's [selection bridge][readium-selection] returns resource href, selected text/context and frame. The [Swift callback][readium-navigator] copies the current location and replaces its text. Its inspected `rangeFromLocator` [resolver][readium-resolver] uses quote/context, optionally CSS scope, then CSS/HTML IDs; it does not consume `partialCfi` or `domRange` there. The [locator specification][locator-html] defines those fields, but a defined model field is not implementation support. Its partial CFI also omits BookOrbit's package path and `epubcfi(...)` wrapper. **Inference:** the default selection/decorations path does not establish unique occurrence identity for the accepted one-note-per-exact-range contract; conversion or additional capture needs validation, especially for repeated identical passages and overlapping ranges.

Reading position is a separate contract: Readium's default reflowable [position service][readium-positions] divides archive-entry length into **1024-byte** units; those are not exact word selections or display pages. [CFI 1.1][cfi] defines structural ranges and UTF-16 character offsets. **Inference:** a percentage or Readium position cannot replace a range selector, and sharing quotes or a field called `Locator` does not prove cross-engine equivalence. Full source-version checks and the existing unresolved-location behavior remain necessary. [Accepted source/anchor rules][note-model].

**Native UI/accessibility evidence:** Readium is a low-level toolkit whose host owns UI and storage, and provides selection actions/decorations. Its EPUB implementation uses WebKit, not a `UITextView` text engine. It contains explicit VoiceOver status/scroll handling and accessibility page-turn actions; its accessibility guide also exposes publication metadata claims. [Integration scope][readium-start], [selection API][readium-highlights], [spread][readium-spread], [navigator][readium-navigator], [metadata guide][readium-accessibility]. **Inference:** both candidates permit native note editors/canvases around web-rendered book text. Readium's hooks are useful source evidence, not proof that the finished BookOrbit flow passes VoiceOver, keyboard navigation, focus return or exact selection. The retained browser fixture review did not establish those accessibility results. [Recorded review][browser-review].

**DRM/password evidence:** The inspected vendored [EPUB encryption decoder][foliate-epub] implements IDPF and Adobe font obfuscation. That is not an EPUB DRM/password unlock implementation. Readium's [feature matrix][readium-readme] supports LCP and marks Adobe ACS as not planned. Its [LCP integration guide][readium-lcp] requires an application-specific private `R2LCPClient` library obtained from EDRLab, in addition to `ReadiumLCP`; an LCP user passphrase is distinct from a PDF open password. **Unknown:** private-client terms, certification, entitlement/identity requirements and suitability for this free-signed app were not established. The BSD toolkit license alone does not answer them. The [3.11.1 release][readium-release] includes CRL/network-handling fixes, so offline LCP behavior must not be inferred merely from a downloaded encrypted EPUB. No DRM scope or policy is selected here.

## Browser PDF licensing and original-coordinate previews

**Artifact evidence:** The version-specific npm records for [core][npm-core], [engines][npm-engines], [models][npm-models], [pdfium][npm-pdfium] and [annotation][npm-annotation] declare MIT; their downloaded source-package tarballs contain MIT `LICENSE` files and matched their registry SHA-512 integrity. PDFium's tarball integrity also matches the [lockfile][lockfile]. No package was installed. Its bundled `LICENSE.pdfium` contains both the PDFium redistribution notice and Apache-2.0 text, also visible in [PDFium's own license][pdfium-license]; calling the entire WASM artifact simply MIT loses that distinction.

The inspected [upstream v2.15.1 release][embed-release] resolves to `176ec6daac51458c9e80733b9c92a66a3bc5e2d1`, whose [licensing map][embed-licensing] declares SDK code Apache-2.0 and the separate CloudPDF server FCL-1.0-ALv2. That source tree is not sufficient evidence of the contents/license of the locked npm artifacts. **Inference:** keep artifact identity, bundled notices and upgrade licensing separate; the CloudPDF server declaration does not establish a paid requirement for BookOrbit's pinned MIT viewer packages. No legal compatibility or complete notice audit is claimed.

The inspected `@embedpdf/pdfium@2.15.1` [tarball][pdfium-tarball] had SHA-256 `658a30188b4009ac6a41585fae1c0058d7b46552d6d193d72d1ad00bb078d3f6`; its WASM SHA-256 was `5e4cd023c3dad4a895b3571ca573d3fc51bac6de48360d95283134385b954eaa`, identical to the installed WASM. The contained metadata did not identify an underlying PDFium commit. The [browser reader][pdf-reader] imports that WASM and uses a worker. The [engine artifact][engines-tarball] defaults fallback-font URLs to CDN `latest` unless configured otherwise. **Inference:** packaged WASM alone is not proof of fully offline PDF rendering; worker, fallback fonts and document resources belong in that check.

**Geometry evidence:** PDFKit supplies per-page native overlays and drawing lifecycle hooks from iOS 16; Apple's example separates rendered annotation appearance from editable drawing data. PDFKit page space has a lower-left origin, while BookOrbit's [shared PDF contract][annotation-types] uses unscaled top-left points and a zero-based page index. Crop/media boxes and intrinsic rotation are separate from viewer rotation/zoom. [Apple demonstration][pdf-session], [page conversion][pdf-convert], [box bounds][pdf-bounds]. PDFKit exposes [password unlocking][pdf-unlock]; EmbedPDF's [2.15.1 models][npm-models] also define password inputs. BookOrbit's current [open-document call][pdf-reader] passes no password, so API support does not establish a working password-entry flow. Neither password API establishes LCP support.

The [completed browser proof][browser-proof] rendered the actual PDF with PDFium, including nonzero CropBox, intrinsic rotation, viewer rotation/zoom and reachable ink beyond the crop. It retained native-canvas geometry and used a fixture-specific inverse transform; its fixed 2x PNG is a preview, not editable ink or an unlimited-detail guarantee. **Inference:** using PDFKit natively leaves a browser adapter requirement: derive each page's transform, preserve the original coordinate origin and full scrollable ink extent, and associate every preview with its precise editable-original revision. Stretching an image to the visible paper or reusing the fixture matrix cannot satisfy arbitrary PDFs. [Accepted PDF geometry and asset rules][note-model].

## Limits for the boundary decision

- No new engine, accessibility, large-book, memory, password/DRM or cross-engine range tests ran. The [retained proof][browser-proof] covers its named fixtures, not a production browser/native integration or large-library certification.
- Foliate reduces changes to existing CFI machinery; Readium supplies additional Swift navigator/publication APIs. **Inference:** this trades ownership of the EPUB host/adapter against range-conversion and behavior differences, rather than choosing between native text and web text. The source evidence above does not rank them.
- Neither reader owns the accepted account-scoped persistence, source identity, conflict handling, original/preview publication or production retry queue. These remain the [confirmed note][note-model] and [sync][sync-model] implementation obligations.
- Official iOS native-source availability/license, Foliate upstream provenance, PDFium build provenance, LCP private-client constraints and finished accessibility remain explicitly unverified. Signing renewal and retained-fixture acceptance are already validated, not pending research gates. [Renewal evidence][renewal], [browser evidence][browser-review].
