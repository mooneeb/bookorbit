# Native iPad Pencil capabilities and personal installation

Research date: 2026-10-20. Research only; no product choices or implementation.

Intake: [ticket question](https://github.com/mooneeb/bookorbit/issues/2) and [accepted brief](../brief.md), read in full from the parent checkout. Those uncommitted intake files are not included in this research commit.

The brief gives EPUB and PDF equal priority, requires page ink and passage-linked notes, preserves editable handwriting, uses Scribble to enter typed notes, limits ink editing to iPad, and requires offline reading/note edits followed by automatic display in the existing MacBook/Android BookOrbit browser app. The iPad model, installed OS, Apple Account, developer membership, and available Xcode/Mac configuration remain unknown. These are intake constraints, not findings about existing support. [Accepted brief](../brief.md).

## Findings that constrain the later specification

Apple provides a native editable drawing model and a capture/rendering view: `PKCanvasView` produces `PKDrawing`, and saved drawing data can later restore the drawing. This establishes a public API foundation for editable ink, not a completed reader, anchoring model, or BookOrbit sync implementation. [PencilKit][pencilkit], [PKDrawing][drawing], [restore drawing][restore].

The capability matrix below separates framework behavior from app work. OS versions are API introduction versions from Apple's documentation metadata, not a proposed deployment target. Hardware capabilities and user preferences must also permit an interaction.

## System preferences and first-party feature boundaries

System Pencil-only drawing, hover previews, preferred double-tap/squeeze actions, enabled Scribble, haptic settings, and accessibility timing/firmness affect the available experience. The picker respects system behavior, but a custom canvas/palette has explicit integration responsibilities. **Inference:** the later spec needs visible controls that remain usable when a gesture is disabled, intercepted by a shortcut, or unsupported. [Pencil-only preference][pencil-only], [hover preference][hover-preference], [double taps][double-tap], [squeezes][squeeze], [accessibility][pencil-accessibility], [haptics][haptics].

Apple describes a system squeeze undo slider, including apps without `PKToolPicker`; installing a squeeze delegate suppresses that behavior. A Notes shape-snapping demonstration is not proof that an arbitrary `PKCanvasView` overlay gains the same feature automatically. [WWDC24][pro-session]. Find My support in the Pencil feature comparison is an accessory/system feature, not a book-note synchronization API. [Apple comparison][pencil-comparison].

Public integration is also evolving: PaperKit, introduced in iPadOS 26, provides a richer canvas for ink, shapes, images, and text boxes. Apple's 27-era material documents additional PaperKit model access and PencilKit stroke recognition. These are context, not a selected alternative or a reason to add OCR. Do not assume every Notes/Markup feature is permanently private, or that adopting PencilKit automatically supplies a complete Notes editor. [Meet PaperKit][paperkit], [PaperKit model access][paperkit-update], [PencilKit updates][pencilkit-updates].

| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Editable source                 | `PKDrawing.dataRepresentation()` returns the entire drawing as data. `PKDrawing.init(data:)` restores previously captured content and can throw. Both are available from iPadOS 13. [Serialize][serialize], [restore][restore].                                                                                            | **Inference:** preserving the source is distinct from keeping a flattened image. The BookOrbit storage/sync contract still needs to identify an ink document and associate it with the relevant note/book/anchor. Apple does not define that contract.                                                                              |
| Stroke access                   | Apple's iPadOS 14 sample and WWDC20 session expose drawings, strokes, paths, masks, inks, and points for inspection and modification. Apple explains that stroke points use lossy compression. [Inspect drawings sample][inspect-sample], [data model session][inspect-session].                                           | Editable ink is not a promise to retain a bit-exact raw Pencil sensor recording. **Inference:** translating sampled centerlines into a different renderer can lose appearance semantics; this research establishes no fidelity guarantee for such translation.                                                                      |
| Image display derivative        | `image(from:scale:)` produces a `UIImage` for a specified drawing-space rectangle and resolution scale. `UIImage.pngData()` encodes PNG and may fail. [Drawing image][image], [PNG encoding][png].                                                                                                                         | **Inference:** a PNG generated on the iPad can serve as an ordinary web display asset while the original ink remains editable there. Crop bounds, coordinate transforms, resolution, transparency, appearance, empty drawings, and memory limits still need definition and tests. The image does not provide stroke editing.        |
| Graphics-context rendering      | The public asynchronous `PKDrawing.draw(in:frame:from:darkUserInterfaceStyle:)` API is documented from iPadOS 26 and accepts a `CGContext`, source rectangle, output frame, and appearance flag. [Context rendering][context-render].                                                                                      | This is another rendering surface, not evidence of a browser runtime or a guaranteed lossless SVG/vector export. Output fidelity and format behavior require validation if selected. It is not needed to establish the older image-export path.                                                                                     |
| PDF export                      | Apple's WWDC22 code demonstrates a custom PDF annotation with an appearance stream plus application-specific archived drawing data. It also demonstrates optional annotation burn-in. [PDFKit overlay and saving session][pdf-session].                                                                                    | A reader may display the PDF appearance without understanding the private ink payload. **Inference:** other PDF editors are not thereby able to edit PencilKit strokes, and flattening is insufficient as the only preserved source. This is evidence of an integration technique, not a BookOrbit device test.                     |
| Content compatibility           | New inks can make drawings unreadable on older PencilKit versions. From iPadOS 17, inspect `requiredContentVersion`; `maximumSupportedContentVersion` can constrain edits and should be set on both canvas and picker when used. [Compatibility guidance][compatibility], [canvas limit][content-limit].                   | A future spec needs an explicit content-version/fallback policy. Do not silently replace an unsupported editable drawing with its display preview.                                                                                                                                                                                  |
| Version growth                  | `PKContentVersion.version3` supports barrel-roll data and is introduced in iPadOS 17.5; `.version4` adds Reed Pen and is introduced in 26. [Version 3][version3], [version 4][version4], [version index][versions]. | OS availability is per API and per content feature. | Browser/server interoperability | The reviewed public PencilKit APIs expose Apple-platform drawing objects, serialized data, and render outputs. Apple's [Drawing with PencilKit sample][drawing-sample] requires a physical device and Apple Pencil. Its downloaded `PencilKitDraw/DataModel.swift` saves a Codable model containing drawings using a serial queue and restores sample drawings from data. That is first-party local-persistence evidence, not a scalable BookOrbit note store or an offline replication protocol. [Sample archive][drawing-archive].

## Reader integration boundary and offline behavior

`PDFPageOverlayViewProvider`, introduced in iPadOS 16, lets an app provide per-page overlay views. Apple demonstrates `PKCanvasView` overlays, captures drawings when views leave display, and describes PDFKit requesting/releasing views according to display needs. [Overlay protocol][pdf-overlay], [WWDC22 demonstration][pdf-session]. **Inference:** this is a credible seam to prototype for PDF page ink; it does not prove gesture coexistence, zoom/rotation alignment, palm rejection, or persistence in BookOrbit. Avoid interpreting the example's in-memory page mapping as a large-library storage design.

`UIViewRepresentable` provides the public bridge from a UIKit view into SwiftUI. [SwiftUI bridge][ui-bridge]. **Unknown:** neither that bridge nor PencilKit establishes the EPUB renderer, EPUB reflow anchoring, PDF passage anchors, or the behavior of an overlay over a chosen web/native renderer. EPUB page ink and passage-linked notes require their own layout/anchor design and device validation, with equal attention to PDF. This ticket makes no renderer selection.

**Inference:** the local drawing serialization APIs and first-party sample provide building blocks for offline ink edits, but the app must implement durable saves, note identity, revision/conflict handling, retries, deletion, and synchronization to BookOrbit. API support is not evidence that these already exist. [Serialize][serialize], [restore][restore], [local-save sample][drawing-archive]. The existing private deployment was not accessed; automatic browser refresh/display and reconnect behavior remain unverified.

## Personal installation and maintenance limits

These are documented options and constraints, not a recommendation to purchase membership or choose a distribution route.

| Route                                              | Official evidence                                                                                                                                                                                                                                                                                 | Maintenance and unknowns                                                                                                                                                                                                                                                           |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Free Apple Account, Xcode Personal Team            | Apple permits installing/testing on a personal device from Xcode. Limits: 10 App IDs, 3 registered devices, and 3 installed apps per device; App IDs/devices and provisioning expire after 7 days. Apple says to rebuild and reinstall after expiry. [Developer account overview][personal-team]. | Regular reprovisioning is part of this route. **Inference:** an offline reading promise cannot ignore an expired installation. Account access and a compatible development environment are unconfirmed.                                                                            |
| Developer Program, development/ad hoc installation | Ad hoc provisioning uses the matching App ID, distribution certificate, and registered devices; Xcode can manage profiles. Exported apps can be installed using Apple's device tools. [Ad hoc profile][ad-hoc], [registered-device distribution][device-distribution].                            | Profiles have expiry dates; Apple's current technote says validity varies and is typically no more than a year. This is not a guarantee of a full year for a particular build. Signing/profile renewal and reinstall planning remain necessary. [Provisioning technote][profiles]. |
| Developer Program, TestFlight                      | Apple distributes beta builds through App Store Connect/TestFlight. Builds become unavailable after 90 days. Internal testers are App Store Connect users; external testing can require beta review. [TestFlight overview][testflight].                                                           | Requires recurring build uploads and installations. **Inference:** TestFlight is not an indefinite unattended personal installation. No upload or publication is authorized by this research.                                                                                      |
| App Store distribution, as a boundary comparison   | Apple checks signing/provisioning in its distribution pipeline; final App Store apps do not carry an embedded provisioning profile. [Provisioning technote][profiles].                                                                                                                            | This differs from personal development/ad hoc installation and entails a distribution process. It is not selected here.                                                                                                                                                            |

Developer Mode is required for Xcode-run/local `.ipa` development workflows; Apple's instructions include pairing, enabling the setting, restarting, and confirming on-device. Ordinary App Store and TestFlight installs do not require this mode. [Developer Mode][developer-mode].

For Developer Program teams created after 2021-06-06, Apple documents an internet certificate check at the first launch of development/ad hoc apps. It offers a separate 7-day offline provisioning option and directs requests for extended support when apps must run offline more than 30 days after first launch. **Unknown:** the applicable signing path/team age and its actual offline validity on this user's device. Do not infer indefinite offline launch from local book/note storage. [Provisioning updates][provisioning-updates].

Apple currently lists Developer Program membership at USD 99 per year, with regional pricing differences; annual renewal is separate from a specific profile/build's validity. [Enrollment][enrollment], [renewal][renewal]. No account, region, eligibility, membership, or entitlement capability is assumed for this user.

## Evidence and limitations

- External findings use Apple-owned API documentation, documentation metadata, support pages, WWDC sessions, and first-party sample code retrieved on 2026-10-20. One background helper collected input API facts; the author consolidated and owns this single repository asset. No secondary summaries or third-party header mirrors were used as evidence.
- API introduction versions were checked in Apple's public DocC JSON `metadata.platforms`, for example [PKDrawing metadata](https://developer.apple.com/tutorials/data/documentation/pencilkit/pkdrawing-swift.struct.json) and [PDF overlay metadata](https://developer.apple.com/tutorials/data/documentation/pdfkit/pdfpageoverlayviewprovider.json). These are availability evidence, not proof of the user's installed SDK/OS or a runtime success. Some Apple HTML pages expose only a JavaScript shell to text clients, so their official data payloads were read directly.
- Apple's served documentation includes newer and beta entries. This note does not identify an installed/latest production OS, infer availability from a marketing feature list, or depend on beta APIs. Recheck exact symbols against the chosen Xcode SDK before implementation. [Content-version index][versions].
- No iPad/Pencil was available or tested. Apple's [drawing sample][drawing-sample] and [stroke-inspection sample][inspect-sample] explicitly require a physical device. No claim here establishes that an ink overlay, EPUB renderer, PDF integration, or browser rendering works in the intended app.
- No private server access, production changes, dependency installation, migration, app code, or parent-ticket edits were performed. BookOrbit authentication, authorization, storage, ownership, browser refresh, and offline sync were not audited by this API research.

## Unresolved decisions and their implications

1. **Device and deployment baseline:** confirm exact iPad/Pencil models, OS, supported tool capabilities, and available Xcode/Mac environment. Until then, availability checks and fallback interaction requirements cannot be finalized.
2. **Ink and typed-note representation:** choose source/archive version policy and browser display format, and define how Scribble-produced text coexists with preserved ink. Neither conversion nor a flattened export satisfies both requirements alone.
3. **PDF and EPUB anchoring:** decide page coordinate transforms, reflow behavior, and passage links for both formats. The PDF overlay API does not answer EPUB reflow or passage identity.
4. **Sync and offline durability:** define local transaction/autosave behavior, revision boundaries, conflicts, export regeneration, and automatic browser updates. PencilKit does not supply a BookOrbit synchronization protocol.
5. **Installation upkeep:** select a personal distribution route only after confirming account circumstances and acceptable renewal/reinstall effort, including offline launch limitations.
6. **Device validation:** measure writing latency and memory use, verify palm/gesture coexistence and tool/interaction preferences, round-trip editable archives, and compare exported appearance in the existing MacBook/Android browsers. These are open validation tasks, not completed acceptance checks.
