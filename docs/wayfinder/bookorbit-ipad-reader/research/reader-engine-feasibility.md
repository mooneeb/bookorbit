# iPad reader engines and annotation anchors

Research date: **2026-10-20**. Repository baseline: `ce118e3890ea8c9019857cb7556552cdc9992f8e`.

This is evidence for the reader-engine feasibility question, not a renderer selection or implementation specification. EPUB and PDF receive equal priority. The accepted requirements include page ink, passage-linked typed and ink notes, editable handwriting, Scribble text entry, offline reading and note edits, and later automatic delivery to the existing browser app. Only iPad needs ink editing. Sources: [ticket question](https://github.com/mooneeb/bookorbit/issues/3), [accepted brief](../brief.md), [reading-note vocabulary](../../../../GLOSSARY.md).

**Evidence labels:** **Documented** means an API, standard, or source implementation was inspected. **Demonstrated** refers to an upstream example, not a BookOrbit integration. **Inference** is a consequence or candidate design derived from evidence. **Unknown** requires a decision or validation. External sources were consulted on the research date; versioned links identify the inspected release where available.

## Findings that constrain the design

- **PDF has a demonstrated native integration route.** Apple's WWDC22 example combines PDFKit/PencilKit, including scrolling/zooming and saving an appearance plus editable drawing data. BookOrbit integration remains untested. [Apple, WWDC22, 2022](https://developer.apple.com/videos/play/wwdc2022/10089/).
- **EPUB passage identity and page geometry are separate concerns.** EPUB defines reflowable and pre-paginated layouts; changing reflow geometry does not define how freehand marks should move. **Inference:** fixed viewport coordinates, including normalized coordinates, cannot preserve an underline or arrow's intended relationship to text after arbitrary reflow. [EPUB 3.3, W3C Recommendation, 2026-01-13, layout](https://www.w3.org/TR/2026/REC-epub-33-20260113/#sec-layout).
- **Readium and Foliate positions are not interchangeable by declaration.** BookOrbit creates full EPUB CFIs; Readium Swift 3.11.0's inspected passage resolver uses quoted text, CSS selectors, and HTML IDs. Its resolver does not consume `partialCfi` or `domRange`, even though the broader locator model defines them. [BookOrbit CFI production](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/public/assets/foliate/view.js), [Readium resolver, 3.11.0](https://github.com/readium/swift-toolkit/blob/3.11.0/Sources/Navigator/EPUB/Scripts/src/utils.js#L275), [HTML locator extension](https://readium.org/architecture/models/locators/extensions/html.html).
- **A renderer does not fulfill the complete notes requirement.** Existing BookOrbit input/shared types expose text, CFI/PDF geometry, and note strings, without an editable ink document. **Inference:** all routes need additional local persistence, synchronization, and browser ink-display work; renderer choice alone cannot supply automatic note delivery. [Create DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/dto/create-annotation.dto.ts), [shared annotations](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/annotation.ts), [current PDF REST store](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/composables/usePdfAnnotations.ts).

## Native PDF feasibility

### Selection, passage notes, and page ink

**Documented:** `PDFView` supports selection/navigation/zoom; `currentSelection` exposes a `PDFSelection`. A selection can span pages and expose text, per-page bounds, per-line selections, and text ranges. `PDFAnnotation` supports text contents, ink paths, and text-markup quadrilaterals. These are primitives for passage notes and native PDF annotations, not an application note model. [PDFView](https://developer.apple.com/documentation/pdfkit/pdfview), [document interactions](https://developer.apple.com/documentation/pdfkit/document-interactions), [PDFSelection](https://developer.apple.com/documentation/pdfkit/pdfselection), [PDFAnnotation](https://developer.apple.com/documentation/pdfkit/pdfannotation).

**Documented and demonstrated:** `PDFPageOverlayViewProvider`, introduced with iOS 16, supplies views per page as PDFKit requests them. PDFKit sizes and rotates the overlays; the lifecycle provides hooks to configure interaction and release offscreen views. Apple's example stores/restores a PencilKit drawing. **Inference:** this supports bounded active canvases rather than one live canvas for every page. A minimum deployment target remains a product decision. [WWDC22 overlay example](https://developer.apple.com/videos/play/wwdc2022/10089/), [current overlay protocol](https://developer.apple.com/documentation/pdfkit/pdfpageoverlayviewprovider).

**Editable versus portable representations:** `PKDrawing` supports serialized data, reconstruction, stroke access, image generation, and affine transforms. Apple's PDF example saves drawing data separately from an annotation appearance; burning annotations into the PDF is another save option. **Inference:** an appearance or preview alone cannot replace the editable ink original. Standard PDF ink paths do not establish lossless PencilKit tool/stroke round trips. Keep embedded annotation data and external sidecar data as alternatives; neither storage policy is chosen here. [PKDrawing](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct), [PDF ink paths](https://developer.apple.com/documentation/pdfkit/pdfannotation/paths), [WWDC22 saving example](https://developer.apple.com/videos/play/wwdc2022/10089/).

### Crop, rotation, zoom, and file identity

**Documented:** PDFKit converts view coordinates to/from page coordinates. Apple's conversion documentation describes page space as 72 dpi with a lower-left origin. `PDFPage.bounds(for:)` distinguishes media/crop boxes, intersects boxes with the media box, and warns about rotation transforms. [Point conversion](<https://developer.apple.com/documentation/pdfkit/pdfview/convert(_:to:)-9twqk>), [page bounds](<https://developer.apple.com/documentation/pdfkit/pdfpage/bounds(for:)>), [page/view conversions](https://developer.apple.com/documentation/pdfkit/document-interactions).

BookOrbit's persisted `AnnotationPdfPosition` instead defines **unscaled points with a top-left origin and zero-based page index**. It stores a bounding rectangle plus segment rectangles, not arbitrary oriented quadrilaterals. Its PDF renderer maps those directly to EmbedPDF objects. **Inference:** native reuse requires an explicit invertible adapter; a universal Y flip is insufficient evidence for cropped pages with nonzero origins, intrinsic page rotation, viewer rotation, and differing display boxes. Screen pixel coordinates must not become persisted PDF coordinates. [Shared PDF position contract](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/annotation.ts), [PDF rendering adapter](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/lib/pdf-annotation-render.ts), [current rotation/zoom configuration](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/PdfV4ReaderView.vue).

**Inference:** for unchanged PDF bytes, page geometry can survive viewport zoom and device orientation through coordinate transforms. Page replacement/reordering or changed crop/content is a different identity problem. Existing `bookFileId` identifies the file record, but the inspected annotation position contract does not carry a content revision/hash. Preserve this as a specification gap, including cross-engine text-range differences and rotated text that axis-aligned rectangles may approximate. [PDFKit page model](https://developer.apple.com/documentation/pdfkit/pdfpage), [BookOrbit create DTO](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/dto/create-annotation.dto.ts), [shared position contract](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/annotation.ts).

**Offline/scale:** `PDFDocument` can open a file URL or data. A downloaded local file is therefore a supported input, without assuming remote streaming or retaining the full book as application `Data`. Apple's overlay lifecycle supports selective view creation, but supplies no measured memory limit for this app. **Unknown:** performance on large image-heavy PDFs, dense ink, long searches, and repeated edit/save cycles. Scan-only PDFs still permit page ink; selection is not a requirement to introduce OCR. [PDFDocument](https://developer.apple.com/documentation/pdfkit/pdfdocument), [overlay lifecycle](https://developer.apple.com/documentation/pdfkit/pdfpageoverlayviewprovider), [PDFPage selection APIs](https://developer.apple.com/documentation/pdfkit/pdfpage).

## EPUB feasibility and stable passage identity

### Readium Swift

**Maintenance baseline:** the latest stable release inspected is **3.11.0, released 2026-07-17**. **4.0.0-alpha.2, released 2026-09-18**, is a prerelease, including mixed-layout changes that must not be assumed in stable 3.11.0. The stable package declares iOS 15 minimum. Pinning a release matters because Readium warns that minor upgrades may include small breaking changes. [Stable release](https://github.com/readium/swift-toolkit/releases/tag/3.11.0), [dated announcement](https://blog.readium.org/release-note-swift-toolkit-version-3-11-0/), [alpha release](https://github.com/readium/swift-toolkit/releases/tag/4.0.0-alpha.2), [package manifest](https://github.com/readium/swift-toolkit/blob/3.11.0/Package.swift).

**Documented:** custom EPUB selection-menu actions can read `currentSelection`, its locator, selected text, and frame in navigator-view coordinates. The app owns highlight persistence, note editors, and surrounding UI. Decorations associate IDs/locators/styles and render through injected HTML/CSS templates, with update diffing. **Inference:** these are credible passage-note/highlight seams; a native editable `PKCanvasView` needs additional composition. The examined public API does not supply PDFKit's per-page native overlay provider. [Highlights](https://github.com/readium/swift-toolkit/blob/3.11.0/docs/Guides/Navigator/Highlights.md), [decorations](https://github.com/readium/swift-toolkit/blob/3.11.0/docs/Guides/Navigator/Decorations.md), [WebKit spread implementation](https://github.com/readium/swift-toolkit/blob/3.11.0/Sources/Navigator/EPUB/EPUBSpreadView.swift#L40).

**Source-level limitation:** the 3.11.0 selection bridge returns resource href, text/context, and a rectangle. The Swift callback copies `currentLocation` and replaces its text. Its JS resolver uses `TextQuoteAnchor`, optionally scoped by CSS selector, or falls back to CSS/HTML IDs. It does not resolve `partialCfi`/`domRange` there. **Inference:** repeated identical passages need explicit ambiguity handling; a generic `Locator` label is not proof of precise cross-engine range identity. [Selection bridge](https://github.com/readium/swift-toolkit/blob/3.11.0/Sources/Navigator/EPUB/Scripts/src/selection.js#L15), [Swift callback](https://github.com/readium/swift-toolkit/blob/3.11.0/Sources/Navigator/EPUB/EPUBNavigatorViewController.swift#L1106), [resolver](https://github.com/readium/swift-toolkit/blob/3.11.0/Sources/Navigator/EPUB/Scripts/src/utils.js#L275).

**Offline and layout:** `AssetRetriever` accepts local `FileURL` assets; HTTP resources stream rather than automatically become downloads. Preferences change fonts, sizing, columns, spacing, and related layout settings. **Inference:** the host must own complete local book availability, fonts/resources, durable note edits, and queued sync. Local ZIP availability alone does not settle external-resource availability. [Opening publications](https://github.com/readium/swift-toolkit/blob/3.11.0/docs/Guides/Open%20Publication.md), [preferences](https://github.com/readium/swift-toolkit/blob/3.11.0/docs/Guides/Navigator/Preferences.md).

### Standards and conversion constraints

**EPUB CFI 1.1:** the stable IDPF Recommended Specification is dated **2017-01-05**; W3C also hosts the CFI text. It defines structural points/ranges, package indirection, character offsets counted in UTF-16 units, and assertions/correction mechanisms. **Inference:** CFIs can identify content independently of page layout, but file/DOM changes and implementation differences still require verification. A W3C-hosted copy should not be mislabeled a newer W3C Recommendation. [Dated CFI specification](https://idpf.org/epub/linking/cfi/epub-cfi-20170105.html), [W3C-hosted text](https://w3c.github.io/epub-specs/epub33/epubcfi/index.html).

Readium's locator model separates resource href/type, locations, and text before/highlight/after. Its HTML extension's `partialCfi` omits the EPUB package path and `epubcfi(...)` wrapper. **Inference:** even a renderer that supports that field would need conversion from BookOrbit's full CFI and agreement about DOM construction. Storing a CFI string under another engine's locator key is insufficient. [Locator model](https://readium.org/architecture/models/locators/), [HTML extension](https://readium.org/architecture/models/locators/extensions/html.html), [BookOrbit CFI creation/resolution](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/public/assets/foliate/view.js).

The **2017-02-23 W3C Web Annotation Recommendation** defines `TextQuoteSelector` with exact/prefix/suffix and normalized text; text positions count Unicode code points. It warns that position selectors are brittle under edits, and quote selectors can match more than one passage. **Inference:** CFI offsets, Readium raw DOM text, and standardized text selectors require explicit normalization/conversion rules. Combining engine-native positions with quotes/context and file revision identity is a candidate recovery strategy, not a guarantee or a selected contract. [Web Annotation selectors](https://www.w3.org/TR/2017/REC-annotation-model-20170223/#selectors), [Readium selection text implementation](https://github.com/readium/swift-toolkit/blob/3.11.0/Sources/Navigator/EPUB/Scripts/src/selection.js).

### What can preserve EPUB ink intent after reflow?

The following are **design inferences**, not demonstrated automatic remapping algorithms. They follow from the distinction between content anchors and EPUB rendering geometry. [EPUB layout definition](https://www.w3.org/TR/2026/REC-epub-33-20260113/#sec-layout), [Readium layout preferences](https://github.com/readium/swift-toolkit/blob/3.11.0/docs/Guides/Navigator/Preferences.md), [CFI content anchors](https://idpf.org/epub/linking/cfi/epub-cfi-20170105.html).

1. **Preserve an annotated layout or page snapshot.** Save its page content/layout identity and editable ink coordinate system. Reopen that representation for page ink; retain a separate passage anchor for navigation into reflowed text. This preserves spatial marks but creates storage, navigation, and accessibility questions. Recording only font/orientation settings is weaker than preserving the rendered content because fonts and engine layout can change.
2. **Use passage-linked editable canvases.** An anchored handwritten card can move with the passage while its internal ink geometry stays intact. This supports passage-linked ink notes; it does not by itself satisfy the separate requirement for page ink.
3. **Remap strokes to content.** Attach stroke groups to words/elements and recompute positions. This may support simple underlines, but arrows crossing paragraphs, diagrams, margin notes, tables, and line-break changes lack an established general transform in the examined APIs. It needs substantial validation before a build-ready claim.
4. **Restrict the annotated layout.** Keep page ink attached to a frozen rendition or offer an explicit annotated view after layout changes. This trades away some free reflow and must specify how font changes, rotation, and split-screen resizing behave. A fixed-layout EPUB naturally has intrinsic dimensions, but is not equivalent to converting every reflowable EPUB into fixed pages.

**Unknown:** which combination meets the user's desired interaction. Do not silently discard page ink, flatten the editable original, or claim that passage-linked canvases replace page ink. The behavior remains a decision ticket, grounded in the [accepted brief](../brief.md).

## Reusing BookOrbit's web implementations

### Foliate EPUB

BookOrbit already turns DOM selections into CFIs with `getCFI(index, range)`, resolves them through its vendored code, and draws annotation styles from current range rectangles. It has customized vendored modules and a server-backed EPUB loader. **Inference:** reusing this exact code is the shortest compatibility route for existing web CFIs, but still needs round-trip fixtures; it is not evidence for another engine's behavior. [Selection composable](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/epub/composables/useFoliateSelection.ts), [CFI methods](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/public/assets/foliate/view.js), [annotation rendering](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/epub/composables/useFoliateAnnotations.ts), [streaming loader](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/public/assets/foliate/streaming-loader.js).

Upstream documents local File/Blob inputs, section loading/unloading, CFI support, SVG overlays, and CSS-column pagination. It also calls the library unstable, with no release, and targets recent WebKitGTK/Firefox/Chromium rather than explicitly promising iPad WKWebView. **Unknown:** the vendored fork's exact upstream revision and iPad compatibility. Its arbitrary SVG overlay mechanism is not a ready-made PencilKit editor or proof of reliable freehand reflow. [Foliate interfaces/status](https://github.com/johnfactotum/foliate-js#readme), [vendored module](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/public/assets/foliate/view.js).

### EmbedPDF/PDFium PDF

BookOrbit pins **2.15.1**, applies four local patches, imports the WASM asset, enables a worker, buffers the fetched PDF before opening it, limits open documents to one, and uses scrolling buffers/tiling. Annotation `autoCommit` is false and the plugin is locked; the database-backed adapter supplies its highlights. **Inference:** current usage is a reusable display/selection integration, not already an editable ink document workflow. Virtualized page rendering does not remove the whole-file buffer or prove bounded total document memory. [Dependencies](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/package.json), [patch registration](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/pnpm-lock.yaml), [reader setup/opening](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/PdfV4ReaderView.vue), [viewport layers](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/components/PdfDocumentViewport.vue), [highlight orchestration](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/composables/usePdfHighlights.ts).

Upstream v2 lists selection, ink annotations, zoom/rotation, and virtualized scrolling; current main explicitly warns that v3 is unfinished and points to v2 for stable use. **Unknown:** current documentation examples' exact compatibility with patched 2.15.1. Native reuse of PDFium alone would omit the Vue/plugin UI and still need native navigation/selection/ink integration. [v2 README](https://github.com/embedpdf/embed-pdf-viewer/blob/v2/README.md), [current main warning](https://github.com/embedpdf/embed-pdf-viewer#readme), [Vue engine documentation](https://www.embedpdf.com/docs/vue/headless/engine).

### Native host and offline boundaries

Apple documents local file/HTML loading in `WKWebView`, script messages to native code, and custom scheme resource handling. **Inference:** a native shell can bridge visible EPUB/PDF geometry and annotation events to an overlaid PencilKit canvas. These APIs do not establish correct alignment during pagination, nested-frame scrolling, crop/rotation/zoom, process reloads, or simultaneous touch/selection gestures. Origin/CSP, local module loading, worker/WASM loading, and font URLs must be verified together. [WKWebView](https://developer.apple.com/documentation/webkit/wkwebview), [script-message handler](https://developer.apple.com/documentation/webkit/wkscriptmessagehandler), [scheme handler](https://developer.apple.com/documentation/webkit/wkurlschemehandler), [Foliate documented WebKit/CSP constraints](https://github.com/johnfactotum/foliate-js#security).

The current EPUB path requests `/epub/:bookId/info` and individual resources; the PDF path fetches `/books/files/:fileId/serve`. The PWA configuration excludes Foliate assets from precaching and its precache patterns omit WASM. These configurations do not establish full offline reader availability. The published 2.15.1 engine additionally defines CDN fallback-font URLs. **Inference:** native hosting needs an explicit local resource strategy, including fonts, reader code, and WASM, rather than assuming a previously opened web page is fully downloaded. [EPUB open](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/epub/composables/useFoliate.ts), [PDF open](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/PdfV4ReaderView.vue), [PWA configuration](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/vite.config.ts), [published engine artifact, `dist/lib/pdfium/index.js`](https://registry.npmjs.org/@embedpdf/engines/-/engines-2.15.1.tgz).

Existing EPUB/PDF note composables write immediately through REST; the inspected implementations do not provide a durable offline edit queue. The EPUB composable also loads the unpaginated annotation list, whereas the PDF composable requests pages. **Inference:** browser reuse must not carry whole-book note accumulation into a large-library/native design. Automatic browser refresh/receipt, deletion/conflict behavior, attachment transfer, and recovery after offline relaunch require a separate sync contract, regardless of renderer. [EPUB note store](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/epub/composables/useAnnotations.ts), [PDF note store](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/composables/usePdfAnnotations.ts), [controller's two list shapes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation.controller.ts), [device-specific existing sync inputs](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/server/src/modules/annotation/annotation-sync.service.ts).

## Input, accessibility, scale, and licenses

**Scribble:** Apple describes Scribble as on-device text entry using existing text-input APIs, including UIKit text controls and standard editable WebKit content. Custom editors must implement the text-input contracts correctly. **Inference:** a typed-note editor can use Scribble offline without converting stored ink notes to text; its interaction must remain distinct from drawing on the page. Physical-device testing is required by Apple's Scribble sample. [Meet Scribble for iPad, WWDC20](https://developer.apple.com/videos/play/wwdc2020/10106/), [Scribble sample requirements](https://developer.apple.com/documentation/pencilkit/customizing-scribble-with-interactions).

**Cross-device ink display:** PencilKit documents native drawing serialization and image generation, not a browser API to read `PKDrawing` data. **Inference:** preserving the editable iPad original alongside a browser-displayable derivative is a credible route; a PDF annotation appearance is another PDF-specific route. The precise derivative, revision linkage, and browser placement remain open. Neither OCR nor a native Android/Mac app is needed to display an exported appearance. [PKDrawing](https://developer.apple.com/documentation/pencilkit/pkdrawing-swift.struct), [PDF annotation appearance](https://developer.apple.com/documentation/pdfkit/pdfannotation/hasappearancestream), [existing annotation response contract](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/annotation.ts).

**Accessibility:** Readium has accessibility metadata/display guidance and source that adjusts EPUB behavior for VoiceOver, including scroll mode. UIKit supplies accessibility behavior and custom-element APIs; PDFKit exposes accessibility extraction permission. These facts do not prove reading order, tagged-PDF behavior, or custom ink-overlay accessibility. **Unknown:** VoiceOver focus through passages/notes, large text, keyboard navigation, and web viewer semantics on actual devices. An image of handwriting is not automatically accessible text, and OCR remains outside the brief. [Readium accessibility guide](https://github.com/readium/swift-toolkit/blob/3.11.0/docs/Guides/Accessibility.md), [VoiceOver source](https://github.com/readium/swift-toolkit/blob/3.11.0/Sources/Navigator/EPUB/EPUBSpreadView.swift#L558), [UIKit accessibility](https://developer.apple.com/documentation/uikit/accessibility-for-uikit), [PDF accessibility permission](https://developer.apple.com/documentation/pdfkit/pdfdocument/allowscontentaccessibility).

**Large books:** Readium exposes preload controls with defaults of two previous and six next positions. Foliate has resource-level loading seams, and BookOrbit's PDF uses scrolling buffers and tiling. **Inference:** these support bounded active rendering but do not prove acceptable worst-case behavior for a giant single EPUB chapter, scanned PDF, or thousands of ink notes. ## Unresolved decisions and their implications

These are follow-up implications, not product resolutions. They derive from the source-backed boundaries above.

1. **Renderer composition:** compare Readium EPUB/PDFKit PDF, Foliate EPUB/PDFKit PDF, and both existing web readers under a native host. Require equivalent proof for EPUB and PDF rather than accepting a shared wrapper as parity.
2. **EPUB page-ink behavior:** choose how page ink is revisited after reflow, and how that differs from passage-linked ink canvases. Font, orientation, split-screen, and accessibility changes belong in this behavior definition.
3. **Anchor compatibility:** decide whether to retain multiple engine positions and recovery context. Before claiming reuse, demonstrate exact or explicitly unresolved round trips, including duplicate passages and file replacement. Define normalization, range boundaries, file revision identity, and ambiguity status.
4. **PDF coordinate/storage contract:** specify page space, display box, rotation, page indexing, and editable-original versus portable-appearance handling. Keep sidecar versus embedded storage open until its sync and file-version consequences are reviewed.
5. **Offline and automatic browser delivery:** define durable local edits, later transfer, conflicts/deletions, attachment revisions, and browser update behavior independently of the renderer. Keep queries/assets bounded and user-scoped, following [project constraints](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/AGENTS.md).

### Smallest validation set needed before a build-ready claim

These are proposed evidence gates, not work performed in this research:

- **EPUB anchor/reflow fixture:** create and reopen passage notes in both engines with repeated paragraphs, RTL, emoji/combining marks, changed font/spacing/columns, portrait/landscape, split-screen widths, fixed-layout content, and cross-resource selection attempts. Show which cases resolve exactly, are ambiguous, or are unsupported. Check both native-to-web and web-to-native navigation.
- **PDF geometry fixture:** native-to-web and web-to-native notes on pages with nonzero media/crop origins, intrinsic and viewer rotations, mixed sizes, rotated text, zoom, and multipage selections. Verify per-page ink alignment after relaunch.
- **Input/accessibility fixture:** Pencil draw/erase/lasso/undo without unintended text selection or page turns; touch selection/scrolling; Scribble typed-note entry; VoiceOver focus and passage/note navigation. Exercise PDF and EPUB independently.
- **Offline/scale fixture:** download, disconnect, cold-open, create/edit/delete notes, terminate/relaunch, reconnect, and verify browser appearance on MacBook/Android while editable iPad strokes remain intact. Include a large PDF, a giant EPUB chapter, and dense annotations; observe memory and bounded loading.
