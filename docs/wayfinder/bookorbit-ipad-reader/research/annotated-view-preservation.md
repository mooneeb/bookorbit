# Preserving original annotated EPUB and PDF views

Research date: **2026-10-20**. BookOrbit baseline: `ce118e3890ea8c9019857cb7556552cdc9992f8e`. Research only. No representation, renderer, file schema, or product choice is selected.

## Fixed inputs and evidence labels

The [research question](https://github.com/mooneeb/bookorbit/issues/14) and [settled page-ink behavior](https://github.com/mooneeb/bookorbit/issues/5) are authoritative intake. Normal EPUB reading reflows. A passage marker opens the exact retained annotated view with its original editable ink. Writing after reflow creates another view grouped under the passage. Source replacement retains annotated pages/excerpts, quote context, and notes; moving notes to changed content needs user approval. Ordinary PDF zoom/display rotation is a coordinate change. Complete old editions need not remain readable.

The [accepted brief](../brief.md) gives EPUB and PDF equal priority, requires page ink and passage-linked notes, iPad-only ink editing, Scribble typed-note entry, offline reading/edits, and later automatic display in the existing MacBook/Android browser app. The three prior assets were read as fixed background: [Pencil capabilities](native-pencil-capabilities.md), [reader feasibility](reader-engine-feasibility.md), and [sync foundations](bookorbit-sync-foundations.md). Their ink serialization and overlay evidence does not establish capture of original EPUB book content.

**Documented** means an inspected public API or standard. **Source detail** means inspected upstream implementation, which may be internal. **Demonstrated** means an upstream example, not a BookOrbit test. **Inference** identifies a proposed combination or consequence. **Unknown** identifies an unverified boundary. Fixture checks below are proposals, not completed experiments.

## Decision-relevant findings

1. **The book background must survive independently of the book.** PencilKit serializes drawings, not the EPUB/PDF beneath a canvas. WebKit separately offers image, PDF, and web-content capture. **Inference:** ink plus font settings, a locator, or an old file ID cannot reconstruct missing original content. A retained artifact must include that content, with a defined mapping to the editable drawing. [Drawing serialization][pk-data], [WebKit capture API][wk-header].
2. **Bounded raster capture is a credible visual-preservation path at its retained resolution.** WebKit can capture the visible viewport or an in-bounds subrectangle. **Inference:** saved pixels cease to depend on the original fonts or text layout, but enlarging them cannot recover omitted detail or original text semantics. This is not a guarantee of unlimited zoom or perfect capture of every EPUB feature. [Snapshot bounds][snapshot-rect], [snapshot scale][snapshot-width], [PNG standard][png].
3. **Native PDF has an explicit page-extraction API; EPUB-to-PDF needs a fidelity gate.** `PDFPage.dataRepresentation` returns a PDF document for one page, without external page links. `WKWebView.createPDF` exports web content, but its existence does not prove a paginated EPUB viewport is captured identically. Neither API promises archival font completeness, PDF/A conformance, or preserved accessibility structure. [PDF page export][pdf-page-data], [Web PDF export][wk-pdf], [PDF/A requirements][pdfa].
4. **Self-contained HTML/resources preserve more source semantics, but do not freeze layout.** A WebArchive can retain DOM/subresources and reopen in WebKit. EPUB permits external dependencies, and Readium can add fonts and reader CSS. **Inference:** replay still depends on rendering behavior and complete resources; it is weaker evidence for an exact old view than a validated visual artifact. [Apple demonstration][wk-session], [EPUB resources][epub-resources], [Readium fonts][readium-fonts].
5. **Readium lacks direct public access to its EPUB WebKit capture APIs in the inspected release.** Version 3.11.0 exposes passage/JavaScript/resource interfaces, while its active EPUB web views are internal. UIKit hierarchy drawing is a separate public raster candidate. **Inference:** capture needs an explicit integration and validation plan; a fork is not proven necessary for every raster route. [Navigator public API][readium-nav], [internal spread][readium-spread], [UIKit hierarchy drawing][hierarchy-draw].

## EPUB capture: public capabilities and precise gaps

### WebKit image and PDF capture

**Documented:** `takeSnapshot` is public from iOS 11. `WKSnapshotConfiguration.rect` uses web-view coordinates and must fit inside its bounds. `snapshotWidth` is measured in points and scales the result while retaining aspect ratio; inspect actual image pixel dimensions rather than treating points as pixels. `afterScreenUpdates`, available from iOS 13, incorporates pending screen updates by default. It does not document completion of every font, image, asynchronous script, or pagination operation. [Public header][wk-header], [rect][snapshot-rect], [width][snapshot-width], [updates][snapshot-updates].

**Inference:** capture a middle EPUB page while it is actually displayed, without changing the viewport to the whole chapter. Enlarging a web view to capture all content can change media queries, column count, and pagination. Scrolling through tiles and stitching them is an additional synchronization algorithm, not a documented single-call capture guarantee. Native ink/toolbars outside the WKWebView are separate from its content; DOM highlights/selection inside it require deliberate inclusion or suppression. Host-owned margins/gutters need their own retained background and geometry. [Snapshot bounds][snapshot-rect], [Readium responsive columns][readium-css], [image composition API][image-renderer].

**Alternative public raster route:** UIKit's `UIView.drawHierarchy(in:afterScreenUpdates:)` draws the visible onscreen hierarchy into the current context and returns `false` when image data is missing. **Inference:** drawing the public navigator content view into `UIGraphicsImageRenderer` is a candidate without accessing Readium's internal web view. Exclude native ink/chrome and retain required margins deliberately. This is untested for Readium/WebKit content and supplies neither WebKit PDF export nor resource extraction. Require a complete result and visual checks; do not treat UIKit's `snapshotView`, which returns a view for display, as a durable image file. [Hierarchy drawing][hierarchy-draw], [image renderer][image-renderer], [snapshot view][snapshot-view].

**Documented/source discrepancy:** `createPDF` and `createWebArchiveData` are public from iOS 14. WebKit's public `WKPDFConfiguration.h` describes its rectangle in **web-page coordinates**; Apple's current Swift `rect` reference instead describes **view coordinates**, an in-bounds constraint, and a view-bounds default. Apple's WWDC20 demonstration describes offscreen PDF capture; the inspected upstream implementation defaults to the main frame's content size and uses an explicit rectangle when supplied. These sources do not agree well enough to promise arbitrary capture bounds across iPadOS versions. Treat the chosen SDK/runtime's crop/offset behavior as a required fixture check. Use the public APIs only; internal source explains behavior, not an additional callable contract. [Public headers][wk-header], [PDF configuration header][wk-pdf-header], [Swift rect reference][wk-pdf-rect], [WWDC20][wk-session], [implementation][wk-pdf-source].

**Inference:** a PDF capture must be compared against the actual screen layout before it can satisfy this requirement. Do not replace it with HTML print output at a new paper size, assume every glyph is embedded, or assume a PDF export is wholly vector. Clipped content, CSS/SVG/image effects, and large source images can affect visual fidelity and size. No reviewed API promises a perfect paginated-EPUB export. [PDF export API][wk-pdf], [PDF/A resource requirements][pdfa], [Readium layout implementation][readium-css].

### Coordinate frame and capture readiness

**Documented:** CSSOM View distinguishes viewport geometry, scrolling, zoom, and client rectangles. CSS columns fragment content; one bounding rectangle can enclose more than the intended passage. **Inference:** use explicit transforms between DOM CSS pixels, each frame/spread, the native web view, and the retained artifact. Do not equate a selection's bounding box, a resource progression, or `scrollX` with an exact page boundary. The capture must preserve the area under all page ink, including margins and strokes that cross a column/gutter. [CSSOM View, Working Draft][cssom], [multi-column specification][columns], [Readium selection][readium-selection].

**Source detail:** Readium 3.11.0 uses CSS column gaps, viewport-height sizing, responsive columns, and scroll-mode overrides. Its native insets differ between paged and scrolled mode. Its code explicitly distinguishes negative RTL WebKit `window.scrollX` from nonnegative UIKit content offsets. Fixed-layout spreads use wrapper iframes and convert points using zoom, offsets, and web-view origin. **Inference:** one generic Y flip or `pageIndex * screenWidth` is not a supported geometry adapter. [Bundled CSS][readium-css], [reflowable spread][readium-reflow], [fixed spread][readium-fixed].

**Documented plus inference:** `document.fonts.ready` is a useful font/layout readiness signal, not a promise that all resources or future scripted changes are complete. The CSS Font Loading text is a Working Draft. A capture protocol would need a bounded readiness check for the visible layout, required fonts/images, settled scrolling, and no intervening reflow between content capture and ink-coordinate assignment. Missing-resource, web-process failure, and capture failure cannot silently count as successful preservation. No atomic EPUB capture transaction is supplied by the examined interfaces. [Font readiness][font-ready], [screen-update option][snapshot-updates], [Readium spread implementation][readium-spread].

### Resource retention and offline replay

**Documented:** EPUB 3.3 permits some resources outside the container. Its font-obfuscation scheme depends on publication identity and `encryption.xml`; obfuscation is distinct from encryption. Readium supports publisher, app, bundled, and system fonts. Its parser/deobfuscator transforms supported obfuscated fonts. **Inference:** copying selected XHTML or an EPUB ZIP alone does not establish all rendering dependencies. An extraction must account for linked CSS/imports, font bytes, images/SVG references, applicable external resources, base URLs, and injected reader styles. Raw obfuscated font bytes without the required context are insufficient. System-font names do not preserve unavailable original font bytes. [EPUB resources][epub-resources], [obfuscation][epub-fonts], [Readium font guide][readium-fonts], [deobfuscator][readium-deobfuscator].

**Documented:** Readium `Publication.get` provides resource access; `Streamable.stream` consumes chunks, whereas `read()` accumulates data. **Inference:** a bounded dependency collector is possible, but resource export does not preserve final layout. A WebArchive is a credible local replay input, not a demonstrated page-sized, cross-browser archival format. Do not use WebKit's `_saveResources` private SPI as a public escape hatch. [Publication][publication], [streaming][streamable], [archive API][wk-archive], [upstream SPI change][archive-spi].

**Unknown:** WebArchive capture completeness for actual EPUB font loading, reader-injected styles, blob/custom-scheme URLs, SVG dependencies, canvas/script state, and spread frames. No reviewed public capture API documents a complete dependency manifest or an excerpt-size guarantee. An app-built resource bundle could address selected cases, but “self-contained” requires verification with source bytes and network unavailable. Even complete resource retention does not pin future WebKit layout. [Archive API][wk-archive], [WebKit source/public interface][wk-header], [EPUB layout][epub-layout].

## PDF preservation with equal rigor

**Documented:** `PDFPage.dataRepresentation` returns one page as a PDF document and omits external page links. `PDFDocument.insert` can assemble selected pages. A page can be drawn into a graphics context or rendered as an image; Core Graphics supplies a drawing transform that accounts for the selected box, its intersection with MediaBox, page `/Rotate`, target rectangle, additional rotation, and aspect ratio. **Inference:** there are public primitives for a selected-page PDF excerpt or a bounded raster excerpt without retaining the full edition. This does not prove minimal byte size or identical output for every PDF. [Page export][pdf-page-data], [page insertion][pdf-insert], [drawing][pdf-draw], [drawing transform][pdf-transform].

**Documented:** PDFKit distinguishes media/crop boxes, nonzero page-space origins, and intrinsic page rotation. Its page/view conversion API exists. **Inference:** ordinary viewer zoom, device orientation, and display rotation can reuse retained page content while content and ink are transformed together. Store/reconstruct the capture's page-box and crop-to-artifact mapping rather than persisting screen coordinates. BookOrbit's current shared PDF highlights use top-left unscaled points and zero-based pages, so direct reuse of PDFKit coordinates needs an explicit adapter. [Boxes][pdf-bounds], [page conversion][pdf-convert], [rotation][pdf-rotation], [BookOrbit contract](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/annotation.ts#L74).

**Important limits:** exporting a source page retains its PDF appearance description, not necessarily a reader's temporary inversion, tint, page shadow, or extra margins. Changing CropBox establishes display bounds but is not evidence of discarding content/resources outside them. A single page can still contain a huge image or shared font. **Inference:** a clipped redraw or raster derivative may be needed for a chosen bound/appearance, with different text/vector tradeoffs. No such policy is selected. Font embedding and self-containment must be inspected; an ordinary PDF export must not be advertised as PDF/A. [Boxes][pdf-bounds], [drawing/transform][pdf-transform], [page export][pdf-page-data], [PDF/A distinction][pdfa].

**Demonstrated:** Apple's WWDC22 example supplies `PKCanvasView` overlays, stores drawings when overlays leave display, and saves a custom annotation appearance plus editable drawing data. It also demonstrates burn-in. PDFKit sizes/rotates overlays, but saving their content is explicit. **Inference:** this is credible for editing preserved PDF excerpts; standard appearance display does not make PencilKit archives editable in other PDF tools. Preserve book background independently of newly added ink so erasing/moving ink can reveal the original content. [Overlay API][pdf-overlay], [Apple demonstration][pdf-session].

**Unknown:** page extraction's treatment of document-level tags/reading order, forms, layers, unusual fonts, and references in the specific fixtures. `PDFPage.string` and `PDFSelection.string` expose text when present; image-only pages have no established selectable text here. Retain available quote/note context and report unavailable extraction instead of introducing an OCR requirement. [Page text][pdf-text], [selection text][pdf-selection-text], [page export limit][pdf-page-data].

## Ink, appearance, text context, and browser display

**Documented:** PencilKit restores serialized drawings, exports an image for a specified drawing-space rectangle/scale, and has a context-drawing API from iPadOS 26 with an explicit dark-style parameter. Its content-version rules can prevent older systems from opening newer inks. **Inference:** retain the editable original with the capture coordinate mapping; render previews from the same ink revision. Do not transform and overwrite the only editable original merely to fit a browser size. A flattened preview cannot supply later erase/lasso operations. [Restore][pk-restore], [image export][pk-image], [context drawing][pk-context], [compatibility][pk-compat].

**Inference, independent of file schema:** distinguish the original book-content appearance, the editable ink, and any derived composite. Their association must preserve capture dimensions/origin, crop/margins, units, scale/rotation transform, source-content association, and appearance. The passage anchor groups/navigation-links views; it does not replace this geometry. New-layout ink must not overwrite an earlier background. Replacement must not regenerate an old view against new bytes. These are consequences of the settled behavior, not proposed table/field definitions. [Settled behavior](https://github.com/mooneeb/bookorbit/issues/5), [image coordinate contract][pk-image], [PDF geometry][pdf-transform].

**Appearance:** Readium's bundled night/sepia CSS can change text/background and image blending/inversion. WebKit PDF export has a public transparent-background option from iOS 17. **Inference:** freeze and retain the original content/ink appearance for the exact annotated view. Automatically re-theming an old image or replaying HTML under new dark/light settings is not equivalent. An alternate appearance would need explicit derivation/fidelity rules; none is selected. Test dynamic ink colors, transparency/highlighters, page backgrounds, and image contrast together. [Readium CSS][readium-css], [PDF transparency][wk-pdf-transparent], [PencilKit appearance API][pk-context].

**Text/accessibility:** Web Annotation defines quote selectors with exact text and surrounding context, while warning about ambiguous matches. **Inference:** retained quotes and available page/excerpt text can support passage labels, reading context, and accessible alternatives independently of a visual capture. They do not authorize relinking to changed content or reconstruct original page layout. A raster preview alone is not an accessible text rendition, and searchable PDF output is not proof of tags/reading order. Scribble-produced typed notes remain text; no ink OCR is required. [Web Annotation Recommendation][text-quote], [PDF text API][pdf-text], [Scribble demonstration][scribble], [settled behavior](https://github.com/mooneeb/bookorbit/issues/5).

**Browser:** PNG has standardized lossless raster/alpha representation; BookOrbit already has a PDF viewing path. **Inference:** an authenticated image or supported PDF derivative can display retained content plus ink in the existing browser, alongside the separately stored editable iPad original. Separate layers need the identical frame/aspect mapping; a composite avoids browser stroke rendering but must track the corresponding revision. WebArchive is not an established Android delivery artifact. No new native Mac/Android app is needed for these display paths. [PNG][png], [existing PDF reader](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/pdf-v4/PdfV4ReaderView.vue), [archive interoperability limit][archive-spi], [PencilKit output][pk-image].

**BookOrbit gap:** the inspected shared annotation shape has text, positions, and note strings, without retained backgrounds or ink assets. Current EPUB note writes use online REST and current hub refresh code loads server lists. **Inference:** adding a capture format does not supply offline durability, asset revision association, upload/retry, or automatic refresh in an already-open browser. Those remain backend/web/sync work under the accepted scope, with user-scoped bounded access. This is a source observation, not a claim about `books.mooneeb.dev`. [Shared shape](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/packages/types/src/annotation.ts#L85), [EPUB writes](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/reader/epub/composables/useAnnotations.ts#L13), [hub loading](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/client/src/features/annotations/composables/useAnnotationsHub.ts#L108), [project rules](https://github.com/mooneeb/bookorbit/blob/ce118e3890ea8c9019857cb7556552cdc9992f8e/AGENTS.md).

## Size, memory, and offline bounds

The examined capture methods return an image or `Data`; they do not supply a BookOrbit-safe maximum document size or memory budget. Readium streaming can bound resource accumulation, but WebKit PDF/archive output and PencilKit image generation still require explicit limits. **Inference:** cap retained area/page count, output pixels/bytes, dependency bytes, capture concurrency, and active canvases; release work between views. A giant single EPUB chapter is not a bounded page merely because only one resource is open. [WebKit outputs][wk-header], [streaming versus read][streamable], [PencilKit image generation][pk-image], [overlay lifecycle][pdf-overlay].

**Illustrative arithmetic, not a measured limit:** an assumed 8-bit RGBA decode costs at least `width * height * 4` bytes before other surfaces/copies. A 2000 x 3000 image is about 22.9 MiB; doubling both dimensions gives about 91.6 MiB. PNG file compression does not remove decoded-pixel costs. A thousand retained views averaging 1 MiB already occupy roughly 1 GiB before ink and previews. No pixel size, retention quota, or zoom ceiling is selected here. [PNG image/color model][png], [configurable image dimensions/format][image-renderer].

**Inference:** successful offline reopen needs durable local background, editable ink, geometry, text context, and any required reader resources before source deletion/replacement. A preview must not be the only surviving copy of editable strokes; an uncaptured view cannot be recovered later from a locator after source loss. Capture/asset failure must be distinguishable from a complete retained view. Later sync must tolerate interrupted transfers and metadata/assets arriving separately, and old view assets cannot be garbage-collected while still referenced by retained notes. These are storage/recovery implications for later decisions, not a finalized transaction or file schema. [Drawing restoration][pk-restore], [local WebArchive replay][wk-session], [Apple background transfer requirements][background-transfer], [settled retention requirement](https://github.com/mooneeb/bookorbit/issues/5).

## Unresolved decision implications

- **Domain/storage:** decide ownership and identity of a passage group, each immutable retained background, and evolving editable ink, including source revision/relink approval. Multiple retained layouts cannot fit an implicit single-page-per-passage assumption.
- **Representation:** choose a validated visual fidelity/zoom/text-context contract for EPUB and PDF, then compare raster, fixed PDF, resource packages, or combinations against it. “PDF” alone does not guarantee embedded fonts; “self-contained HTML” alone does not guarantee stable layout.
- **Stack:** require an explicit supported capture seam and readiness/geometry contract. Compare Readium with public UIKit raster drawing, added direct WebKit hooks, and an app-owned WKWebView without assuming equal fidelity or maintenance cost.
- **Bounds/recovery:** set per-view pixels/bytes/dependency/page limits, oversized-content behavior, failure visibility, local durability, and referenced-asset retention before treating a note as preserved.
- **Appearance/browser/accessibility:** decide capture-appearance treatment, enlarged-display expectations, text-context availability, and browser surfaces. Keep display derivatives linked to the ink/background revision; automatic delivery remains a sync requirement.

These implications follow from the preceding cited evidence and fixed behavior. They are not new user decisions or a schema recommendation.

The private-SPI history is separately pinned. GitHub API metadata was rate-limited; public raw source and `git ls-remote` were used without cloning/installing.

CSSOM View and CSS Font Loading sources are Working Drafts, not Recommendations. EPUB 3.3 and Web Annotation use dated W3C Recommendations. No beta/private API is required or proposed; API availability does not select the deployment target.

In particular, original EPUB page capture remains an untested combination until the fixture gates pass. Source-level negative findings are limited to the named inspected interfaces, not proof that all future versions lack a hook.

The parent checkout, tickets/status, map, glossary, app code, project setup, database, private server, and production were not changed. No application dependencies were installed, and no artifact was published.

The PDF Association page rejected the terminal client with HTTP 403 but was retrieved through the web reader.
