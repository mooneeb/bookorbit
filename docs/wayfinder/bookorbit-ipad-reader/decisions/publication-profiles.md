# Unprotected book support and partial reading

Complete proposal for [Define supported EPUB and PDF publication profiles](https://github.com/mooneeb/bookorbit/issues/23). All eleven live choices are accepted; the issue holds final shared-understanding confirmation and resolution status. This specifies first-version requirements and future acceptance, without claiming production support or authorizing implementation.

## Accepted scope

The [first live round](https://github.com/mooneeb/bookorbit/issues/23#issuecomment-6397939205) establishes:

1. Require both reflowable and fixed-layout EPUB reading, keeping designed fixed pages intact. EPUB handwriting remains inside notes attached to actual selectable words.
2. Require horizontal LTR, RTL and mixed-direction text. Vertical writing is outside the initial required profile.
3. Initially require static PDF reading, search, selection, navigation and reading notes. Interactive form filling, digital-signature workflows and embedded-media interaction are outside scope; a Pencil signature is ordinary page ink.
4. Initially cover static EPUB content, identifying unavailable audio/video and synchronized read-aloud. Existing website features remain available under their existing roles.
5. Permit clearly labelled partial reading, identifying unavailable content/features without claiming missing content is available offline.

The [second live round](https://github.com/mooneeb/bookorbit/issues/23#issuecomment-6398122462) adds:

6. Require books that are entirely reflowable or entirely fixed-layout initially. Mixed-layout EPUBs receive explicit partial/unsupported handling.
7. Fixed-page controls include page navigation, zoom, single pages and optional paired spreads respecting page order. Font resizing and continuous vertical scrolling apply to reflowable EPUBs; fixed-page continuous scrolling is not required initially.
8. Support bundled fonts and recognized standard font obfuscation. Allow a clearly warned substitute only when text remains readable and layout usable; missing letters and broken layout remain failures.
9. Allow source-bound page bookmarks on image-only EPUB pages, with editable labels and the accepted bookmark sync/removal/conflict/recovery behavior.
10. Show existing embedded PDF annotations and their available comment text read-only, preserving source PDF ownership. Initial import/edit/sync of those annotations as BookOrbit notes is outside scope.
11. Include ordinary static tables, SVG diagrams and MathML equations, preserving actual selectable text and authored accessibility, with representative acceptance fixtures.

The [native stack](native-stack.md), [note model](note-model.md), [sync model](offline-sync.md), [reader controls](reader-controls.md), [storage/recovery](storage-recovery.md) and [book-merge policy](book-merge.md) remain authoritative. Both formats matter equally. No profile weakens source verification, available-text accessibility, protected local work or complete saved context. The selected engines remain Foliate/WKWebView and PDFKit.

## Fixed pages, source identity and page bookmarks

Detect layout from verified publication metadata and spine declarations. An explicit mixed-layout declaration cannot be ignored because a global renderer opens one part. For uniform legacy content, recognize the audited Apple/Kobo fixed-layout flags without claiming all vendor behavior. Conflicting, incomplete or unrecognized hints need an explained outcome; do not guess from a cover or turn an unreadable fixed book into reflowed prose. The source facts document the current precedence and limited recognized options, which need regression fixtures.

Reflowable controls keep their accepted defaults. Fixed pages use page navigation/zoom and optional spreads; show inapplicable font/continuous-scroll controls as unavailable with a concise reason. Preserve local reflowable preferences rather than rewriting them when opening a fixed book. Respect the publisher's page sides and reading order when pairing pages; changing orientation/spreads changes the view, not the source location.

Text notes still use exact canonical ranges, untrimmed quoted text and verified resource provenance. The correct document must come from the actual selection, including the second spread page, not the first loaded iframe. Restoring a note must navigate to and decorate that range. Viewport rectangles, zoomed positions and a spread index are not note identity. Preserve canonical parsing/body structure across XHTML, SVG and mathematical/table content.

Extend the existing source-bound bookmark/location model with an explicit EPUB resource/page kind where selectable text is unavailable. Bind it to the verified full source, spine occurrence and normalized resource identity, with an engine locator as a navigation aid. A transient spread pairing, screen page count or reading percentage is insufficient. A visible image description is not a substituted text quote. Keep text-point and resource/page locations explicit; do not silently translate one into the other. Canonically equal resource targets converge under the accepted one-active-location rule.

The current resource/page and active-side relocation paths need implementation fixes. Reopen must reach the requested side/resource in native and browser readers, including RTL spreads and the already-visible opposite page. An unreadable target returns failure instead of silently skipping to another section. Automatic resume can retain the same verified resource kind without changing competing-position policy or moving an open page.

Page bookmarks retain the existing bookmark owner, editable labels, offline durable operations, revision checks, conflict review, Undo without Trash, removal barriers and local Recovered changes. Include the new locator kind in capability negotiation, shared/native transport fixtures, migrations, legacy guards, browser controls, server recovery and the existing unencrypted app recovery file. Old clients/importers cannot claim complete support while dropping or misreading it. A bookmark alone adds no whole-page/excerpt capture obligation and never authorizes complete-book access after removal.

## Fonts, static structures and accessible content

Use verified local font resources, including recognized obfuscation decoding, before deciding a font is unavailable. Preserve original archive/member bytes; decoded presentation resources do not redefine source identity. Unknown font algorithms must produce an explicit diagnostic, rather than only a console warning. Protection outside accepted scope is not unlocked through the font path.

A substitute is acceptable only when clearly disclosed and both words and layout remain usable. In fixed pages, check clipping, overlap, text/image placement and meaning; readable glyphs alone do not make a broken designed page acceptable. Missing/replaced glyphs, altered mathematical meaning and failed shaping remain failures. Fallback cannot be used to report a known-good required decoder fixture as passing its decoding check. Publisher styling, device-local typography and the user's selected font remain distinct from a recovery substitution.

Render static tables/SVG/MathML using the selected contained engine, preserving namespaces, canonical body structure and source text. Keep wide tables/diagrams/equations reachable through appropriate view movement without changing exact-note bindings. Expose supplied table headers, SVG names/descriptions and mathematical semantics/alternatives. No automatic description generation, OCR, formula transcription or DOM text injection is added. Represent an image description as an authored description, not source words selected from the picture. If a reliable range cannot be produced, explain that limit and preserve existing notes instead of manufacturing an anchor.

Available book text and authored semantic content must pass required accessibility checks. An image-only page can announce unavailable text; a text-bearing page skipped by VoiceOver or read across columns in a meaning-destroying order is a failed available-text check. Incorrect/missing source semantics and missing authored alternatives are recorded separately from adapter failures. Partial reading can explain a limitation but cannot turn a failed mandatory fixture into daily-use acceptance. If a required case cannot be achieved within the selected adapter, expose a precise blocking design question before claiming the handoff complete.

## Existing PDF content and static interaction

Keep original PDF bytes immutable. PDFKit renders existing annotation appearances according to their visibility flags and appearance streams; expose associated comment text through a read-only, accessible page/annotation interface. A painted icon is insufficient if a required comment remains undiscoverable. Bounded page-local enumeration can support this without importing a whole document's annotations into memory or creating BookOrbit note rows.

Comments supplied by another application remain embedded source content. They do not enter BookOrbit note conflict/Trash rules, become editable PencilKit archives or silently appear as imported personal annotations. New BookOrbit typed/ink notes and page ink remain editable sidecars under their existing owner. Viewing comments or adding sidecar ink must not flatten, rewrite or invalidate the source PDF. Missing/stale appearances or unsupported annotation types need a specific content limitation; do not promise complete attachment/rich-text/thread support.

Existing static form values/signature appearances may be displayed when usable, with interactive features identified as unavailable. No form submission/editing, XFA workflows, document scripting, embedded-media playback, cryptographic signature creation/verification or embedded-annotation import is added. Drawing a signature is page ink and conveys no cryptographic verification. Do not bypass protection or content-access restrictions. An unavailable extraction/accessibility operation has an honest state and cannot be treated as successful available-text support.

Supplied outline/internal links retain normal navigation and return. Controlled external URL opening stays separate from publication resource loading. A cross-document or unavailable destination needs a specific explanation and preserves the origin; opening a different file cannot masquerade as reaching the target. Retained single-page context is a preservation artifact and does not promise the original document's complete cross-page navigation.

## Partial reading, refusal and offline availability

| State                      | Observable contract                                                                                                                                                                                                                                                   |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Complete supported reading | Required static content/functions are usable within the declared profile. A fully verified offline package may show unqualified Ready offline.                                                                                                                        |
| Partial reading            | Identify unavailable content/feature and affected resource/page where known; preserve access to usable content and existing note lists/context. Static content may be kept locally with an explicit partial-offline label. Never claim omitted material is available. |
| Content unavailable        | Explain an unreadable target/resource, unsupported layout/protection, unavailable glyphs/text or essential missing content. Keep a way back; never skip silently or produce a false successful jump.                                                                  |
| Preparation/save failure   | Preserve protected drafts/originals and the prior complete server revision. Offer applicable retry/space/recovery actions under existing policy, without publishing incomplete context or showing Saved/Synced falsely.                                               |

Report rendering, available text, selectable source ranges, accessible reading, navigation, note placement and offline completeness independently. A visual preview does not establish safe text anchors. A font warning or unsupported media notice does not by itself mean every other function is unavailable. Diagnostics must not disclose other users' source paths or private data.

Mixed reflowable/fixed books, vertical writing, unsupported vendor extensions, media-dependent content and interactive document features are outside the initial required profile. Offer partial reading only for content that can actually be isolated and read faithfully; otherwise explain the refusal. Missing resources and broken source content must not masquerade as complete offline availability. Static fallback chains need bounded, cycle-safe resolution to a supported local alternative, or an explicit unavailable state. Retain the actual rendered resource/source mapping; notes on an original target never silently move to different fallback content.

Publication scripts and unsolicited remote resources stay blocked. A partial-reading choice cannot enable them. Missing network-only content remains identified, online as well as offline, unless a separately authorized normal external link is opened. No remote fetching or format conversion is an unasked repair procedure.

Only verified usable selections can create text-linked notes. Saved context must contain the required source words/page/resources faithfully within existing bounds; an affected unavailable part cannot be replaced with blank content. Capture/preview/publication failure retains the local draft/original and prior complete server revision. Existing PDF page ink keeps its page identity even without text. Download removal, book replacement and merge/reimport retain their already-confirmed preservation and approval rules.

## Implementation obligations and evidence

The [source audit and supplemental facts](../research/publication-profile-current-facts.md) identify concrete adapter work: fixed-layout range selection/navigation; correct iframe/spine and active-side relocation; explicit resource/page locators; local font decoding; metadata/layout diagnostics; bounded manifest fallback handling; trusted-host containment; static rich-content/accessibility checks; PDF comment discovery and general geometry. Missing fallback-chain projection is an implementation gap, not evidence that fallback has been exercised. Do not substitute parser recognition or one fixture's rendering for these outcomes.

Keep the owning interfaces from the accepted stack. PublicationStore prepares verified manifests/resources and diagnostics; ReaderSession resolves format-specific text/resource/page targets and accessible rendering; ReadingNotes verifies exact ranges/context; the bookmark owner handles resource/page identity and lifecycle; existing sync/recovery owners transport and preserve the new locator variant. Views do not create alternative identities or bypass durable saves. New contracts need explicit DTO/shared/native schema support and negotiated capabilities, not guessed fields sent to strict legacy routes.

Retain resource limits from storage/recovery: file/member/entry/expanded-byte/image/DOM limits, deadlines, page limits, working-set targets and bounded concurrency. Fonts, SVG, MathML, comments and fallback processing add no unbounded exception. Use representative fixtures and later private-library copies under the agreed twenty-download scale target and conditioned measurements; this decision changes neither the count target nor backup/export scope.

The [standalone profile cases](../acceptance/publication-profiles.md) complement existing reader, control, sync, accessibility, management, signing, recovery and scale matrices. Record source digests, layout/resource declarations, expected words/order/images, app/server/browser/OS versions, actual outcomes and Pass/Fail/Blocked. Required cases remain unrun until implementation. No prior human fixture verdict is copied into these runs.

After final shared-understanding confirmation, resolve only this decision and feed the result into [Agree the complete reading journey and build-readiness criteria](https://github.com/mooneeb/bookorbit/issues/13). Final handoff assembly and that decision's own confirmation remain subsequent work. No production code, new prototype, installation, private-book access or server operation is authorized here.
