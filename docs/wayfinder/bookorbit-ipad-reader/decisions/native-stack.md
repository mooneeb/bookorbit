# Personal iPad app: stack and module interfaces

Specification prepared for shared review in [Choose the native app boundary and reader stack](https://github.com/mooneeb/bookorbit/issues/10). All nine product choices are accepted; the linked issue records final shared-understanding confirmation and resolution status. This document describes the proposed stack and contracts, not a production implementation or acceptance result.

## Accepted product inputs

The [app-scope round](https://github.com/mooneeb/bookorbit/issues/10#issuecomment-6369981693) and [management/accessibility round](https://github.com/mooneeb/bookorbit/issues/10#issuecomment-6370068019) establish:

1. Include all book management alongside browsing/search, downloads, reading, notes and sync status.
2. Initially open ordinary, unprotected EPUB and PDF files. Neither password-protected PDF nor EPUB DRM support is required.
3. Book management includes imports, metadata editing, organization, bulk actions and removal. Server configuration, user/permission administration and Kobo setup stay in the website.
4. Book-management changes require a connection; downloaded reading and reading-note editing keep their accepted offline behavior.
5. Native controls own the library, reader controls, notes, downloads and sync status. Advanced online management reuses existing BookOrbit pages inside the app.
6. VoiceOver reading/navigation of book text and notes, plus larger interface text, is required for the first usable version. Handwriting is identified by its selected words and optional typed description; automatic transcription remains outside scope.

The [next product round](https://github.com/mooneeb/bookorbit/issues/10#issuecomment-6370708393) adds:

7. Keep management available for all server-supported formats. Clearly identify that the native reader initially opens only unprotected EPUB/PDF.
8. Existing personal book notes and journals remain available through online management pages. Native offline editing covers the agreed reading annotations, without adding those whole-book note owners to the offline protocol.

The [last accessibility choice](https://github.com/mooneeb/bookorbit/issues/10#issuecomment-6371017678) is:

9. Image-only book pages announce that text is unavailable and remain visually readable. Book-page OCR is not part of the first version; available book text, controls and reading notes retain the required VoiceOver support.

The confirmed [reading-note model](note-model.md) and [offline-sync specification](offline-sync.md) remain authoritative: PDF page ink, EPUB exact-word mixed notes, stable identity, fully verified source bindings, retained context, per-part conflicts, safe retries, explicit deletion recovery and source-specific resume choices. This decision selects implementations for those contracts rather than changing them.

## Evidence and limits carried forward

- [Reader/library and official-source facts](../research/reader-stack-current-facts.md) distinguish BookOrbit's public server/web code from the official native app, whose source/license could not be substantiated in the bounded public-source check. An independent owned app is the viable planning baseline; no official native implementation is assumed reusable.
- [Native platform facts](../research/native-platform-stack-facts.md) establish supported mechanisms and alternatives. They do not pass production gesture, accessibility, geometry or network checks.
- The [completed browser proof](../prototypes/browser-compatibility/README.md) covers retained EPUB/PDF fixtures and matching editable native originals. Its native PDF used a fixed canvas, rasterized page and extracted PDF context; the browser inverse transform was fixture-specific. It did not establish a production PDFView overlay or arbitrary-page geometry.
- [Native selection code](https://github.com/mooneeb/bookorbit/blob/ebf17719a2207eb9dd0abad32830b12d9c63992b/docs/wayfinder/bookorbit-ipad-reader/prototypes/context-preservation/Fixtures/Reflow/reader.js#L122) carries CFI, exact quote/context and source hash, but the scratch controller does not enforce the accepted one-note-per-range identity. The prototype's individual atomic JSON/drawing files and unsent marker are not a transactional store or network queue.
- [Manual SideStore renewal and update](https://github.com/mooneeb/bookorbit/issues/20#issuecomment-6299949060) already preserved fixture identity and editable originals. Production packaging still needs its own acceptance under the same signing policy; the completed fixture gate is not reopened.

## Proposed stack

These are the recommended technical choices for the complete shared review. They are not established by the product answers alone.

| Area               | Proposed choice                                                                                                                               | Reason and consequence                                                                                                                                                                                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| App UI             | Swift 6, SwiftUI navigation/screens, UIKit-owned reader and drawing controllers through representable wrappers                                | Native controls and text input with explicit responder, canvas and gesture ownership. SwiftUI reconstruction never creates note identity or implicitly saves it.                                       |
| Runtime            | iPad-only, minimum iPadOS 26.0, acceptance on the current 26.6.1 device; available Xcode 27/Swift 6.4 toolchain                               | Keep the confirmed device baseline. Compile-time availability checks exclude 27-only runtime behavior. No OS update is required by this proposal.                                                      |
| EPUB               | The existing modified Foliate snapshot inside a contained WKWebView                                                                           | Retain the current CFI/body-structure machinery and prior native/browser work. Native controls and mixed-note editing surround web-rendered publication text.                                          |
| PDF                | PDFKit with an owned page workspace and PencilKit overlays                                                                                    | Native PDF text/selection and drawing integration, with app-owned page/ink extent and transform handling. A page-sized overlay alone does not satisfy margin-ink reachability.                         |
| Ink                | PKCanvasView, system PKToolPicker and native PKDrawing archives; maximum PencilKit content version 4 on both canvas and picker                | Includes the supported 26-era inks/roll data and avoids silently writing 27-only archives. Unknown/incompatible originals remain preserved and visibly unavailable for editing.                        |
| Typed note editing | Standard UIKit text input, native Scribble, Unicode text body                                                                                 | Text and ink remain independent parts of one note. Existing text is preserved without HTML rewriting or treating Scribble as an ink format.                                                            |
| Local metadata     | GRDB 7.11.1 over system SQLite, one serialized DatabaseQueue per active account/server store                                                  | Explicit constraints, migrations and transactions for note parts, pending operations, receipts and checkpoints. Use rollback journal DELETE and synchronous FULL initially, with foreign keys enabled. |
| Local assets       | Immutable files in Application Support, separated from disposable resource caches                                                             | Editable originals, previews, context and pending upload bodies survive download eviction and normal updates. File placement and database references follow the confirmed save/recovery ordering.      |
| Credentials        | Keychain, scoped by verified server/account                                                                                                   | Use after-first-unlock, device-only credentials and compatible file protection for conditional background access. Losing credentials causes reauthentication, preserving local work.                   |
| Transport          | URLSession with explicit application chunk/offset/receipt handling; bounded background attempts through normal lifecycle time/BGTaskScheduler | Foreground sync is the correctness path. Background expiration preserves the queue. Apple's separate resumable-upload protocol is not assumed compatible with the BookOrbit staging contract.          |
| Online management  | Existing Vue management feature views inside a separate remote WKWebView                                                                      | Full book-management coverage while keeping core reading UI native. A mobile management mode constrains navigation and reports changed books/jobs to the native host.                                  |

GRDB's default WAL pool uses NORMAL synchronization and the device SQLite patch identity is unverified. The proposed single-connection rollback-journal configuration avoids relying on that pool behavior. It still needs measured migrations, file/DB crash recovery, lock-state behavior and power/durability checks. SwiftData and Core Data can also support explicit saves/transactions; the preference for GRDB comes from direct ownership of this protocol's rows and constraints, not a claim that those frameworks lack transactions or are inherently unsafe. [Persistence evidence](../research/native-platform-stack-facts.md#local-persistence-grdbsqlite-and-apple-alternatives).

Readium Swift 3.11.1 is a viable alternative with Swift publication/navigation APIs and accessibility hooks. It also renders EPUB through WebKit. Its default selection/locator resolver does not establish the accepted exact occurrence identity or BookOrbit CFI interoperability. Adopting it would require a separately validated selection adapter and behavior comparison. Keeping the current Foliate fork reduces that change surface; finished VoiceOver support remains a release gate for the selected adapter. The existing browser PDF engine remains patched EmbedPDF/PDFium 2.15.1; moving its WASM/worker stack into the native app would add an integration without replacing PencilKit or the durable store. [Reader comparison](../research/reader-stack-current-facts.md).

## Module interfaces and ownership

The following are conceptual Swift interfaces, not existing routes or generated code. Their value/result types carry explicit account/server scope and source/schema versions. Views render observable state and issue intents; they never write a web cache, drawing widget or database table as a substitute for these interfaces.

| Module            | Small caller interface                                                                 | Owned behavior and failure contract                                                                                                                                                                                                        |
| ----------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ConnectionSession | Connect/reauthenticate, obtain scoped transport/management session, sign out           | Verify server/account/recovery generation/capabilities; serialize token refresh; isolate Keychain and website-store identities. Sign-out freezes the old queue.                                                                            |
| Catalog           | Query a page, load book detail, open a management destination                          | User-scoped online browsing/search plus downloaded-book metadata offline; permissions and supported reader formats; bounded page results, changed-book invalidation and management navigation.                                             |
| PublicationStore  | Prepare a download, open a verified publication, remove a download                     | Original-byte/hash verification, complete offline package manifest, resumable file transfer, resource availability and source provenance. Download removal never removes note assets.                                                      |
| ReaderSession     | Open/resume, select/navigate a canonical location, present annotations/capture context | EPUB and PDF adapters own renderer locators/geometry, layout generations, active-page loading, reading-position events and self-contained original context. Unresolvable locations return explicit states, preserving list/context access. |
| ReadingNotes      | Open a selection/page note, commit changed parts, review/Trash/restore/recover         | Exact-range/page uniqueness, mixed drafts, lifecycle/revision checks, save states and one logical note shared by reader/lists. Existing journals and personal book notes keep their existing owners.                                       |
| InkWorkspace      | Bind a note revision, control writing/tools/undo, snapshot an ink revision             | Focused PKCanvasView, native tool preferences, version limits, final drawing-change capture, archive/preview geometry and bounded rendering. A snapshot identifies its immutable drawing revision.                                         |
| LocalStore        | Read bounded views, commit a local revision/operation, apply a received result/page    | GRDB migrations, constraints, sequences/dependencies, receipts/checkpoints and asset references in transactions. Native UI/engine identifiers cannot bypass the store.                                                                     |
| SyncCoordinator   | Reconcile, observe status, request Sync now                                            | The confirmed foreground/conflict/lifecycle protocol, asset ordering, retry scheduling, visibility-aware browser counterpart and recovery after expired history/credentials. It consumes durable state rather than an in-memory task list. |

EPUB and PDF are real adapters at the ReaderSession seam, with format-specific selection/geometry records. Do not force callers to understand both engines through a large generic drawing interface. Keep archive/image creation inside InkWorkspace and file persistence inside LocalStore/PublicationStore; the sync module transports verified manifests rather than manipulating UIKit views.

Use explicit Codable transport records checked against the server DTOs, shared TypeScript contracts and common JSON fixtures. Preserve the existing server/client shared-type owner. Do not send new fields to legacy strict DTOs or assume the current annotation/progress responses already acknowledge operations. New reader-sync, offline-package and management-session capabilities require declared server contracts and consumer checks.

## EPUB delivery, selection and containment

Use the vendored EPUB member-loader interface, which accepts loadText/loadBlob/getSize and creates lazy section resources. The initial native delivery design is an in-process, loopback-only HTTP resource adapter serving the active downloaded publication and frozen trusted reader assets. This retains the tested HTTP/module behavior; WKURLSchemeHandler is not silently substituted for a proven loader. The scratch server's whole-file Data reads and the prototype's whole-EPUB arrayBuffer/File construction must be replaced with bounded member requests. The vendored ZIP bundle has no exported HTTP Range reader. [Member-loader interface](https://github.com/mooneeb/bookorbit/blob/ebf17719a2207eb9dd0abad32830b12d9c63992b/client/public/assets/foliate/epub.js#L1084), [production member loader](https://github.com/mooneeb/bookorbit/blob/ebf17719a2207eb9dd0abad32830b12d9c63992b/client/public/assets/foliate/streaming-loader.js#L77).

Prepare an immutable offline package on the server from the verified original EPUB: original ZIP bytes plus an indexed manifest of unmodified archive members and their hashes/sizes. The app streams/verifies the original and stores the raw members needed for the complete publication. Every manifest names that same source digest/revision; package extraction never substitutes a converted edition. Existing resource endpoints are the starting seam, but their current online book-ID lookup is not this immutable snapshot contract. Publish a package only after its manifest is complete and resource hashes match. This new contract and its download state are proposed implementation work, not an existing capability.

The local member provider streams indexed files, validates normalized manifest keys and enforces request, archive-expansion, member and aggregate bounds. Bind only to loopback, use an unpredictable per-session path token, allow required read methods and release the lease when the reader closes. Never accept arbitrary filesystem paths or expose the management/native HTTP credentials. Complete local publication availability must be checked before announcing Ready offline. Resource/byte/working-set limits are set in the storage decision using representative books, including giant chapters; lazy sections alone are not a memory bound.

Use the same body parsing and canonical-range serializer in native and browser adapters. Selection records include source revision/full digest, spine/resource location, canonical start/end boundaries, CFI, exact untrimmed quote and bounded context. Verify the resolved quote before decorating. Keep UTF-16 boundary conventions explicit, test repeated/overlapping text and preserve the existing body-tree parsing fixes. Cross-resource selections outside the adapter's representable range are explicitly rejected rather than silently shortened or split into independent notes. Reflow changes display geometry and never moves the independent handwriting canvas.

Give EPUB its own nonpersistent website store and content controller. The trusted host owns a narrow, bounded message interface with active source/session/layout tokens. Validate the sending web view, content world, exact origin and permitted frame; do not trust a payload-supplied origin. The native store revalidates the selection before any note action. Web-process termination reloads the verified package and restores a durable logical position/draft, discarding stale geometry callbacks.

Publication code is untrusted. The current Foliate sandbox allows scripts, its script-load hook defaults to allow, and external resource URLs can pass through unchanged; these are known host requirements to change. Block publication scripting and unsolicited remote loads while allowing the trusted reader host to operate. Enforce policy on generated child documents/resources without changing canonical body structure; verify CSP/blob/srcdoc and WebKit selection behavior together. Static content and reader-owned navigation remain supported; script-dependent or network-only behavior must have an explicit unsupported/partial-content state. Missing resources must not masquerade as complete offline availability or a successful saved-context capture.

## PDF workspace and native input

PDFKit owns PDF parsing, text/selection and rendering. The app owns the surrounding page workspace, active-page lifetime and ink bounds. Use per-page PencilKit views with a stable page-ink identity; keep only the active and bounded neighboring views alive. Save on finalized drawing changes, not only when an overlay leaves display. When reopening an archived page, the context copy's page index is separate from the original source-page index.

Persist MediaBox, CropBox, intrinsic rotation, zero-based original page index, units, canvas/drawing bounds and an explicit invertible canvas-to-unscaled-PDF transform. PDFKit default page space is lower-left; existing browser records use top-left unscaled points. Each adapter calculates and validates that conversion from the actual page geometry. Compose viewer zoom/rotation separately and exactly once. Check transformed corners/known points and reject invalid/non-finite/singular geometry. Never reuse the fixture matrix as the arbitrary-page algorithm.

The scrollable/hit-test workspace is the union of the page and retained ink extent, including negative/outside-crop margins. A page-sized PDFPageOverlayViewProvider view alone is insufficient. The native adapter must own the extra extent and render the page plus drawing under one verified mapping; it cannot rely on undocumented changes to PDFView's internal scroll views. Standard PDF rendering/selection, margin visibility, page navigation and VoiceOver must pass together. This extra workspace is specified app work, not a capability already demonstrated by the PDFKit prototype.

Writing ON makes Pencil input draw while fingers navigate; writing OFF routes both inputs to navigation and keeps ink visible. Use Pencil-only drawing explicitly, one focused canvas/tool picker and stable undo ownership. Keep eraser, undo/redo and standard tool affordances available with accessible controls. Do not clear undo merely because the same note's view was reconstructed; persistent undo history across relaunch is not promised, while retained strokes must remain editable.

Use native PencilKit behavior for supported pressure/tilt, barrel roll, hover/tool previews and feedback, respecting the system's squeeze/double-tap/hover/accessibility preferences. Start with the system picker rather than replacing squeeze with an app mapping; installing a custom squeeze delegate can suppress Apple's undo slider. If integration requires a handler, dispatch only the system-selected action and verify that native behavior is preserved. Archive the final drawing-change callback, including later force updates, rather than treating tool-up as the last stroke data. Scribble stays with the standard typed editor; it never converts the stored drawing into typed text.

## Ink, previews and saved-context formats

Use schema-versioned manifests with explicit discriminators, encoding and provenance. Keep archive compatibility, app schema and sync protocol versions separate.

| Record/asset               | Required fields/meaning                                                                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source descriptor          | Server/account/book association, source file UUID/revision, full original SHA-256, format/size; delivered variant/digest and verified mapping when applicable.              |
| Selection or PDF placement | Canonical range/CFI/quote/context, or source-page geometry and canvas-to-page transform. Include serializer/geometry schema version.                                        |
| Editable drawing           | Raw PKDrawing data, encoding identifier, required content version, app/OS provenance, byte length and SHA-256. Keep the native bytes authoritative.                         |
| Ink display manifest       | Exact drawing hash/revision, canvas and preview bounds, transparency, logical-to-pixel scale, pixel size, PNG digest/length and rendering profile.                          |
| Saved context              | Self-contained PDF excerpt/page, exact quoted text and bounded readable context, source/selection/page provenance, context digest and mapping back to original coordinates. |

Generate transparent, lossless PNG on a supported iPad runtime. Start from the tested 2x rendering profile, while making scale and crop explicit; that fixture result is not an unlimited zoom guarantee. The archive remains editable independently of raster resolution. The storage decision selects production pixel/byte/quality limits and higher-resolution or oversized handling from the retained evidence. Render bounded work, preserve the full ink extent and refuse incomplete publication if the required preview cannot be produced. Do not use a Linux server to decode PencilKit or use an approximate SVG reconstruction as the original.

For EPUB, capture a bounded original excerpt as a self-contained PDF with quote/context text and capture-layout provenance. It accompanies the separate note canvas. For PDF, retain an extracted original page with its original boxes/rotation and an explicit original-page/context-page mapping. Keep source PDF bytes immutable; the editable drawing remains a sidecar. App exports that embed ink into a PDF are a later export-policy choice, not the canonical note owner.

Hash and place complete immutable local files before the transaction that references them, changes note parts and records pending operations. Keep original/preview/context revision matching. A failed preview or context capture preserves the draft/original locally, leaves the prior valid server revision intact and reports the incomplete state. Save badges follow the confirmed sync contract. Garbage collection respects every active/recoverable/pending reference.

## Online management and account sessions

Reuse existing management feature views with a mobile in-app navigation mode. Native browsing can open a book-scoped management destination; ordinary book actions remain available even when their current permission or route name mentions Settings. Server/provider/library configuration, user/permission administration and Kobo setup open the website separately. The backend remains the authorization authority; allowed UI routes and menu visibility are not permission checks.

Configuration of those systems remains web administration.              |
| [Existing whole-book notes](https://github.com/mooneeb/bookorbit/blob/ebf17719a2207eb9dd0abad32830b12d9c63992b/server/src/modules/book-journal/book-journal.service.ts#L23)       | Personal book note, journal and available aggregate views retain their owners and online behavior; they do not become copies of native reading annotations.                                 |

Current bulk selection/locks/results can be unbounded, some streams cancel on disconnect, and browser multipart uploads do not use the existing resumable-session API. Reuse does not certify these paths for tens of thousands of books. Enforce bounded server work and record job/status or uncertain-outcome handling before treating a long action as complete. An interrupted destructive request is checked against current state rather than automatically replayed. Existing metadata writes, book deletion and collision merges must participate in source-version and retained-note safety; the legacy cascade behavior is not acceptable for new annotations.

Create a persistent WKWebsiteDataStore identifier for each verified management account/server scope. Keep its cookies/storage separate from EPUB and other accounts. Use the existing web cookie session transport; never place a native refresh token into a web cookie or expose Keychain credentials through the bridge. A proposed one-time native-to-web session handoff creates a real web session and verifies its user before loading the management mode. This capability is missing in the current server. Consume the handoff once over the configured HTTPS origin, with short expiry/scope binding and no secrets in URLs; otherwise require explicit web sign-in rather than guessing cookie transport. [Authentication/store facts](../research/native-packaging-containment-facts.md).

The management bridge permits bounded navigation/change/job messages, not arbitrary native requests or filesystem access. Validate exact origin tuple, world, main-frame policy, current scope and schema, including redirects/new windows. Authentication-provider navigation uses a controlled external/system login flow; unrelated destinations open externally. Returning to native browsing refreshes affected bounded views and source descriptors. Account changes cancel/freeze work and close the old management view before changing scope.

## Persistence, lifecycle and diagnosis

Keep one account/server store actor and one GRDB writer connection. Schema migrations are explicit and resumable/recoverable; a failed migration opens recovery state rather than replacing the database. Record SQLite runtime/source identity and verify requested journal/synchronization settings. Do not maintain a second source of pending work in UIKit or JavaScript. Use bounded asynchronous reads/writes away from UI work and keep network requests outside transactions.

Use Application Support for the database, immutable note assets and transfer files; use regenerable caches for reader resource views. Source downloads and note assets have separate retention rules. Apply compatible after-first-unlock file protection, with device-only Keychain credentials. Preserve note IDs, pending sequence/UUID/digests and assets across in-place updates. A replacement installation reauthenticates and reconciles; it never treats an empty credential store as permission to wipe retained notes.

Foreground URLSession requests implement negotiated stage/chunk/status/publication contracts and enforce the configured scope/redirect policy. Reconcile after saves, reopening, connectivity recovery and Sync now. Background lifecycle time and BGTaskScheduler may attempt the same queue with explicit expiration cancellation; no fixed completion deadline or force-quit relaunch is promised. Automatic URLSession background transfers are not required for the first implementation; adding them later must preserve origin policy, file-backed bodies, task reconciliation and the same publication/receipt rules.

Expose native status for local saves, pending transfers, accepted sync, conflicts, sign-in/upgrade requirements and recovered changes. Offer Retry/Sync now, conflict review and a diagnostic export limited to app/OS/schema/engine/SQLite versions, capability status, sanitized errors, counters and timings. Exclude credentials, book/note contents, full paths and arbitrary request/response bodies. A changed server capability pauses affected work and gives an upgrade instruction without disabling local reading/editing.

## Build, dependencies and updates

Create an owned iPad target in the monorepo with checked-in Xcode project and SwiftPM resolution, keeping prototype code/evidence separate. Proposed production bundle ID: dev.mooneeb.bookorbit.reader. Do not overwrite the contextprototype identity or migrate scratch fixture notes into real library annotations automatically. Use one app target without extensions, push or iCloud dependencies. Native access to the self-hosted HTTPS server uses the current confirmed address and capability handshake.

Pin GRDB to 7.11.1 and freeze the actual Foliate vendor tree/files by hash; do not call it a numbered release or automatically replace it with upstream main. Use the existing patched browser EmbedPDF/PDFium 2.15.1 artifacts while keeping their original notices. Apple frameworks follow the supported runtime. Include source/dependency/license manifests and the applicable BookOrbit AGPL/additional terms, Foliate MIT, zip.js BSD/codec and fflate MIT notices for actually bundled material. The asset audit identified missing current vendor notices; restoring them and recording per-file provenance is required packaging work, not a claim that this planning branch has already bundled compliant binaries.

Free signing retains the accepted weekly renewal bound. SideStore plus the retained prototype plus this separate reader would use all three ordinary free app slots; actual available IDs/slots are checked at installation. Preserve this reader's AppID with Append Team ID unchecked during manual IPA updates. Xcode remains the build/bootstrap/recovery route. The validated prototype renewal is evidence for that route, while production identity/data/credential continuity still needs a controlled first update check. App Groups are not categorically paid-only, but are unnecessary for this single-target design. [Packaging/capability facts](../research/native-packaging-containment-facts.md).

Reviewed dependency/server updates must retain old archive bytes, schema provenance and queued operations, negotiate compatibility before uploading, and run the affected fixtures. Do not silently downgrade an unsupported drawing or regenerate its preview as though it were a new editable original. Failed updates need recovery of local work before any reinstall that would erase its container.

## Remaining acceptance and adjacent decisions

This proposal settles implementations and interfaces only after the user's complete shared review. It does not report the production system as passing. Carry these integration cases into [Agree the complete reading journey and build-readiness criteria](https://github.com/mooneeb/bookorbit/issues/13):

- EPUB package completeness/cancellation/resource bounds, script isolation, canonical selection round trips, font/reflow/resize, repeated/Unicode ranges, WebKit termination and accessible book/notes focus.
- General PDF crop/media origins, intrinsic/viewer rotations, mixed sizes, zoom, page recreation and reachable outside-page ink, with native text selection, finger/Pencil routing and VoiceOver.
- Production Pencil settings/tools, Scribble, final-force persistence, undo/redo after view changes, content-version refusal and ordinary app-update continuity.
- GRDB/file durability and migration faults, lock state, lost responses, staged assets, all accepted conflict/deletion/recovery cases and browser arrival while protecting unsaved drafts.
- Per-account management sessions, handoff expiry/replay, route/new-window isolation, iPad file upload, long/partial jobs, source-changing actions and offline-disabled catalog changes.
- Actual daily build/update/free signing capability checks, fresh restore of server-backed editable originals and honest diagnostics.

Storage/download eviction, archive/pixel/byte/working-set budgets, backups, portable exports and meaningful performance limits remain with [Set library scale, storage, backup, and export requirements](https://github.com/mooneeb/bookorbit/issues/12). Online management's newly exposed identity/history question is tracked in [Choose how book merges preserve notes and personal book state](https://github.com/mooneeb/bookorbit/issues/21), which blocks complete-journey readiness. It is not resolved by selecting the native stack. Image-only pages need an honest unavailable-text state; available text, reading-note identity/context, controls, focus order and larger interface text must pass the required accessibility checks. No book-page or handwriting OCR is added here.
