# Native audio bookmarks

The production audiobook reader now opens an audio bookmark sheet. Create a bookmark at the real player position, edit its title and optional note, remove it, or jump to its position across tracks. Global positions require known durations for every track. Unknown durations show an explanation and prevent inventing a position. Jumping first confirms the old playback position and then uses the real engine seek on the destination track.

The owning audiobook API adds authenticated `GET /api/v1/audiobooks/:bookId/bookmarks/page?limit=40&afterId=<bookmark UUID>`. The query DTO accepts integer limits from 1 through 100 and an optional UUID cursor. Responses use the canonical shared `AudiobookBookmarksPage` contract with `items` and `nextCursor`. The owning repository selects only bookmark fields, filters user, book, active audio rows, orders by position and row ID, and reads at most limit plus one. Foreign, deleted, or unavailable cursors return a useful error without revealing bookmark data. The existing user/book/position partial index supports the bounded query. The existing unpaged endpoint remains compatible with the web reader.

The native sheet loads 40 rows into a bounded page and retains at most 32 previous cursors. It validates the bounded response before replacing the visible page. Retry after an uncertain create or edit retains the original body and bookmark UUID, freezes the fields, and checks the exact acknowledged identity, position, chapter, title and note. Explicit note clearing encodes JSON null through generated `FieldUpdate`. Unknown removal outcomes retain the same UUID for retry. Explicit discard or close warns that the server may already have saved the change. A failed page read never becomes a confirmed empty collection. Requests remain pinned to the opening authenticated session.

String limits count Unicode scalars to match the DTO string validator. The form, row actions and reader footer use scalable text, minimum 44-point action heights and stacked fallback layouts. Those source choices require actual keyboard, Dynamic Type, accessibility and layout verification; they do not establish a passing native audit.
