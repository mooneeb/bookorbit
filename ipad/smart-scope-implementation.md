# Native smart scopes and library queries

The native library now opens authorized book scopes, pages their results, and supports search, nested All/Any filters and up to five sort fields. Scope creation and editing use the existing owning server routes. Sharing is explicit; each viewer's accessible libraries and content restrictions remain enforced by the existing scope query service. Delete requires confirmation, and shared non-owner controls omit editing and deletion except for authorized superusers. Kobo opt-in uses the requesting user's existing subscription route.

The new authenticated `GET /api/v1/smart-scopes/page` validates page, size, search, media type and ownership filters. It returns a bounded page plus total without evaluating every saved filter or fetching every scope. Subscription state is resolved once for the page. The existing unpaged endpoint remains available to existing clients. Native listing requests forty book scopes at a time; book results retain forty entries. Search and async result guards keep paging scoped to the current query.

Filter trees, scalar/list values, field/operator vocabularies, reading statuses, file formats, rating providers, sort fields and request/response models are generated from `packages/types`. The book-only scope projection decodes its canonical book filter tree. The recursive editor preserves existing nested groups and provider values, validates bounded groups/conditions and list values, and offers explicit Apply/Cancel. Random sort holds one seed across pages. A paged native scope picker also adds named scopes to dashboard shelves.

Production strict Swift 6 simulator build passed in `/tmp/bookorbit-smart-scope-build.log`; the existing OIDC presentation-anchor deprecation and absent-AppIntents metadata warnings remain. The shared-types build, configured production server typecheck (`tsconfig.build.json`, `/tmp/bookorbit-smart-scope-server-production-typecheck.log`), full server ESLint, generated-contract freshness, handwritten strict Swift lint, Swift parsing and source formatting also passed. The first test-inclusive server typecheck failed with errors in existing test files, retained in `/tmp/bookorbit-smart-scope-server-typecheck.log`; it is not counted as a passing check. It reported no errors in the changed scope production files.

There is no runtime acceptance claim yet. Independent tests must exercise the real authenticated API, native screens, actual web state and delivered files, including ownership/sharing, query bounds, faults/retry, acknowledged writes, relaunch and full accessibility audits. Custom-field pickers, local saved views and the broader issue's reading integrations remain separate unfinished work.
