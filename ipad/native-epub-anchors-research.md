## Established boundary

The implementer's retained native TextKit 2 diagnostic passed exact UTF-16, actual-pixel Vision checks and unfiltered portrait/landscape audits on cached iOS 26.0. It supports only bounded plain paragraphs and does not prove anchors, rich XHTML, pagination or physical behavior. Its parser discards IDs/tree structure and inserts `\n\n`; extending those flattened offsets directly into CFIs would be incorrect. The original WebKit audits remain failed. [Evidence](verification.md#native-delivered-chapter-accessibility-diagnostic), [parser](ReaderProof/Sources/NativeChapterDocument.swift), [WebKit diagnosis](epub-accessibility-research.md).

## Preserve source coordinates, then project native text

Use two representations, with one explicit mapping between them:

- An immutable, bounded XML source tree containing namespaces, element IDs, ordered children and original expanded character data, including non-displayed nodes. Coalesce parser callback fragments into CFI character-data chunks; comments do not create chunk boundaries, and adjacent text/CDATA share a chunk. Retain source whitespace and UTF-16 offsets without Unicode normalization.
- Native attributed runs with display `NSRange`, original source chunk/range, element ancestry and a kind: copied text, transformed whitespace, generated separator/marker or attachment. Preserve source endpoints when several offsets collapse visually; specify endpoint affinity when converting a new selection back. Generated characters need an explicit neighboring source boundary, never an invented text offset.

This is a proposed adapter, following the actual [Foliate chunk/index algorithm](../client/public/assets/foliate/epubcfi.js:196) and [range producer/resolver](../client/public/assets/foliate/epubcfi.js:298). Implement bounded parsing of the existing CFI grammar, escaped assertions, package indirection and source endpoints; reject unsupported syntax explicitly during the diagnostic. A CFI range is two relative endpoints, not a flattened chapter substring. Side bias belongs to point locations, not range endpoints. [CFI specification](https://w3c.github.io/epub-specs/epub33/epubcfi/index.html#sec-path-res).

Fetch the actual OPF through `GET /api/v1/epub/B/file/{containerPath}?fileId=F`. `EpubSpineItem.idref` identifies a manifest item; it does **not** provide the OPF `itemref`'s own ID assertion or package path. Preserve all spine items, including nonlinear items, before resolving a CFI. Foliate derives its package paths from actual itemrefs; do not substitute its explicitly fake `/6/2` index helper. Existing contracts suffice. [Shared info](../packages/types/src/epub.ts:11), [resource route](../server/src/modules/reader/epub/epub.controller.ts:55), [package mapping](../client/public/assets/foliate/epub.js:698), [fake helper](../client/public/assets/foliate/epubcfi.js:350).

Keep the real selectable TextKit 2 `UITextView`. Project emphasis/fonts, real link attributes, language runs and actual image attachments from source ancestry. UIKit provides heading-level text attributes and attachment-view APIs; their VoiceOver behavior must be observed. Do not assume font size alone preserves heading semantics. Read iOS 26 `selectedRanges`; its deprecated singular range is a union that can include unselected bidirectional text. A discontiguous selection needs an explicit supported persistence policy. [Installed heading/language attributes](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/UIAccessibilityConstants.h:311), [selection contract](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/UITextView.h:231), [attachments](https://developer.apple.com/documentation/uikit/nstextattachmentviewprovider).

## Reuse recorded SMIL targets

The public overlay playlist already supplies normalized `textHref`, `textFragment`, full-spine `sectionIndex`, audio resource and clip times. Resolve an ID fragment against the source tree, map its descendants to native text, and highlight that actual range during AVPlayer playback. An element target requires explicit subtree endpoints to create a selection CFI. Keep section zero valid. Other fragment schemes need deliberate resolution or truthful unsupported feedback. [Playlist](../packages/types/src/epub.ts:41), [server normalization](../server/src/modules/reader/epub/epub-media-overlay.ts:228), [fragment rules](https://www.w3.org/TR/epub-33/#sec-media-overlays).

Playback must honor clip begin/end; missing end means the actual media duration, and excessive end is clamped to it. Do not derive passage anchors from audio percentages. Persist the existing narration source/position/fragment/section tuple independently of text and TTS. The server currently omits SMIL pars without audio, so its playlist alone cannot prove complete text-only-overlay behavior. [Timing requirements](https://www.w3.org/TR/epub-rs-33/#sec-media-overlays), [progress DTO](../server/src/modules/book/dto/save-progress.dto.ts), [existing ownership research](reader-feasibility-research.md#separate-tts-resume-and-ebookaudiobook-bridging).

## Bound real pagination

First prove anchors in the existing scrolling view. Then measure current/adjacent pages from ensured TextKit 2 layout fragments and line geometry, mapping actual visible endpoints back to source CFIs. `viewportRange` includes overdraw, so it alone does not identify a visible page. Offscreen estimates and byte locations cannot establish boundaries. Keep paragraph context across continued lines; slicing strings can change shaping. Cache only current/adjacent live controllers by layout generation, viewport, typography and source anchors. [Apple viewport limits](https://developer.apple.com/videos/play/wwdc2021/10061/), [line geometry](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/NSTextLineFragment.h:38).

Apple recommends real text-input views, next/previous text-navigation links and `causesPageTurn` with `accessibilityScroll` for continuous reading. Relevant UIKit APIs exist before iOS 26; the session's SwiftUI linked-group modifier requires iOS 27. Actual VoiceOver reading/selection and completed/canceled native curls remain proof gates. [Apple reading-app guidance](https://developer.apple.com/videos/play/wwdc2026/219/), [installed navigation API](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/UIAccessibility.h:497).

Independently derived range: `epubcfi(/6/2[c1ref]!/4/2[p1],/1:6,/2[em1]/1:5)`. Native selection remains `[6,14)` while its source endpoints now cross chunks. 3. Join existing genuinely playable recorded clips to source IDs; verify actual highlighting, clip transitions, section-zero resume, persisted narration and web reopening while text/TTS positions survive. Parser placeholder audio cannot count as playback proof.

These are successive proofs, not reduced production scope. Open risks include full XHTML/CSS, tables, ruby, vertical writing, SVG/MathML, embedded fonts and fixed layout; hostile XML/ZIP/URI and decoded-asset limits; actual transport-byte caps despite false advertised sizes; large-chapter storage and selection across pages; Pencil, VoiceOver, signing, memory and performance on physical devices. The tiny parser's 64 KiB/128-paragraph limit is a diagnostic bound, not a production library strategy.
