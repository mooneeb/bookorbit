# Ebook renderer feasibility research

Research date: 2026-10-05. This is source-based preparation for IPAD-03 in issue #2, not a passed renderer, narration, accessibility, signing, or hardware proof. No packages, runtime images, or sample books were installed. The applicable decision permits local WebKit content layout with native interaction; the engine remains undecided until the proof passes. [ADR-0004](../docs/adr/0004-allow-local-epub-rendering-in-the-native-reader.md), [IPAD-03](../docs/ipad/tickets.md#ipad-03).

## Smallest local WebKit experiment

Bundle a small reader HTML/module wrapper plus the pinned Foliate files, without the Vue app or upstream demo controls. Create `foliate-view`, register its events before `open`, then navigate to a saved CFI or the text start. Native controls own contents, search, settings, page gestures and playback. Use `WKScriptMessageHandler` for validated result messages and `callAsyncJavaScript` with named arguments for commands, rather than interpolating book text into executable JavaScript. Apple exposes both APIs in the installed Xcode 27 SDK; asynchronous evaluation resolves returned promises. [WKWebView API source](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebView.h), [message handler](https://developer.apple.com/documentation/webkit/wkscriptmessagehandler).

First verify `loadFileURL(_:allowingReadAccessTo:)` using a dedicated per-reader directory containing the wrapper, module assets and selected content. A directory grant permits its contents, so do not grant an entire account store. Local file loading does not itself prove that ES-module imports, `fetch`, blob iframes, obfuscated fonts or audio work in this configuration. Test those before adopting it. [Apple file-loading API](<https://developer.apple.com/documentation/webkit/wkwebview/loadfileurl(_:allowingreadaccessto:)>).

If file-origin behavior fails, test an app-owned custom scheme with `WKURLSchemeHandler`, serving only registered assets and the current reader's authorized content. WebKit forbids registering schemes it handles internally, so this cannot intercept `https` or `file`. Stop callbacks immediately after cancellation. Supply proper MIME types, restrict normalized paths to the package root, and test module/CORS behavior rather than assuming a custom scheme grants browser privileges. [Configuration API source](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebViewConfiguration.h), [scheme handler](https://developer.apple.com/documentation/webkit/wkurlschemehandler).

Keep credentials and authenticated delivery in the existing native API boundary. A local `EPUB` loader needs `loadText`, `loadBlob` and `getSize`; the existing server streaming loader demonstrates that seam. Do not call `view.open(url)` for a large local archive without measuring its allocation: the fork's `fetchFile` first materializes the complete response as a Blob/File. A native extraction or disk-backed resource loader is the bounded alternative to prove. Foliate still materializes each requested Blob, so a single large narration resource can be expensive. [view.js:293-335](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/view.js#L293-L335), [streaming-loader.js](../client/public/assets/foliate/streaming-loader.js).

Block publication scripts, external network loads and unauthorized bridge messages. The renderer sets iframe sandbox flags to `allow-same-origin allow-scripts`, and upstream explicitly requires CSP because the iframe sandbox does not provide the assumed protection in WebKit. Prove the policy with hostile scripted content and legitimate local modules. [paginator.js:276](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/paginator.js#L276), [upstream security guidance](https://github.com/johnfactotum/foliate-js/blob/78914aef4466eb960965702401634c2cb348e9b1/README.md#security).

## Location and native-control bridge

| Native operation       | Fork API/event                                     | Contract or trap                                                                                                                                                      |
| ---------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Open and resume        | `await view.open(book)`; `await view.goTo(cfi)`    | Inspect the returned destination and actual visible passage. `goTo` can skip an unreadable section and return a different one.                                        |
| Observe position       | `relocate` event                                   | `detail.cfi` represents the visible DOM Range; serialize its CFI and explicit text context, not the Range object.                                                     |
| Selected passage       | `view.getCFI(sectionIndex, selectionRange)`        | Use the selected iframe's section index; confirm text and normalized passage endpoints in the web reader.                                                             |
| Resolve an anchor      | `view.resolveCFI(cfi)` / `resolveNavigation(cfi)`  | Returns `{index, anchor(doc)}`. Resolve against the corresponding content document.                                                                                   |
| Contents               | `view.book.toc`; `view.goTo(item.href)`            | Foliate nested items use `subitems`; canonical HTTP contents use `children`. Deliberately map the shape.                                                              |
| Search                 | `for await (const result of view.search({query}))` | Results include CFI/excerpt, grouped results, progress and final `"done"`; stream and cap displayed results. The implementation collects matches within each section. |
| Font/settings relayout | `renderer.setStyles(css)` and layout attributes    | Retain a logical CFI, await fonts and observable relocation, then verify the same passage. An initial `load` callback precedes all layout settling.                   |
| Previous/next          | `view.prev()` / `next()`; `goLeft()` / `goRight()` | Directional helpers account for RTL. Do not replace CFI navigation with estimated progress pages.                                                                     |

The API details come from [view.js:582](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/view.js#L582-L606), [view.js:711](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/view.js#L711-L923), [EPUB package resolution](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/epub.js#L698-L723), [web selection bridge](../client/src/features/reader/epub/composables/useFoliateSelection.ts), and [canonical contents type](../packages/types/src/epub.ts).

CFI offsets count UTF-16 units, not Swift `Character` values. Preserve original section text/structure instead of regenerating XHTML through an unrelated parser; DOM changes need deliberate filtering. Test surrogate pairs, combining marks, adjacent text nodes, escaped assertions, image boundaries, chapter boundaries and old web CFIs. Foliate exposes `CFI.collapse(cfi)` and `collapse(cfi, true)` for visible-range endpoints, but its paginator boundary logic explicitly handles extra spaces and zero-width hyphenation rects. Page-start/end CFIs therefore require measured cross-page tests, not a guessed `end + 1` offset. [CFI specification](https://w3c.github.io/epub-specs/epub33/epubcfi/index.html), [epubcfi.js](../client/public/assets/foliate/epubcfi.js), [visible-range algorithm](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/paginator.js#L81-L155).

The fork's `location.current/next/total` values are estimated byte-based locations, not rendered page ordinals. They must not identify pages in a native curl cache. Use layout generation, viewport/settings and actual start/end CFIs for page identity. [progress.js:53](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/progress.js#L53-L91).

## Recorded Read Along and separate TTS

Foliate parses SMIL text/audio pairs, clip offsets and emits `highlight`, `unhighlight` and `error`. Its `mediaOverlay` supports start with a section/filter, pause/resume/stop, previous/next, rate and volume. Starting from a passage should use overlap with each narrated element, rather than assuming the nearest DOM ID is a SMIL ID. The existing web overlap helper covers that distinction. [epub.js:403](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/epub.js#L403-L579), [overlap helper](../client/src/features/reader/media-overlay/lib/media-overlay-range.ts).

Two source hazards require proof fixtures: the automatic highlight handler uses assignment in `find((x) => (x.index = resolved.index))`, which fails for index zero and can choose the wrong document in a spread; and `MediaOverlay` skips text-only SMIL `par` entries. Do not copy this behavior into a new native bridge or label it complete EPUB media-overlay support. W3C describes clip-boundary playback and optional TTS rendering for text-only overlay entries. [view.js:528](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/view.js#L521-L539), [EPUB Reading Systems section 9](https://www.w3.org/TR/epub-rs-33/#sec-media-overlays).

For native audio, the existing authenticated API already supplies `GET /api/v1/epub/:bookId/media-overlay?fileId=...` and ranged `/media-overlay/file/*` resources. `EpubMediaOverlayPlaylist` contains section/fragment IDs, resource MIME/size and clip boundaries. Prototype native AVPlayer against these resources or downloaded local audio, coordinating highlighting through the DOM bridge. This is a route to native playback, not evidence of correct suspension/resume or timing. Do not use the explicitly audioless EPUB download for Read Along. [controller](../server/src/modules/reader/epub/epub.controller.ts), [playlist contract](../packages/types/src/epub.ts), [source-file delivery](../server/src/modules/book/book.controller.ts).

Preserve `source: "text" | "narration"`, `mediaOverlayFragment`, `mediaOverlaySectionIndex`, and `positionSeconds` when saving progress. Recorded narration and TTS need separate state, resume identities and audio-focus ownership. Foliate TTS produces SSML and mark-to-Range mappings; it does not synthesize speech. The installed Apple SDK exposes SSML utterances from iOS 16, but mark callbacks and compatibility with Foliate's SSML must be tested before selecting that adapter. [progress DTO](../server/src/modules/book/dto/save-progress.dto.ts), [existing web progress](../client/src/features/reader/shared/composables/useReaderProgress.ts), [TTS source](../client/public/assets/foliate/tts.js), [Apple utterance API](https://developer.apple.com/documentation/avfaudio/avspeechutterance).

## Genuine interactive page turns and remaining proof

UIKit `UIPageViewController(transitionStyle: .pageCurl, navigationOrientation: .horizontal, options: ...)` provides an interactive book curl with app-supplied child controllers. Its data source supplies adjacent controllers on demand. Commit navigation only when the delegate's `transitionCompleted` is true; canceled curls must preserve the original CFI. The installed UIKit header permits one controller for an edge spine with `doubleSided=false`; double-sided edge pages require a front/back pair. A middle spine requires two controllers and double-sided content. Transition style/orientation are read-only after creation, so rebuild the container around a retained anchor when changing them. Reverse the before/after data source for RTL. [Apple page-controller guide](https://developer.apple.com/library/archive/documentation/WindowsViews/Conceptual/ViewControllerCatalog/Chapters/PageViewControllers.html), [current API](https://developer.apple.com/documentation/uikit/uipageviewcontroller).

Foliate provides pagination and scrolling, with an optional sliding animation. It does not provide native page curls, public arbitrary-page enumeration, or every required mode/animation combination. Scrolled axis follows document writing direction; setting `flow="scrolled"` does not establish continuous horizontal reading for ordinary horizontal text. A prototype needs a bounded page-boundary adapter and current/adjacent controller cache. Compare live renderer controllers with temporary snapshots during the actual UIKit curl; verify immediate return to selectable, accessible content and native input after completion/cancellation. A snapshot plus an unrelated decorative animation is insufficient. [paginator.js:787](https://github.com/mooneeb/bookorbit/blob/5c56bb4bab256f5855e6f26e053b13d52ee6147a/client/public/assets/foliate/paginator.js#L787-L792), [turn/relayout implementation](../client/public/assets/foliate/paginator.js), [approved modes](../docs/ipad/specification.md#reader-behavior).

The next prototype must establish these outcomes through actual native UI, the web reader and delivered files:

1. Local modules, image/font/CSS/SMIL/audio resources and content isolation work without a live content server; missing or changed resources report failure clearly.
2. Native and web selections/resume CFIs resolve to the same passage after fonts, rotation, window changes and every mode change, including fixed layout and RTL. Compare passage text/endpoints, not raw CFI equality or percentages alone.
3. Interactive forward/reverse curls, canceled drags, rapid turns, chapter boundaries, Pencil/finger arbitration and Reduce Motion preserve location. Test single/facing pages and all four mode families before choosing the engine.
4. Recorded playback/from-here/follow/resume, section zero, a spread's second section, shared audio clips and missing clip ends work with measured timing. TTS remains independently resumable. Suspension/background playback and audio interruptions require a physical iPad.
5. Measure active/adjacent renderer count, peak/resident memory, page preparation latency, display cadence, repeated open/close retention and search on representative large books. Set thresholds from actual hardware results.
6. Verify VoiceOver, accessible text selection and native keyboard controls on the real renderer. Simulator screenshots or an audit of unrelated library controls do not prove reader accessibility.
7. Complete the preceding physical signing/network proof through the actual AltStore/AltServer route and home-server connection. Simulator ad hoc signing establishes neither free-signing renewal nor physical-device reader performance.

No source reviewed establishes a pass for those outcomes. Integration should remain behind the required proofs until results and any design blockers are recorded explicitly.

## Concrete proof fixture plan

This section specifies fixtures to build and exercise later. No media was generated and no renderer prototype was run during this research. Existing [server media-overlay tests](../server/src/modules/reader/epub/epub-media-overlay.test.ts) write `Buffer.alloc(16, chapter)` as each MP4 and omit the referenced sentence elements from their XHTML. Those fixtures prove parser behavior only. They cannot demonstrate decoded audio, narration, highlight placement or clip timing. The [iPad harness](../server/test/ipad/harness.ts) currently provides a PDF, so the native renderer proof needs its own valid EPUB file.

### Recorded audio with independent clip boundaries

Build the recording before packaging/playback. Use an already installed local system voice, record its name and OS build, and save four spoken sentences to AIFF with `say -v '<installed voice>' -r 160 -o p1.aiff 'Alpha grinning face cafe omega.'` and analogous commands for `p2` through `p4`. Using speech synthesis during fixture creation produces recorded narration; playback of the resulting immutable file must use AVPlayer and must not invoke live app TTS. The local `say(1)` manual documents voice selection and file output. FFmpeg 8.1.2 and `say` are already available on this Mac.

Reject any source utterance that lasts six seconds or more rather than truncating speech silently. Resample each to 44,100 Hz mono, pad to exactly 264,600 samples, reset timestamps, concatenate four segments, and encode one AAC-LC M4A. The independently selected segment boundaries are 0, 6, 12, 18 and 24 seconds, rather than timings inferred from the player's own callbacks. A proposed command, to validate during fixture construction, is:

```sh
ffmpeg -nostdin -i p1.aiff -i p2.aiff -i p3.aiff -i p4.aiff \
  -filter_complex '[0:a]aresample=44100,aformat=sample_fmts=fltp:sample_rates=44100:channel_layouts=mono,apad=whole_len=264600,atrim=end_sample=264600,asetpts=N/SR/TB[a0];[1:a]aresample=44100,aformat=sample_fmts=fltp:sample_rates=44100:channel_layouts=mono,apad=whole_len=264600,atrim=end_sample=264600,asetpts=N/SR/TB[a1];[2:a]aresample=44100,aformat=sample_fmts=fltp:sample_rates=44100:channel_layouts=mono,apad=whole_len=264600,atrim=end_sample=264600,asetpts=N/SR/TB[a2];[3:a]aresample=44100,aformat=sample_fmts=fltp:sample_rates=44100:channel_layouts=mono,apad=whole_len=264600,atrim=end_sample=264600,asetpts=N/SR/TB[a3];[a0][a1][a2][a3]concat=n=4:v=0:a=1[out]' \
  -map '[out]' -c:a aac -profile:a aac_low -b:a 64k -movflags +faststart narration.m4a
```

Retain a PCM master and construction manifest with the sample count, sentences, voice/rate, tool version and final SHA-256. Inspect the encoded file with `ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,profile,sample_rate,channels,start_time,duration:format=duration -of json narration.m4a`; decode the complete file with `ffmpeg -v error -i narration.m4a -f null -`, and listen to all four clips. Inspect AAC priming/edit-list behavior rather than assuming the first compressed packet timestamp is zero. Pin the generated bytes once validated; do not claim speech output hashes are identical across OS/voice updates. [FFmpeg padding/trimming/concatenation documentation](https://ffmpeg.org/ffmpeg-filters.html), [ffprobe fields](https://ffmpeg.org/ffprobe.html).

`OPS/c1.smil`:

```xml
<smil xmlns="http://www.w3.org/ns/SMIL" xmlns:epub="http://www.idpf.org/2007/ops" version="3.0"><body><seq epub:textref="c1.xhtml"><par id="s1"><text src="c1.xhtml#p1"/><audio src="narration.m4a" clipBegin="0s" clipEnd="6s"/></par><par id="s2"><text src="c1.xhtml#p2"/><audio src="narration.m4a" clipBegin="6s" clipEnd="12s"/></par></seq></body></smil>
```

`c2.smil` uses the same structure with `c2.xhtml`, fragments `p3`/`p4`, and clips 12-18 / 18-24 seconds. This deliberately reuses one audio resource across two SMIL files. The public playlist should report section indices `[0,0,1,1]`, text fragments `[p1,p2,p3,p4]`, clip starts `[0,6,12,18]`, clip ends `[6,12,18,24]`, and section start times `[0,12]`. Its resource list should contain the audio once. Those expectations are independent of Foliate's automatic highlight handler. [Playlist builder](../server/src/modules/reader/epub/epub-media-overlay.ts), [playlist contract](../packages/types/src/epub.ts).

Exercise section zero first, then starting from `p2`, crossing to `p3`, pause/relaunch/resume, rates 0.5/1/2, cancellation during loading and stale observer callbacks after file switching. ### A real native route, with an explicit content model

`UITextView` renders attributed text through TextKit and supplies native text interaction. Start a small proof with `UITextView(usingTextLayoutManager: true)`, `isEditable = false`, `isSelectable = true` and ordinary `attributedText`, retaining the built-in text accessibility. Use `UIFontMetrics` for readable fonts that respond to Dynamic Type. Do not substitute a copied accessibility label, hide meaningful text, assign fictional roles, increase typography merely for the audit or retain an underlying WKWebView. On the current SDK, accessing `layoutManager` silently switches a TextKit 2 view to TextKit 1 and invalidates cached TextKit 2 objects; the proof must avoid that accessor and record its actual engine. [Apple TextKit overview](https://developer.apple.com/documentation/uikit/textkit), [explicit initializer](<https://developer.apple.com/documentation/uikit/uitextview/init(usingtextlayoutmanager:)>), [font scaling](https://developer.apple.com/documentation/uikit/uifontmetrics), [installed UITextView header](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/UITextView.h:261).

TextKit is a native text/layout system, not a complete EPUB XHTML/CSS engine. Apple's HTML attributed-string importer is explicitly intended for styled-text conversion rather than general HTML; its documented main-thread synchronization and external-resource timeouts make it a poor foundation for this proof. It does not provide an original-source CFI map. Instead, parse the **delivered XHTML** into an explicit source model and create attributed text deliberately. `XMLParser` supports an input stream, namespaces and an external-entity policy of `.never`; its callbacks report content rather than defining HTML rendering. Bound bytes, tree depth, text/element counts and decoded assets, check cancellation, and report unsupported/malformed content. Disabling external entities alone is not a complete resource or memory policy. Do not fetch publication DTDs or arbitrary external image/CSS resources. [Apple importer limits](<https://developer.apple.com/documentation/foundation/nsattributedstring/init(fileurl:options:documentattributes:)>), [installed parser API](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/Foundation.framework/Headers/NSXMLParser.h:27).

The proposed model keeps original package/spine identity, element hierarchy/IDs, character-data chunks and UTF-16 values independently of display runs. Each display run records its original source endpoints; inserted paragraph separators/list markers and attachment characters are identified as generated display content. Parser `foundCharacters` callback boundaries are not source text-node boundaries. Coalesce callbacks according to source structure, handle CDATA/comments and retain source whitespace even when display collapses it. Never normalize decomposed accents to NFC or trim the source model. The exact conversion and its supported formatting rules are implementation work, not functionality supplied by `XMLParser`.

### Passage anchors and actual layout boundaries

Foundation's attributed-string length uses UTF-16 units, which matches the CFI offset unit, but equal units do not make flattened-text offsets into CFIs. EPUB CFI character-data chunks retain expanded entities and source whitespace; element and character-data steps are indexed differently. Source hierarchy and package indirection remain essential. The current Foliate implementation merges adjacent text/CDATA nodes into logical chunks, ignores comments, counts empty chunks and emits range paths. The native adapter must interoperate with that actual public web behavior rather than introducing a native-only location field. [Foundation length](https://developer.apple.com/documentation/foundation/nsattributedstring/length), [CFI source rules](https://w3c.github.io/epub-specs/epub33/epubcfi/index.html#sec-path-res), [BookOrbit CFI chunk/index algorithm](../client/public/assets/foliate/epubcfi.js:196), [BookOrbit CFI producer](../client/public/assets/foliate/view.js:711).

For the current delivered fixture, `p1` remains exactly 21 UTF-16 units and `😀 café` is `[6,14)`. Its independent oracle remains `epubcfi(/6/2[c1ref]!/4/2[p1],/1:6,/1:14)`. If the native displayed chapter places `p1` first, that native range is `{location:6,length:8}`; generated separators after `p1` must not change this source offset or the later paragraph's independent map. Source-to-display and display-to-source maps need deterministic policies for collapsed whitespace and generated characters; do not silently invent an anchor for unmapped content. Preserve original source coordinates when resuming a point whose whitespace is visually collapsed. Test mixed inline elements, escaped IDs/assertions, entity references, CDATA/comments and anchors beside images. [Delivered fixture builder](../scripts/ipad/reader-fixture.mjs:80), [earlier independent Unicode vector](#independent-unicode-oracle-and-isolation-gates).

Use actual native selection ranges and actual selected text. The iOS 26 `selectedRanges` API supports discontiguous bidirectional selections; its deprecated `selectedRange` is only their union and can include unselected text. Do not serialize that union as a single selected-passage CFI without an explicit supported policy. A CFI range cannot cross two content documents; chapter-crossing selections need separate valid anchors or a truthful unsupported result. [Native selection API](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/UITextView.h:231), [existing single-document range producer](../client/public/assets/foliate/epubcfi.js:147).

TextKit 2 provides viewport layout, fragment/line character ranges and geometry. That supports a bounded current/adjacent layout experiment; it does not make estimated offscreen heights into page boundaries. Apple warns that geometry outside the viewport can be estimated until explicitly laid out, and ensuring broad document layout can be expensive. Derive page identity from actually laid-out visible content mapped back to original CFIs, with layout-generation/viewport/font identity. Native line ranges are relative to their associated attributed text/element, so conversion to a chapter range must be verified rather than assuming every range is document-global. Preserve grapheme/ligature boundaries without changing source UTF-16 endpoints. [TextKit 2 viewport constraints](https://developer.apple.com/videos/play/wwdc2021/10061/), [line ranges/geometry](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/NSTextLineFragment.h:38), [viewport range](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/NSTextViewportLayoutController.h:139).

For a separate tiny TextKit 1 pagination experiment, `ensureLayout(for:)`, `glyphRange(for:)` and `characterRange(forGlyphRange:actualGlyphRange:)` can measure real fixed-container pages before mapping them to source anchors. Do not accidentally switch the TextKit 2 accessibility proof by requesting these APIs. TextKit 1's glyph/character mappings can expand around composed text and can force preceding layout; the controlled small-book result would not establish scalable pagination. Native `UIPageViewController.pageCurl` still needs current/adjacent live controllers, complete/cancel semantics and selectable accessible content, as described earlier. [Installed layout APIs](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/NSLayoutManager.h:144), [glyph/character expansion](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/NSLayoutManager.h:249).

Viewport layout bounds drawing work, not necessarily storage. Standard `NSTextContentStorage` still owns an attributed backing string. Avoid parsing/loading the whole spine or decoding every image at open; start with the selected chapter, cancellable adjacent preparation and a finite cache. Arbitrarily large single chapters/paragraphs need measured limits or a disk-backed source index/custom `NSTextContentManager` that supplies retained elements on demand. A chapter-at-a-time array alone is not a general bounded-memory guarantee. Custom storage entails native selection/location/accessibility work, not a free framework switch. [Backing storage](https://developer.apple.com/documentation/uikit/nstextcontentstorage), [custom content-element lifetime requirements](/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneSimulator.platform/Developer/SDKs/iPhoneSimulator.sdk/System/Library/Frameworks/UIKit.framework/Headers/NSTextContentManager.h:38).
