# Authenticated native audio playback proof

The Reader Proof app now opens audiobook files through genuine AVPlayer playback. This is the implementation for the first integration experiment recommended by [the audio feasibility note](audio-engine-feasibility.md). It remains separate from the production reader until independent localhost runtime evidence establishes its behavior.

Manifest, playback-state and PUT request models are generated from the shared version-2 contracts. The proof validates the selected book, opaque asset IDs, unique file IDs, sequence, safe numeric bounds and bounded track/chapter counts. Chapter navigation requires complete track durations and checks the whole-book chapter position against its asset-local offset. Missing durations do not produce guessed chapter positions.

AVURLAsset uses a registered custom URL containing a random reader identity. Only that exact URL resolves to the selected descriptor; URL text cannot choose an authenticated endpoint. The resource loader retains at most eight live requests and two active HTTP transfers. Each transfer reads at most 256 KiB, and completed chunks rotate through the queue so a large request cannot monopolize a transfer indefinitely. Content information uses the validated MIME type's UTI, real byte length and allowed content types. All-data-to-end requests stream successive finite chunks, and byte delivery follows the next unprovided offset. There is no app-owned full-file materialization or persistent media cache.

The existing native API performs same-origin, cookie-free authenticated range requests with one coalesced-refresh retry, checked range arithmetic, exact 206 Content-Range and length checks, identity encoding, exact body bounds, cancellation and a pinned account/session generation. Reader close cancels loading, finishes retained requests and removes the player and observers. A same-size replacement is not currently protected by a strong representation validator; this remains an explicit integration gap from the feasibility note.

Native controls provide Play/Pause, asset-local Seek, track selection, validated chapter selection, retry, and explicit progress Save. Saves use asset-local milliseconds, the acknowledged revision and a stable operation UUID. An uncertain write retains the exact request for retry; track switching is disabled until it is acknowledged. Conflict or manifest-change responses require closing and reopening rather than overwriting an unexamined newer state. Reopening resumes the acknowledged track and local position. The proof activates the spoken-audio playback session when playing. Automatic production-reader progress, remote commands, background entitlement and interruption/route behavior are separate integration work.

Audiobook HTTP routes now enforce the existing LibraryDownload permission in addition to the service's book-access checks. The proof's Read and chapter-inspection actions follow that permission, including the existing superuser bypass. Asset responses use private, no-store caching. Single-range parsing accepts exact, open-ended and suffix ranges with safe integers and EOF clamping. Malformed, multiple, reversed, empty and unsatisfiable ranges return 416 with the total size instead of falling back to an entire-file response.

Focused real-source Swift 6 typechecking passed with complete concurrency checks and warnings treated as errors in `/tmp/bookorbit-audio-proof-source-typecheck.log` and `/tmp/bookorbit-audio-proof-source-typecheck-final.log`. Strict formatting, Node syntax, generated-contract freshness and diff checks passed. Production backend typechecking and full ESLint passed in `/tmp/bookorbit-audio-proof-server-typecheck.log` and `/tmp/bookorbit-audio-proof-server-eslint.log`. Both production and Reader Proof native builds passed for both simulator architectures in `/tmp/bookorbit-audio-proof-production-build.log` and `/tmp/bookorbit-audio-proof-build.log`. No playback, audible output, seek latency, memory budget, format compatibility, browser reopen, accessibility or background/device proof is claimed by these source checks.

The independent tester should begin with a tiny two-asset AAC/MP3 book and real localhost API/native/browser/file journeys, then expand the format, fault and bounded-resource matrix described in the feasibility note. Advancing AVPlayer time is distinct from captured audible output. Unsupported format results, missing installed encoders or simulator capture limitations must remain visible. Use the cached simulator and installed tools without downloads, a physical iPad or user assistance.
