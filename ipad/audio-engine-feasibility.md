# Native audio engine feasibility

Research date: 2026-10-07. Source snapshot: `e8f1469902d5ef59f459192547ea1ccb59cdeff8`; installed SDK: iPhoneSimulator 27.0. This is a source-based recommendation for issue #2, not a passed compilation, playback, background, accessibility, format, or physical-device proof. No app build, simulator run, dependency installation, runtime download, or media download was performed. The private-client target retains permission enforcement; selected offline books are a separate explicit download feature. [Private-client decision](../docs/adr/0006-build-a-private-client-for-the-home-server.md), [offline decision](../docs/adr/0002-save-offline-reading-and-annotations-locally.md).

## Recommended experiment

Prototype `AVPlayer` with an `AVURLAsset` using an app-owned custom scheme and `AVAssetResourceLoaderDelegate`. Resolve that opaque URL through a registered asset descriptor, then fetch bounded authenticated HTTP ranges through the existing `BookOrbitAPI` boundary. Keep credentials out of media URLs and do not use an undocumented `AVURLAssetHTTPHeaderFieldsKey`. The installed public `AVURLAsset` declarations expose cookie and transport options but do not declare that header key. This recommendation follows the documented arbitrary-byte resource-loader seam; whether this exact audio path plays the required files remains a runtime gate. [Apple resource loader](https://developer.apple.com/documentation/avfoundation/avassetresourceloader), [custom loading example](https://developer.apple.com/videos/play/wwdc2022/110379/), [public URL-asset options][sdk-asset], [native API](Sources/Connection/BookOrbitAPI.swift).

Start with one local, generated AAC/MPEG-4 asset and one MP3 asset. Do not add a decoder, whole-file cache, local HTTP server, or transcoding pipeline before the public framework experiment answers whether it is needed. The repo already generates and verifies a 24-second recorded AAC `.m4a` fixture using installed tools; that is useful material, although its current EPUB narration route is not itself an audiobook delivery proof. [Recorded fixture builder](../scripts/ipad/reader-fixture.mjs).

## Existing contract and ownership

The canonical manifest is `bookorbit.audiobook-manifest` version 2. Each asset has `assetId`, matching book `fileId`, sequence, format, nullable duration/size, and `etag`; each chapter has a revision-dependent ID, asset identity, global start/end, and asset-local offset. Preserve these meanings instead of inventing a native track index as persisted identity. Current server asset ordering uses the existing media comparator. [Shared contract](../packages/types/src/audiobook.ts), [manifest construction](../server/src/modules/audiobook/audiobook.service.ts).

The public routes are under `/api/v1/audiobooks/:bookId`: manifest; `assets/:assetId/content`; playback-state GET/PUT/DELETE; and bookmark GET/POST/PATCH/DELETE. Asset delivery checks book access, resolves an asset belonging to that book, and checks file access before filesystem streaming. Global authentication and library guards are registered. These checks do not replace a specific content-delivery permission. [Controller](../server/src/modules/audiobook/audiobook.controller.ts), [service](../server/src/modules/audiobook/audiobook.service.ts), [book/file access](../server/src/modules/book/book.service.ts), [global guards](../server/src/app.module.ts).

Playback state is **asset-local milliseconds**. The PUT body requires `assetId`, `positionMs`, `capturedAt`, stable operation UUID, `baseRevision`, and `manifestRevision`; the DTO validates these fields. The service returns 412 for a changed manifest and 409 for a revision conflict, clamps small duration-rounding overruns, and calculates whole-book percentage only when all asset durations are complete. It also invokes existing ebook progress synchronization. Audio bookmark positions are **whole-book milliseconds**, with optional current-manifest chapter identity. Equal units do not make these coordinates interchangeable. [Canonical types](../packages/types/src/audiobook.ts), [playback DTO](../server/src/modules/audiobook/dto/put-audiobook-playback-state.dto.ts), [service](../server/src/modules/audiobook/audiobook.service.ts).

The web queue retains only the active Howl and immediate neighbors, uses actual loaded duration, tracks activation generations, and preserves position during bounded token recovery. Web progress coalesces writes every five seconds, retries network failures with the same operation ID, reloads conflicts, and holds writes after a stale-manifest response. Reuse the canonical behavior deliberately, including truthful failures and acknowledged saves; do not copy browser session/cookie delivery into the native loader. [Web queue](../client/src/features/reader/audiobook/composables/useAudioQueue.ts), [web progress](../client/src/features/reader/audiobook/composables/useAudioProgress.ts).

For chapter selection, prefer the manifest's `assetId` and `assetOffsetMs`. The current server constructs those offsets from cumulative known durations, treating missing durations as zero. A chapter mapping across unknown-duration assets therefore needs explicit proof or an unavailable/uncertain state. Native AVPlayer duration alone does not silently revise the server manifest, and a global slider cannot be assumed accurate when durations are incomplete. [Chapter construction](../server/src/modules/audiobook/audiobook.service.ts), [web absolute seeking](../client/src/features/reader/audiobook/AudiobookReaderView.vue).

## Resource loading rules

These are documented framework obligations, followed by proposed BookOrbit limits:

- Retrieve the loader from the asset and set its delegate and dispatch queue. The delegate is weak, so the playback owner must retain it. Returning `true` accepts responsibility: retain the request until completion, handle overlapping requests, and complete success or failure. [Loader lifetime and callbacks][sdk-loader], [Apple callback](<https://developer.apple.com/documentation/avfoundation/avassetresourceloaderdelegate/resourceloader(_:shouldwaitforloadingofrequestedresource:)>).
- Populate content information with the **UTI identifier**, total byte length, and genuine random-byte-access support. `contentType` is not the HTTP MIME string. Honor nonempty `allowedContentTypes`; an incompatible type can cause an exception at completion. Derive the UTI from validated content/format, not an arbitrary publication-supplied URL. [Content information][sdk-content].
- Feed bytes with `dataRequest.respond(with:)` in ascending request order. `currentOffset` is the next unprovided byte; `requestedOffset`/`requestedLength` describe the original request. Use checked Int64 arithmetic. Finish only after satisfying the requested extent or actual EOF, because premature success can make the framework infer a truncated resource. [Incremental data request][sdk-data].
- When `requestsAllDataToEndOfResource` is true, ignore `requestedLength` and provide the remaining bytes incrementally until EOF, failure, or cancellation. A large request does not justify a large `Data` allocation. On `resourceLoader(_:didCancel:)`, remove that request and cancel its owned network work; prevent later callbacks from responding to it. [All-to-end and cancellation][sdk-data], [cancellation callback][sdk-loader].
- Leave `isEntireLengthAvailableOnDemand` false for authenticated remote content. Apple reserves the optimization for data available immediately and warns about network-dependent loading. It is not a substitute for HTTP range support. [Installed property contract][sdk-content], [Apple performance guidance](https://developer.apple.com/videos/play/wwdc2022/110379/).

For the prototype, propose 256 KiB HTTP ranges, at most two active transfers, eight retained loading requests, and no persistent byte cache. Serve larger framework requests through sequential chunks; fail overload explicitly instead of retaining an unlimited queue. These numbers are **experimental limits**, not measured product requirements. Bound app-owned pending buffers, capture transferred bytes/startup/seek latency and process-memory samples, and compare short and longer generated media. Framework caching and decoding are outside that arithmetic, so two chunks do not prove total process memory is 512 KiB. Apple documents the framework's separate dynamic caching behavior. [Framework caching](https://developer.apple.com/videos/play/wwdc2022/110379/).

## Authentication, validation, and cancellation

Extend the owning API with a range operation rather than exporting tokens. Existing native transport is ephemeral, disables cookies, limits redirects to the original origin, coalesces refresh, and tracks a session generation. Its existing bounded byte methods cancel the URLSession task and recheck session identity while reading. Carry those policies into audio delivery. A custom URL such as `bookorbit-audio://<reader-nonce>/asset.m4a` should identify a registered descriptor only; never translate arbitrary URL hosts, paths, or query parameters into authenticated requests. [Existing native transport](Sources/Connection/BookOrbitAPI.swift), [Apple incremental URLSession API](<https://developer.apple.com/documentation/foundation/urlsession/bytes(for:delegate:)>).

For each requested finite chunk, propose an exact `Range: bytes=start-end` and identity content encoding. Require a 206 response with consistent `Content-Range`, total size, MIME type, length, and exact bytes; cancel on excess, shortage, invalid numbers, transformed encoding, or mismatched asset identity. A 200 response to a requested range must fail this prototype instead of buffering the whole file. A server may legally ignore a Range header, so that failure is a deliberate client capability requirement. Validate every response before supplying media bytes. [HTTP range semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-14), [current delivery implementation](../server/src/modules/audiobook/audiobook.controller.ts).

Permit at most one authenticated retry after 401 through the existing coalesced refresh path, from the next **unprovided** byte. Do not feed an error body or replay bytes already supplied. Bound timeout/retry behavior; treat 403, missing files, revocation, and invalid content as terminal until an explicit retry. On reader replacement, logout, or account change, invalidate the reader/session generation, cancel transfers, fail still-live loading requests, and detach the old player. Stale bytes or progress must never cross into the new account. These are proposed acceptance conditions derived from existing session isolation and framework request lifetime, not a tested audio implementation. [API session isolation](Sources/Connection/BookOrbitAPI.swift), [request lifetime][sdk-loader].

The installed SDK explicitly marks `AVURLAsset` Sendable, while the resource-loader request API remains an Objective-C delegate boundary. Keep mutable loading requests on one proven executor; pass IDs, offsets, immutable descriptors, and bounded `Data` across the API actor. One reversible prototype arrangement is a delegate queue set to `.main`, synchronous `nonisolated` delegate entry points that verify `MainActor` isolation, and actor-owned request lookup by ID for async completion. Do not capture a loading request in a detached task or blanket-mark mutable state `@unchecked Sendable`. `MainActor.assumeIsolated` verifies executor identity and traps when used incorrectly; it is appropriate only with an established queue contract. Compile the exact arrangement under the repo's Swift 6 strict concurrency settings before assuming it works. [Asset Sendable declaration][sdk-asset], [delegate queue contract][sdk-loader], [isolation verification](<https://developer.apple.com/documentation/swift/mainactor/assumeisolated(_:file:line:)>), [project settings](project.yml).

## Smallest autonomous localhost proof

The following is a proposed sequence, **not an executed test report**. Reuse the existing isolated real-server harness, installed tools, and cached simulator; no home-server URL, user interaction, iPad, new runtime, or imported full audiobook is necessary. [Harness](../scripts/ipad/run-harness.mjs), [fixture generator](../scripts/ipad/reader-fixture.mjs).

1. Add an isolated audio proof entry and tiny local generated fixtures through ordinary authenticated audiobook routes. Start with a two-asset book containing distinct recorded content and deterministic chapters. Register descriptors from the actual version-2 manifest. Add a longer generated variant whose beginning and seek target can play before downloading its entire bytes. Preserve the original narration fixture oracle.
2. Compile the real AVPlayer/loader code with Swift 6 strict concurrency. Through actual native controls, play, pause, seek ahead/back, switch assets, and select a chapter mapped to the second asset. Record item status, current time, measured duration, asset/chapter IDs, exact HTTP ranges/byte counts, startup/seek latency, app-owned queue/buffer peaks, and process-memory samples. Verify decoded/rendered audio with an actual audio-output capture and independent fixture comparison when the runner supports it; advancing time alone is not audible-output evidence.
3. Save progress through the canonical PUT body, close/reopen, and verify the acknowledged asset-local position using public GET and the actual web player. Create a whole-book audio bookmark and resolve it correctly across an asset boundary. Exercise duplicate operation replay, conflicting revision, changed manifest, and missing duration without guessing global positions. Inspect delivered range bytes against the fixture source.
4. Use controlled public transport faults for 401/refresh, denied permission, wrong range/length/MIME, ignored range, truncated/oversized body, slow request, canceled seek, cross-origin redirect, replacement and account switch. Verify cancellation, bounded failure/retry, no credential-bearing URLs, no stale progress/bytes, and no complete-file materialization. Keep all failures and unfiltered native accessibility findings; inspect actual native/web images.
5. Expand the same path to generated M4A/M4B AAC/ALAC, MP3 CBR/VBR, FLAC, Ogg Vorbis and Ogg Opus. Use installed encoders only; unavailable encoding means an unresolved fixture gate, not a pass. Include tail-located MPEG-4 metadata, null manifest duration, zero/truncated files, and many small tracks/chapters. Compare the longer fixture to the short one with stated memory/latency budgets rather than extrapolating from a tiny asset.

The two-asset AAC/MP3 journey answers the first integration question. The expanded format, fault, performance and accessibility matrix is still required for corresponding production claims. Native playback readiness must not be represented by a network stub or a mocked clock. [Public playback contracts](../packages/types/src/audiobook.ts), [framework load/data contract][sdk-data].

## Background audio and physical residuals

Configure `AVAudioSession` with `.playback` and `.spokenAudio`, activate when playback starts, and handle activation failures, interruptions and route disconnects. Playback category plus the audio background mode supports audio with the app backgrounded or device locked; spoken-audio mode requests pausing rather than ducking during another app's spoken prompt. The inspected native project does not yet declare `UIBackgroundModes: audio`. These are necessary integration changes, not evidence that a lock-screen journey already works. [Apple configuration](https://developer.apple.com/documentation/avfoundation/configuring-your-app-for-media-playback), [spoken-audio mode](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/spokenaudio), [route-disconnect policy][sdk-session], [native project](project.yml).

Use the shared `MPRemoteCommandCenter` for supported play/pause/skip/position commands and `MPNowPlayingInfoCenter` for title, duration, elapsed time, rate, and bounded artwork. Retain registration tokens/targets and remove them on reader/session replacement; report unsupported or unavailable actions truthfully. Remote command callbacks need the same verified concurrency/lifetime treatment as loader callbacks. The system chooses how metadata appears on Lock Screen and Control Center. [Remote commands](https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter), [target ownership][sdk-commands], [Now Playing info](https://developer.apple.com/documentation/mediaplayer/mpnowplayinginfocenter).

Autonomous simulator testing can establish actual app background transitions, native controls, API persistence, and available simulator system controls. It cannot by itself establish physical speaker/headphone output, a hardware lock screen, Bluetooth/AirPlay behavior, real interruption/route changes, thermal/battery performance, or reliable long background playback on the iPad. Keep those issue-required residuals explicit without making them prerequisites for the autonomous implementation/test loop. Whole-book offline delivery, SMIL narration, ReadAlong/TTS persistence, and ebook/audio anchor correctness remain separate features; an audio engine proof does not implement them. [Playback configuration](https://developer.apple.com/documentation/avfoundation/configuring-your-app-for-media-playback), [issue scope](../docs/ipad/specification.md), [offline decision](../docs/adr/0002-save-offline-reading-and-annotations-locally.md).
