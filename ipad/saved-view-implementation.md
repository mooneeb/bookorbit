# Native saved views and table layout

Native saved views capture the active query, search, list/grid/table presentation and table layout. Create, apply, rename, duplicate, favorite and confirmed deletion operate locally. Storage is namespaced by server and authenticated user; snapshots belong to the current all-books, library, collection or smart-scope location. The catalog retains at most 100 views and one MiB of encoded data, with useful validation messages. Applying a snapshot awaits the owning book query before closing the picker; a rejected query remains visible as an error.

`SavedView` moved from a web-only type declaration into the canonical shared table-layout contract. The web composable imports and re-exports that type, preserving its existing runtime behavior. Native contracts generate the same saved view, recursive filter, sort and table layout, including canonical dictionary values. The native wrapper only adds native presentation, search and location state.

Table controls change column visibility, order and width for title, authors, formats, series and progress. At least one column remains visible; widths are bounded to 120 through 600 points. A horizontal viewport contains the existing vertically virtualized native table when configured columns exceed the window. Rows and headers use multiline scalable UIKit labels. Applying or canceling the column editor is explicit, and saved views restore the layout. Row accessibility exposes the displayed metadata and retains book selection.

No runtime, measured performance or visual-baseline approval is claimed by source checks. Snapshot import/export, pinned columns and automatic last-view selection are not implemented by this change.
