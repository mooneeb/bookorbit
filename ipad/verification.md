## Failures and corrections

### Native simulator recovery

The initial native run passed all four HTTP tests, then stalled in Xcode preflight without starting either native test. When the disk filled, that attempt was stopped. Task-generated build output and browser runtime caches were removed; source changes, dependency installations, user files and captured evidence were preserved. The installed simulator asset occupies approximately 7.5 GiB. Its removal was interrupted before the user authorized resuming after freeing space.

The resumed attempt used the cached runtime, restarted the local PostgreSQL container and disabled parallel native testing to avoid creating multiple active test devices. Run `run-32399-1791221842979` passed all four HTTP tests without retries. Xcode again stalled before test execution. A one-second process sample shows its simulator profile queue blocked in the kernel `stat` call while loading a runtime profile. Simulator boot and cache creation were also blocked. Stopping orphaned processes from the task-created simulator released substantial swap allocation; free disk space stabilized at approximately 44 GiB. These measurements do not attribute all system storage or memory use to this task.

The first service restarts and runtime unmount/remount attempts did not restore booting. The system-owned `simdiskimaged` service remained blocked; a noninteractive administrator restart was unavailable because macOS requires a password. No password was requested. A Mac restart was proposed prematurely. After the user requested recovery without a restart, the pending runtime unmount completed. `simctl runtime scan-and-mount` remounted the existing asset; `simctl runtime dyld_shared_cache update` rebuilt approximately 3.9 GiB of cache. Simulator boot then completed in 34 seconds. No Mac restart, new runtime download, administrator prompt or global security-setting change was needed.

Run `run-32399-1791221842979` preserves `run.log`, `xcode-stall.sample` and `core-simulator-recovery.log`. It produced no native test result. Run `run-41630-1791222445251` compiled and launched the runner, but test bootstrap failed before either case entered: simulator `testmanagerd` was waiting on the automation-mode service. Restarting only those simulator services restored test execution.

Run `run-44343-1791222740608` entered both native cases but failed secure credential storage with signing disabled. Its inspected `connection-keychain-failure.png` shows the correct localhost profile and a useful credential-storage error. Enabling ad hoc simulator signing restored Keychain access. This does not prove physical-device signing.

Run `run-45811-1791222890292` passed the native OIDC journey, including relaunch and sign-out. Local login, search, details, rotation and relaunch worked, but the accessibility audit found weak count/pagination contrast and partial Dynamic Type support on sign-out. The control request for session revocation also failed because it sent an empty JSON body. The test helper now sends that header only with a body; assertions still require a successful public HTTP response. Count/pagination text and sign-out use readable semantic styles, and unavailable pagination actions are omitted. Post-failure Xcode diagnostics stalled; only the verified `simctl diagnose` child was stopped so Xcode could finish its failing report. This is not an unqualified clean run.

Run `run-49132-1791223396941` again passed native OIDC. Its local journey stopped at a sidebar contrast audit failure. The agent opened the audit element and full-screen PNGs: the flagged element was the `Large library` sidebar button. Explicit semantic sidebar-row backgrounds corrected contrast. Moving sign-out into a scalable sidebar action corrected the toolbar Dynamic Type failure. Earlier landscape attachments used a stale application crop with clipped content; the capture helper now takes a main-screen screenshot and asserts landscape image geometry. The final actual images above confirm complete landscape content. Free disk space was approximately 38-40 GiB during these runs.

Run `run-51663-1791223738072` stopped at compilation because the initial screen-capture fix used an unavailable `XCUIDevice.screenshot()` method. The corrected helper uses `XCUIScreen.main.screenshot()`. Run `run-52616-1791223790252` passed session revocation/recovery and OIDC, but retained both sidebar contrast and toolbar Dynamic Type failures. Its inspected failure-element, landscape and expired-session images and process sample remain in the run directory. Post-test verbose diagnostics were stopped after assertions completed; the failing report was preserved. The harness now passes `-collect-test-diagnostics never`, retaining assertion failures, logs, screenshots, recordings and `.xcresult` reports without verbose system diagnostics. Final run `run-54941-1791223995874` completed normally with both native cases and the accessibility audit passing.

Every attempt passed the four public HTTP tests. Failed native reports and attachments remain under their run directories. The harness removed each temporary database and its server listeners after completion or interruption.
