# Native metadata matching and cover search

The authorized metadata editor now includes provider identifiers, multiple series memberships, personal and provider ratings, audio narrators/duration/abridgement/chapters, and comic metadata. Generated contracts derive request fields, provider identifiers and limits from the shared TypeScript package; owning Nest DTOs implement those contracts while retaining validation. Fields preserve omission versus explicit clearing, and existing field locks remain available. Series expected-book counts are shared series data and are identified as such in the editor.

Provider matching uses the existing authorized provider-list, SSE search and identifier-lookup routes. The native editor offers title/author/ISBN inputs, ebook/audio/comic media, provider selection, per-provider status and retry, cancellation, and current/proposed comparisons. Applying explicitly selected unlocked fields changes the draft. Genre merging is optional. Provider identifiers and cover choices are separate explicit selections; nothing is written until the editor's Save action.

Metadata Save acknowledges the owning metadata-and-locks transaction before applying staged ebook/audio covers through the existing from-URL route. These writes are separate server operations. If a cover write fails, acknowledged metadata remains saved and the failed selection remains available for retry. If a cover succeeds but refreshing details fails, the message identifies the saved cover and refresh failure separately. Already acknowledged custom and extended metadata values are rebased before retry.

The cover editor also searches the existing four canonical cover providers, previews actual proxied images, and stages a chosen URL until Save. Search is available for ebook and audio media. Existing photo upload, versions and reversion remain available. Search cancellation and failures retain useful input; source images expose a separate preview retry. The client validates HTTP(S) selections before enabling Choose, while server URL validation and library/metadata permissions remain authoritative.

Search retains at most 100 distinct results. Metadata SSE delivery is limited to 4 MiB total, 512 KiB per line/event and 100 candidates, with cancellation, session checks and a two-minute request timeout. Cover previews share the authenticated server/user/session-scoped loader with dashboard covers: three active requests, at most thirty-two waiting requests, twenty-four cached images and a 400-pixel decoded dimension. ImageIO decoding happens outside the main actor. Publication files and full libraries are not loaded to perform matching.

Automatic refresh and embedded-file preview/comparison remain separate parity work. This editor does not claim chapter duration editing, all-language localization, production-reader integration, physical-device acceptance, or human-approved visual baselines. Independent public HTTP/native/browser/file acceptance is the next handoff, including actual provider protocol fixtures, locks, omission/clears, role denial, cancellation, partial save failures, identity isolation and cross-client reopen. Full unfiltered accessibility audits and actual opened screenshots remain gates.
