# Personal reading status, dates and notes

Book details now includes Your reading and a native editor for all canonical reading statuses, started/finished dates and the reader's personal note. This editor is available to authenticated readers with access to the book independently of shared metadata editing. Existing server library access checks and user-scoped status/note storage remain authoritative; editing does not grant library or metadata permissions.

Cancel leaves the draft unwritten. Save sends only changed status/date fields through `PATCH /books/:id/status` and changed notes through `PATCH /books/:id/personal-note`. Clearing sends explicit null; unchanged dates are omitted. The editor acknowledges the actual server response, including automatic dates and transitions such as rereading. An acknowledged status is retained if the separate note write fails, with the note draft available for retry. Already acknowledged status/date fields are not sent again on note retry. Parent book details receive acknowledged values even after a partial save.

Dates use the authenticated account's time zone. Date-only values and projected UTC-midnight reading-attempt dates retain their calendar day; other stored timestamps use the account time zone. Real calendar dates, future dates, ordering and unread/want-to-read date combinations are checked in the editor, with the existing server rules providing the final validation. Notes use the existing trim/clear behavior and the shared 10,000 UTF-16-unit storage limit. Native controls expose loading, validation, failure/retry and Save states with semantic fonts, wrapping text and at least 44-point action labels.

Request shapes, status vocabulary and the note limit now come from the shared package. Owning DTOs implement the shared request types without changing existing routes or validation semantics. The web status/note composables consume the same declarations. Native requests use bounded authenticated JSON with cancellation and session checks, a 1 MiB response limit and a two-minute request timeout. Neither complete libraries nor publication downloads are needed.

Book details refreshes after the reader closes, so progress-driven status changes are visible when reopening Your reading.

Shared, production backend and full web typechecks passed, as did full backend/web ESLint. The Swift 6 production build passed for both simulator architectures in `/tmp/bookorbit-personal-reading-build-final.log`. The first full build exposed draft initialization before all stored properties were initialized; that error was corrected, and its original log is preserved at `/tmp/bookorbit-personal-reading-build.log`. Focused production-source Swift 6 checks also passed with complete concurrency checking and warnings treated as errors. Strict handwritten Swift formatting and generated-contract freshness passed.

Independent public HTTP/native/browser/file acceptance is the next handoff, including cross-user isolation, access denial, real date transitions/time zones, note Unicode/clears, omitted-field preservation, Cancel, partial saves/retry, relaunch and actual web reopen. Source checks do not establish runtime acceptance or human-reviewed baselines.
