# Native comic-series handoff

Production comic reading now resolves the next accessible comic through the existing server-side series-next route. It fetches one current-book detail and one bounded next-book answer rather than paging through a series. The selected successor is rechecked through its actual book detail and matching CBZ/CBR/CB7 file before opening. Canonical next-book models and the current book's primary series ID are generated from shared contracts, with account/session identity pinned across requests.

At the final visible page or pair, a semantic native action opens the next comic. Opening first advances the logical position to the actual last page, then waits for the existing acknowledged progress save. Failed progress or successor loading keeps the current reader open with the draft/retry behavior intact. A wrapping host replaces the active reader instead of stacking another full-screen reader for every issue, keeping a long series bounded to one active reader and its page window.

The existing automatic-advance preference is now loaded, changed-only saved, reset and defaulted through canonical reader preference routes, or persisted in the existing account/server-scoped local settings when synchronization is disabled. Automatic advance means a deliberate next-page action after the final page has been visible for 1.5 seconds, matching the web reader. It never starts a timed unsolicited transition. Continuous reading retains the explicit successor action; automatic advance applies only to paged reading. No successor is offered for a book outside a series, the last accessible issue, an unsupported file, or the isolated comic proof path.

The Next page button and keyboard command can advance into the successor after arming. Genuine page-turn boundary gestures can do the same, without using speculative page-controller data-source queries as user actions. Boundary detection requires a one-finger forward gesture that began on the last visual unit, a completed transition state and an 80-point dominant reading-axis movement. It ignores zoomed or scrollable content on that axis, and still applies the reader's delayed-arming and single-opening guards. Discrete/Reduce Motion navigation uses the same successor action. Last-page logical position and final completion are retained before replacement.
