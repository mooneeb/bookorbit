# Issue 3 acceptance harness

The confirmed seams are the actual native and web UI, authenticated HTTP routes, and delivered or exported artifacts. The harness runs the production native app, the real Nest application, a newly migrated isolated PostgreSQL database, and temporary source content. Tests may replace Pencil/Scribble input and controlled transport or file-write failures. They must observe saved behavior through the confirmed seams.

Use Node 24 or newer, pnpm 11.22.0, Xcode 27, an iOS 26 iPad simulator, PostgreSQL from the development compose file, and locally installed Chromium. No paid signing membership is required for simulator tests. The PDF artifact drivers use the locally installed Poppler renderer independently of the publication writer.

```sh
node scripts/ipad/run-harness.mjs --list-annotations
node scripts/ipad/run-harness.mjs --annotations
node scripts/ipad/run-harness.mjs --annotations --web
node scripts/ipad/run-harness.mjs --annotations --ui --web --case=A01
node scripts/ipad/run-harness.mjs --annotations --ui --web --case=A05
node scripts/ipad/run-harness.mjs --annotations --serve --web
node scripts/ipad/restart-server.mjs <existing-run-ID>
node scripts/ipad/restart-server.mjs <existing-run-ID> --allow-stopped
node scripts/ipad/run-bookmark-retirement.mjs
```

`--case=A01` through `A07` selects implemented native method names and public HTTP/browser test titles. `--native-only --annotations --ui` isolates the native seam for a targeted RED/GREEN cycle. `IPAD_TEST_ONLY` accepts comma-separated `BookOrbitUITests/Class/method` identifiers. Set `IPAD_TEST_DESTINATION='platform=iOS Simulator,id=<UDID>'` to use the designated test simulator. The runner boots explicit IDs and resets the app container once before an E02 suite, while termination/relaunch within a test retains its real local state. It rejects simultaneous harness-owned Xcode runs using `/tmp/bookorbit-ipad-xcode.lock`.

`run-bookmark-retirement.mjs` prepares and migrates its own uniquely named database, invokes only the two public A05 bookmark-retirement protocol tests in `server/test/ipad/bookmark-retirement.http.test.ts`, and drops that database in cleanup. It leaves the retained native/API fixture untouched and writes a separate `test-results/ipad/bookmark-retirement-*` report.

The focused A05 command starts the browser before running native and browser tests concurrently. Test-only transport checkpoints coordinate `native-offline-ready`, `browser-delete-done`, and `native-reconciled`; assertions still use actual UI, authenticated routes, and PDF bytes. Run all other affected journeys as their independent cases so each run has a fresh database and source artifacts. No failure receives an automatic retry.

The self-contained `--annotations --web` command starts the real fault proxy before annotation HTTP checks, runs all annotation HTTP drivers serially, then runs the six main browser journeys, the two collection journeys, and the dense shared-source window journey in that order. Collection and dense-window reports use separate `-collection` and `-source-window` artifact directories so the main report is retained. The actual additional case titles are A01 for the EPUB collection and A03 for both the PDF collection and dense source window. Focused runs invoke only matching additional configs/tests; A02 retains the main source-PDF alias journey. The proxy starts once and normal cleanup stops it, web/API processes and the isolated database. Existing retained fixtures must release ports before this fresh command is run.

The retained server exposes the API at `http://localhost:16482/api/v1`, web at `http://localhost:16484`, and fault transport at `http://localhost:16485`. Use `ipad-owner`, `ipad-reader`, `ipad-editor`, or `ipad-restricted`, password `IpadFixture123`. The owner is a superuser; the reader has viewer library access; the editor has metadata permission and editor library access; the restricted account has no library access. Tests create annotations through public routes rather than inserting expected canonical rows.

The temporary library has 50,000 books inserted in batches of 500. Book 1/file 1 is a three-page PDF with 600 by 800 point pages and independently specified text `Orbit fixture: passage 1` through `3`. Book 2/file 2 is the existing actual EPUB/Read Along fixture, titled `Native renderer proof`. Book 6 has PDF/audio files, and book 10 has a comic. Retrieve the latter file identities through authenticated book detail; do not infer IDs from internal rows. The EPUB fixture includes an emoji and combining accent to exercise passage coordinates.

## Controlled faults

For E02, the viewer fixture also has `LibraryDownload`, allowing actual reading/offline delivery without source editing permission. Offline journals and retained work stay in Application Support. The production app exposes its Documents folder to Files for user-selected exports; exported artifacts can be inspected without using the private local store as an assertion seam.

`restart-server.mjs` rebuilds before replacing the isolated API listener and uses `IPAD_REUSE_FIXTURE` to preserve the existing database and temporary source folder. This supports retrying the exact recorded failed operation after a repair. `--allow-stopped` permits recovery when this retained API has no listener; it validates the controlled fixture and rechecks the port after compilation before launching. A per-run signing key is retained in a private ignored file, so subsequent helper restarts keep authentication configuration. The first recovery from an older helper requires fresh login because its prior signing key was ephemeral. PID, supervisor and log metadata are written durably to `restarted-runtime.json`. Coordinate the writer window first. Stop the restarted runtime supervisor before stopping the original retained harness, which owns final database/content cleanup.

To refresh an old in-process transport proxy after all active test leases release, root runs `node scripts/ipad/serve-fault-proxy.mjs <existing-run-ID> --replace-outer`. The supervisor validates the retained API and the exact old proxy owner, kills only the named outer harness without running its database cleanup, and starts the current proxy module on port 16485. The replacement API and detached web process remain running. `proxy-runtime.json` records their PIDs and transfers final fixture cleanup to root. Stopping this new supervisor stops only the proxy. Final cleanup stops the replacement API normally to remove temporary content, stops the detached web process group, then drops only the recorded isolated database. Never refresh during a native/browser/HTTP test lease.

Source fault restoration clears its saved snapshot only after successfully restoring the bytes. The next fault journey therefore captures the current source, including intervening legitimate publications. Serialized artifact drivers may explicitly capture their current baseline with authenticated owner POST `/api/v1/__faults/source-pdf/source/1/snapshot`, then restore it in cleanup and compare the public delivered SHA. Snapshot changes only the controlled backup and never the source bytes.

All controls exist only in the isolated test harness. Production annotation routes, permissions, database writes, source mutation and delivery remain real.

| Control                                                                                                      | Effect                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |

| POST `16485/__faults/annotations/transfer-arm?path=<encoded API path>`                                       | Hold a real successful content stream after its first byte; GET `held` waits for the hold; POST `release` continues; POST `cut` interrupts the socket |

| POST `16485/__faults/annotations/reset`                                                                      | Clear network controls and checkpoints                                                                                                                |
| GET `16485/__faults/annotations/traffic`                                                                     | Read bounded forwarded-request status, byte and Range observations; require `truncated: false` when proving unselected content was not delivered      |

Await visible progress, authenticated canonical state, a held/checkpoint state, or delivered bytes. Fixed sleeps and private database observations do not establish acceptance.
