The working tree was based on `5c56bb4bab256f5855e6f26e053b13d52ee6147a`; native proof files were being edited concurrently. WebKit citations below pin upstream revision `b2b4227bf36860deba3330f07003857ff6458a3b`. That revision has not been identified as the WebKit binary in the cached iOS 26.0 runtime. [ADR 0004](../docs/adr/0004-allow-local-epub-rendering-in-the-native-reader.md) keeps EPUB engine acceptance open and assigns controls and gestures to the native reader.

## Finding and limits

The retained [run-18468 summary](../test-results/ipad/run-18468-1791277099332/native-summary.json) and [run-22358 summary](../test-results/ipad/run-22358-1791277406121/native-summary.json) each report one failed EPUB test with “Hit area is too small.” The implementer identified the highlighted element as the plain publication text `Alpha 😀 café omega.`, a `WebAccessibilityObjectWrapper` at 20px font, with a 292 by 38 pixel glyph screenshot. The implementer's 44px line-height/minimum block-size experiment enlarged actual layout space but retained the failing text bounds. These are previous run observations, not measurements performed for this report. Device screenshot pixels, CSS pixels and accessibility frame points must be recorded separately; the glyph screenshot alone does not establish a 44-point target size.

Primary source explains why paragraph spacing can fail to enlarge the exposed text. It also identifies Foliate's inherited script interaction as a concrete hypothesis to isolate. It does **not** establish that Apple's audit has a confirmed false positive: the public SDK/docs do not publish its element-selection or hit-size decision algorithm. Preserve the full audit failure and keep renderer acceptance open until an actual native tracer establishes the result. Apple describes hit-region auditing as detecting elements too small to interact with; its 44 by 44 point button guidance does not require ordinary publication text to use a 44-point font. Passing audits also does not replace VoiceOver testing. [Apple audit documentation](https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app), [Apple button guidance](https://developer.apple.com/design/human-interface-guidelines/buttons).

## Why block spacing does not fix a text leaf

HTML `p` maps to the paragraph role, while its text node maps to static text. On iOS, a nonempty static-text object is exposed as an accessibility element with the static-text trait. A normal paragraph is a container rather than an independently exposed element; its special leaf eligibility requires keyboard focusability, no accessible children and a description. The accessible glyph leaf therefore need not share the paragraph's padded/minimum-height box. [Role mapping](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/AccessibilityNodeObject.cpp#L528-L537), [paragraph mapping](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/AccessibilityNodeObject.cpp#L615-L620), [static-text trait](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/ios/WebAccessibilityObjectWrapperIOS.mm#L938-L940), [static-text exposure](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/ios/WebAccessibilityObjectWrapperIOS.mm#L1043-L1052), [paragraph container eligibility](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/ios/WebAccessibilityObjectWrapperIOS.mm#L1130-L1172).

The iOS wrapper's `accessibilityFrame` takes `elementRect()` and converts it to screen coordinates. For ordinary text, `elementRect()` falls through to `boundingBoxRect()`, whose `RenderText` branch takes text quads. Those quads use each text box's visual rectangle, not the paragraph's minimum block size. This directly supports the observed difference between layout space and text AX bounds. Static text also participates in WebKit's fuzzy accessibility hit testing, so being plain text does not make it absent from hit testing. None of these functions implements Apple's audit threshold. [Frame conversion](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/ios/WebAccessibilityObjectWrapperIOS.mm#L1917-L1925), [element rectangle](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/AccessibilityNodeObject.cpp#L324-L335), [text bounding box](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/AccessibilityRenderObject.cpp#L649-L703), [visual text quads](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/rendering/RenderText.cpp#L685-L712), [static-text fuzzy hit testing](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/ios/WebAccessibilityObjectWrapperIOS.mm#L347-L379).

## Smallest legitimate Foliate isolation

The inspected [reader bridge](ReaderProof/EPUBProof/reader.js) opens the local book, preserves ordinary XHTML content and resolves original DOM ranges. It does not assign a paragraph a button action. Foliate, however, registers script interaction on every chapter's ancestors:

| Registration                                                                                    | Source                                                                                                                                                                                        | Consequence for the diagnostic                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `touchstart`, `touchmove`, `touchend` on the paginator host and every loaded chapter `Document` | [paginator constructor](../client/public/assets/foliate/paginator.js:601)                                                                                                                     | All three handlers are registered unconditionally. Remove both registration sets for a coherent native gesture ownership option.                                                                                                                                                                                                                         |
| `pointerdown`, `pointerup` on every chapter `Document`                                          | [selection tracking](../client/public/assets/foliate/paginator.js:626)                                                                                                                        | These also count as touch-related events in WebKit. Keeping them prevents a zero-script-touch diagnostic. Their removal loses Foliate's script-driven cross-page pointer-selection auto-turn behavior.                                                                                                                                                   |
| `keydown`, `keyup`, `selectionchange`, `focusin`                                                | [selection/focus tracking](../client/public/assets/foliate/paginator.js:630)                                                                                                                  | Keep keyboard selection and focus navigation. Ordinary browser selection, DOM Range/Selection APIs and CFI generation do not require the removed gesture registrations. Actual touch selection and selection across rendered pages still need native verification.                                                                                       |
| `mousemove` cursor autohiding; delegated `click` for actual links and annotations               | [cursor handler](../client/public/assets/foliate/view.js:358), [link handler](../client/public/assets/foliate/view.js:623), [annotation handler](../client/public/assets/foliate/view.js:683) | `mousemove` is not in the source's `TouchRelated` category ([classification](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/dom/EventNames.json#L158-L164)). Preserve real link/annotation actions. Do not infer that a delegated `Document` click listener alone assigns every paragraph a press action. |

WebKit's `hasTouchEventListener()` inspects the text node and all composed ancestors, then exposes the result to UIKit through `_accessibilityHasTouchEventListener`. Its category includes **pointer** events as well as touch events. Both mechanisms existed in source before the iOS 26 release period, although that still does not identify the shipping binary. [Current ancestor scan](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/ios/AccessibilityObjectIOS.mm#L127-L139), [UIKit bridge](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/ios/WebAccessibilityObjectWrapperIOS.mm#L1233-L1238), [pointer categories](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/dom/EventNames.json#L194-L203), [touch categories](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/dom/EventNames.json#L270-L274), [August 2025 scan](https://github.com/WebKit/WebKit/blob/b0dc25a5f71ee46f06838c3694d65c9489f15be3/Source/WebCore/accessibility/ios/AccessibilityObjectIOS.mm#L128-L140), [August 2025 pointer categories](https://github.com/WebKit/WebKit/blob/802028539c2dc706ea8c5b57f0dc98c61a2be57b/Source/WebCore/dom/EventNames.json#L193-L200).

`parentInComposedTree()` crosses a shadow root to its host but otherwise returns `parentNode()`. The chapter's `Document` is therefore the direct relevant ancestor; this source does not make a chapter text node inherit outer iframe-host listeners across the document boundary. [Composed parent implementation](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/dom/Node.cpp#L1371-L1379). Separately, click action detection checks an `Element` for click/down/up handlers, rather than treating every delegated `Document` listener as an element action. [Click detection](https://github.com/WebKit/WebKit/blob/b2b4227bf36860deba3330f07003857ff6458a3b/Source/WebCore/accessibility/AccessibilityNodeObject.cpp#L1685-L1688).

The paginator inspected before the native extension had **no public disable-gesture configuration**. Its [observed attributes](../client/public/assets/foliate/paginator.js:459) cover flow and layout sizing. `flow="scrolled"` makes touch move/end return early, but leaves touch and pointer listeners installed, so it does not isolate the inherited listener flag. [Scrolled getter](../client/public/assets/foliate/paginator.js:786), [touch handlers](../client/public/assets/foliate/paginator.js:843). The constructor binds private functions without retaining removable references. A native-specific opt-out needs a small explicit renderer extension that controls registration before chapter load and handles the already-installed host listeners, or a deliberately separate prototype asset variant. Keep the web default and genuine EPUB actions. Global `EventTarget` monkeypatching, blanket listener removal, CSS `pointer-events:none`, passive-listener changes and disabled native pan recognition do not provide an honest equivalent.

During this research the implementer introduced public [Paginator.disablePointerNavigation()](../client/public/assets/foliate/paginator.js:854), backed by an abort controller, and called it in the [native bridge](ReaderProof/EPUBProof/reader.js:38) after `view.open()` and before `goTo()`. Its required registration coverage is all six host/chapter touch listeners plus both chapter pointer listeners, including `touchend`; aborting only start/move leaves a touch-related ancestor listener. Check this coverage in the actual revision under test. The completed [run-31686](../test-results/ipad/run-31686-1791278118246/native-summary.json) still failed the unchanged full `testIPADE01A05EPUBContentAccessibility()` audit on the first ordinary paragraph after the implementer removed all eight registrations. The opt-out did not resolve the hit-region finding. The implementer separately reported run-27795 as passing the actual portrait/landscape DOM Range and CSS-highlight selection proof, but that is not a content-audit or VoiceOver pass.

## Completed plain-chapter diagnostic

The independent [run-36630](../test-results/ipad/run-36630-1791278645783/native-summary.json) failed unchanged full `testIPADE01A05PlainDeliveredChapterAccessibility()` on the same ordinary paragraph. The [diagnostic](ReaderProof/EPUBProof/reader.js:62) reloaded the delivered first chapter in a new ordinary sandboxed iframe and replaced Foliate's displayed content. The [native UI checks](ReaderProof/UITests/EPUBReaderProofTests.swift:50) reached “Plain chapter loaded,” the actual hittable publication text and `minX < 40` before the audit. The implementer opened all six actual PNGs: both original paragraphs remained at 20px, with chapter text starting at x = 8 points and no Foliate layout or chapter listeners. The retained [glyph crop](../test-results/ipad/run-36630-1791278645783/native-attachments/DA427841-4DE0-434A-91A0-B25039B9E139.png) and [detailed description](../test-results/ipad/run-36630-1791278645783/native-attachments/38BA2FA0-0E61-4303-A0D0-93F90E9A1FBF.txt) identify `WebAccessibilityObjectWrapper`. The runtime was iOS Simulator 26.0 (`23A343`), iPad Pro 13-inch M4. Six HTTP tests passed separately; the native audit failed. These are retained artifacts and the implementer's image inspection, not researcher-run tests.

Report this as a reproducible **suspected WebKit/platform hit-region audit incompatibility on this runtime**. The closed audit algorithm still prevents a confirmed false-positive diagnosis. The genuine plain-content reproduction strengthens the platform hypothesis and shows that Foliate interaction opt-out alone is insufficient. Both native full-audit failures remain open. A source-based proposal for an actual native TextKit alternative, with CFI/semantics/storage and physical-proof limits, is appended to [reader feasibility research](reader-feasibility-research.md#native-textkit-alternative-after-the-epub-content-audit-failures).

## Semantics and the next tracer

Do not replace all paragraphs with `role="text"` to obtain larger atomic AX geometry. WebKit itself documents this role as nonstandard and WebKit-only, warns that interactive descendants become inaccessible, and has discussed removal with current support behind a feature flag. Its presence is not a stable accessible EPUB contract. Adding button roles without real actions, hiding publication text, replacing text with a label, or collapsing arbitrary chapters into one spoken element also loses required semantics. Standard paragraph/group semantics do not establish that a descendant text leaf inherits a parent's padded bounds. [WebKit's intent and current status](https://bugs.webkit.org/show_bug.cgi?id=260641).

The original isolation tracer proposal below is preserved as source research. Its plain-chapter and complete Foliate opt-out audits have now both failed as recorded above; rerunning them is justified only by a relevant renderer/runtime change. Any further native tracer should retain the same delivered Unicode XHTML, readable font, exact native controls and unchanged full `performAccessibilityAudit()`:

1. Audit a minimal local WKWebView rendering that ordinary XHTML without Foliate's touch/pointer registrations. Retain the original paragraph text and AX hierarchy. Record runtime/build, `issue.auditType`, full descriptions, actual XCUI element type/label/frame in points, window/device scale and screenshots. This separates plain WebKit exposure from renderer behavior.
2. Audit the Foliate native opt-out above. Keep original DOM text and semantics, CSP/resource isolation, links, fonts and CFI conversion unchanged. If it passes, reintroduce touch and pointer registration families separately to locate the trigger. A pass would support gesture ownership as the fix; it would not prove the private audit algorithm.
3. At the public native UI boundary, verify actual touch selection, visible selection painting, exact `😀 café` CFI round trip, keyboard selection/focus, link activation, read-all/paragraph navigation in VoiceOver and reachable native page controls. Test selection extending across rendered pages before claiming parity with Foliate's removed pointer auto-turn behavior. Audit portrait, landscape and supported type sizes; the existing [EPUB tests](ReaderProof/UITests/EPUBReaderProofTests.swift) currently separate selection/CFI from full content audits.

If a clean, noninteractive WKWebView still fails, report **a reproducible suspected platform hit-region audit incompatibility on a specific static-text element**, with the full failed result and minimal evidence. Do not call it a confirmed Apple/WebKit false positive, suppress `.hitRegion`, ignore all web/static-text elements, or mark the full audit passed. An actual native renderer/accessibility implementation remains an engine option under ADR 0004, but requires a complete reading/selection/CFI/semantics proof and cannot be replaced with a fabricated AX overlay. Apple explicitly permits investigating expected audit behavior, but this issue's full-audit acceptance requirement remains unresolved without a genuine passing result or an explicit requirement decision. [Apple's audit interpretation guidance](https://developer.apple.com/videos/play/wwdc2023/10035/).
